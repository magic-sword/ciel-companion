現状欄も素材合成で、既存 Mouth_Large をそのまま表示しているため、Unity の口パラメーター0.8の形とは少し異なる。

## 素材

全て2172×2896・RGBA PNG、現在の顔の座標に配置した。

| 層 | 内容 |
| --- | --- |
| [Eye_R_Happy.png](layers/Eye_R_Happy.png) | 画面左の笑い目。先端を細くした短めの弧、小さな白い光。上側の独立したまぶたの線と肌パッチを含まない |
| [Eye_L_Happy.png](layers/Eye_L_Happy.png) | 画面右の笑い目。同上 |
| [Mouth_Happy.png](layers/Mouth_Happy.png) | 丸い底の小さな笑い口。柔らかいピンクの口内。歯の帯・灰色の口内・肌パッチを含まない |

左右名は既存モデルに合わせた。Rは画面左、Lは画面右。
頬の赤み・顔の輪郭・髪・眉・耳・首輪は既存素材を使っており、今回変更していない。

## 作り方と確認

1. 現在の59層から通常の顔を組み上げ、(550,650)–(1600,1700)の1050正方形を切り出した。
2. この既存の顔を画像生成ツールで編集し、承認見本の笑い目と丸い笑い口を顔の中で描いた。1回。
3. 描いた顔を再度画像編集し、笑い目の線・小さな白い光・笑い口だけを透明背景へ抽出した。1回。上側のまぶたの線・肌・髪などを除いた。
4. 保存済みの透明抽出画像を矩形で3つに分け、アルファの範囲で切り詰めた。縦横同率の拡大縮小と移動だけで配置した。描き足し、塗り直し、非等方変形はしていない。
5. 各側の元の目の9層と口の既存層を非表示にし、修正素材を重ねた。前髪は既存の層順で素材の上に重なる。

組み上げで、以前の黒い帯・上の弧・歯の帯を減らし、見本の白い光とピンクの丸い口に近づいたことを確認した。
肌パッチを使わないため、笑い目の周囲に色の違う肌の楕円は重ならない。
見本と画素単位で一致する素材ではなく、形・大きさ・色に差は残る。最終的な顔の印象の判断はユーザー確認が必要。

原画は `edits/`、透明抽出は `keyed/`、入力は `inputs/`。
全依頼文は [生成記録](generation-provenance.json)、切り出し・倍率・座標は [配置記録](placement.json)、
ファイル検証は [verification.json](verification.json)。
処理は `scripts/live2d/v25/prepare.py` と `build.py`。prepareは入力を作る工程なので、入力を更新しない再構築にはbuildだけを使う。

## 取り込み時の注意

今回は素材の修正案を納品した段階。`assets/ciel/current/`・正式リグ・Unityは変更していない。

- 新しい笑い目には肌がない。既存の `ParamEyeLSmile` / `ParamEyeRSmile` が元の目の9層を消す構成を維持する。
- 笑い目の絵の範囲が変わるため、メッシュとアトラスを更新する。
- `Mouth_Happy` は新しい別層。`Mouth_Large` を置き換えて通常会話の口まで変更することは避け、嬉しい用の笑い口として表示を切り替える。
- 口の開閉と笑い口の表示を別に制御し、会話中の口パクが途切れないようにする。
- 見た目の確認後、Cubismで正面・頭の角度・表情フェード・口の開閉を確認し、Unityへ書き出す。
