# 現行ドキュメントを管理する

作業起点はリポジトリのルート。最初に[資料一覧とフォルダの担当範囲](../../../docs/README.md)と[管理ルール](../../../docs/project/documentation-policy-ja.md)を読み、対象の正本だけを追加で読む。設計判断を変える場合は[設計方針](../../../docs/project/design-policy-ja.md)も確認する。

- 既存の責務に属する情報は既存の正本を更新する。新しい責務だけを別ファイルへ分け、担当フォルダへ置く。日付付き報告、旧仕様、履歴用の転送ファイルは作らず、過去はGitで参照する。
- 実装・設定・正式manifestに照合し、採用方針、実装状況、実測、本番反映を区別する。測定値・条件・ソース識別・生データの場所・未確認範囲は[分野別の実測資料](../../../docs/README.md#テストと確認状況)、現在の配布・確認範囲は[確認状況](../../../docs/testing/verification-status-ja.md)を更新する。文書更新だけで実機確認済みとは書かない。
- ファイルを追加・移動・統合したら、資料一覧の相対パスと責務、文書冒頭の`> 責務：`をそろえる。`docs/`直下は索引だけとし、共通契約とゲーム・モデル固有の仕様を担当フォルダへ分ける。
- 移動前の位置を基準に、相対リンク・画像・見出し参照を解決して移動先へ付け替える。README、AGENTS/CLAUDE、両エージェントのスキル、ソースコメント・コマンド内のパスも更新する。統合前に固有の制約・採用条件・測定根拠を保持する。
- このスキルの共通手順はここへ置く。Codex側の`.agents/skills`にある同名スキルはここへの入口とし、手順を二重管理しない。文書の方針や配置の定義は管理ルールと資料一覧を正本にする。

完了前に以下を実行し、残る意味上の不一致も対象の実装と照合する。外部URLの到達性や実装の動作はリンク検証の対象外。文書整理からサービス再配布や有料試験へ作業を広げない。

```powershell
.\.venv\Scripts\python.exe -B -X utf8 scripts/docs/check-docs.py --self-test
.\.venv\Scripts\python.exe -B -X utf8 scripts/docs/check-docs.py
git diff --check
```
