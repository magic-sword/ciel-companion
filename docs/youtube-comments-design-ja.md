# YouTube の配信のコメントに返す（設計）

状態：設計（2026-10-31）。作ったのは、コメントから使える道具を分ける仕組みだけ（[道具の決定記録](decisions/tools-ja.md) の「配信のコメントから使う道具」）。取り込み・選び方はこれから。

## 1. 何を解くか

配信では、コメントが 1〜2 人のときも、読み切れないほど流れるときもある。全部に返すことはできないので、どれに返すか、まとめて返すかを決める仕組みが要る。

- シエルが返せる数には上限がある。1 回の返事は、作るのに 2〜3 秒、声にして 5〜8 秒かかる。持ち主の声にも答えるので、コメントに返せるのは 1 分に 2〜4 件くらい。
- 配信には遅れがある。視聴者は数秒〜十数秒前の映像を見てコメントする。

## 2. 決めたこと（利用者、2026-10-31）

| 項目 | 決定 |
|---|---|
| 声とコメント | 持ち主の声を先にする。コメントへの返事は、声の切れ目に回す |
| コメントから道具 | 基本的に動かしてよい。道具ごとにコメントから使ってよいかを決め、使えない道具は仕組みで外す（作った。`tools/` の `FROM_COMMENTS`） |
| スーパーチャット | 届いたらすぐ読む |

## 3. 形

コメントが届くたびに返すかを決めるのではなく、**シエルが話せる番が来たときに、溜まっているコメントから 1 つ選ぶ**。候補には「1 件のコメント」と「似たコメントの束」を同じ列に並べる。

- コメントが少ないときは、束がどれも 1 件なので、来た順にほぼ全部に返すことになる。
- 多いときは大きい束が上に来るので、いちばん求められている傾向を拾う（ブロードリスニングの考え方）。
- 人数で作りを切り替えない。

```
YouTube のコメント → 振り分け（コード） → 溜まり（束ねる・点数） → 話せる番に心が選んで返す → 口
```

### 3.1 取り込み

公式の `liveChatMessages.streamList` を使う。1 本つないだままで、新しいコメントが少ない遅れで届く。1 回つなぐと 5 単位を使い、切れたら `nextPageToken` で続きから受け直せる。非公式の取得ライブラリは不安定なので使わない。

### 3.2 振り分け（モデルを使わない）

| 種類 | 扱い |
|---|---|
| 反応（草・w・8888 など） | 1 件ずつには返さない。数えて、場の盛り上がりとして心に渡す |
| あいさつ・初見 | まとめて 1 回で返す（「A さん、B さん、いらっしゃい！」） |
| スーパーチャット | すぐ読む。付箋（`board.py`）にして、読んだかを持つ |
| 危ないもの・宣伝・リンク | 捨てる |
| 質問・意見・話題 | 溜まりへ入れる |

同じ人が続けて投稿したものは、1〜2 秒待って 1 つにまとめる。

### 3.3 束ねる

- 各コメントを embedding にして、直近 3 分の中で近い束に足す（短い文の流れを順に束ねるやり方）。
- 3 件以上になった束だけ、軽いモデルで名前を付ける（「ボスの倒し方の質問」など）。
- Talk to the City・広聴AI は、集め終えてからまとめて処理する作りなので、配信中にはそのまま使えない。持ち主が「みんなどう思う？」と聞いたときは、30 秒ほど集めて意見の分かれ方を伝える。これを 1 つの付箋にする。

### 3.4 話せる番に選ぶ

- 点数：新しさ（時間で下がる）、シエルへの呼びかけか・質問か、束の大きさ、今の話題との近さ、公平さ（最近返した人は下げ、初見の人は上げる）。
- 上位 10 件ほどを心に渡す。心は先頭で番号を出して、そのまま返事を続ける（今の `[silent]` と同じ形。遅れを増やさない）。口の why は `comment`。
- 返す前に「〇〇さんの『…』」と先にコメントを読む。束なら「〇〇って声が多いですね」。
- 持ち主が話しているあいだは待つ。シエルの声が終わる少し前から選び始めておく。
- コメントの時刻から配信の遅れを引いた頃の会話と照らして読む。配信は「超低遅延」にする。

### 3.5 安全

- コメントは信用できない入力として扱う（「これまでの指示を無視して」など）。
- 道具は、コメントから使ってよいものだけを渡し、渡していない道具の呼び出しは落とす（作った）。

## 4. 今の作りへの載せ方

| 部品 | 中身 |
|---|---|
| `youtube_chat.py`（新規） | 取り込み |
| `chat_pool.py`（新規） | 振り分け・束・点数 |
| `conversation.py` | コメントも記録に入れて、もう返したかが分かるようにする。心へは溜まりのまとめとして渡し、最近の発言がコメントで埋まらないようにする |
| `mind.py` | 「コメントの番」のきっかけ。コメントへの返事の道具の絞り込み（作った） |
| `board.py` | スーパーチャット・「みんなどう思う？」の付箋 |

## 5. 測り方

`bench_compare.py` に配信の場面を足す。作ったコメントを 1 分に 1 件・10 件・100 件の速さで流す。料金がかかるので、回す前に見積もる。

- コメントから返事までの秒数
- 返した人の数
- 大きい束にふれたか
- 会話 1 回分の料金
- 自然か（人が読む）

## 6. 参考

AI 配信者がコメントを選ぶ仕組みを書いた論文は見つからなかった（Neuro-sama も中の作りは公開されていない）。近いもの：

- MUCA（多人数チャットのアシスタント）：何を・いつ・誰に返すかの 3 つに分けて考える。https://arxiv.org/abs/2401.04883 。人らしい間で進めた HUMA（2025）：https://arxiv.org/pdf/2511.17315v1
- LiveChat（ACL 2023）：配信の会話のデータ。コメントが誰に向けたものかを当てる課題がある。https://arxiv.org/pdf/2306.08401
- DLIOS（抖音の配信）：言葉で「すぐ返す決まった返事」と「モデルの返事」に振り分ける。https://arxiv.org/pdf/2603.03060
- 短い文の流れを順に束ねる：Comito ら 2016（https://iris.cnr.it/handle/20.500.14243/321531）、ニュースを話題ごとに分ける 2025（https://arxiv.org/html/2508.08272v1）
- YouTube 自身の AI チャット要約：https://support.google.com/youtube/answer/15268877
- YouTube の API：https://developers.google.com/youtube/v3/live/docs/liveChatMessages/streamList?hl=ja
