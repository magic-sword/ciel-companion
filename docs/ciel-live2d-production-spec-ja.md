**現在の状態（2026-10-08）：素材v2（2172×2896px）の目のレイヤーを作り、Cubismで開眼・半目・閉眼の開閉キーを設定済み。次は体・髪・口のパーツ分けと、PRO版での書き出し（第12節）。**

## 1. 目的と初期制作範囲

シエルがこちらを見て話を聞き、返答に合わせて口を動かし、表情や小さなしぐさで反応する上半身モデルを制作する。
初期版では、顔の読みやすさ、自然な口パク、白い髪・耳・衣装の見分けやすさを優先する。

| 区分 | 内容 |
|---|---|
| 必須 | 正面の上半身、まばたき、呼吸、軽い体の揺れ、再生音声に同期する口の開閉 |
| 必須 | 通常・笑顔・困り・驚きの4表情、停止時の閉口、通常表情への復帰 |
| 制作案 | 視線、顔の小さな左右・上下・傾き、髪の揺れ、左右の耳の軽い反応 |
| 追加案 | アホ毛の反応、頬の色、胸のプリズムの弱い明滅 |
| 初期対象外 | 全身歩行、横顔・背面への回転、大きな手振り、衣装切替、尻尾の本格的な可動、食事動作、カメラによる顔追跡 |

全身絵を将来の資料として保持しても、今回の納品に全身リギングは要求しない。
耳・アホ毛はモデル原画に含め、追加の動きは顔・口の品質を確認してから調整する。

公開文書には個人環境の絶対パスや元資料の全文・画像を転載せず、制作に必要な要約と資料名を記載する。

| 資料名 | 本制作での用途 | 現状・注意点 |
|---|---|---|
| キャラクター設定資料_主人公_シエル.md | 第2章の外観・配色・衣装・表情 | Ver.2.0を参照。初期三面図から変更した記述あり |
| シエル_正面.png | 顔立ち、全体の配色、シルエット | 一枚絵。Live2D用のレイヤー構造なし |
| シエル_側面.jpg／シエル_背面.jpg | 髪・衣装・耳の厚みと重なりの参考 | 上半身原画に必要な範囲を制作時に照合 |
| 3Dフォルダの四方向PNG | 立体感の参考 | 3Dモデルデータではない。採用デザインを保証しない |
| 台詞集・動画・ボイスサンプル | 後工程の口調・動き・音声評価の参考 | 今回は会話設定や参照音声を確定しない |

上記の元資料を最初に確認した時点では、レイヤー付きPSDやLive2Dモデルは含まれていなかった。プロジェクト内で制作した現行PSDは第12節を参照。
「既存絵を直接Unityで動かす」段階ではなく、原画整理→パーツ分け→Cubismでのモデル制作が必要。
一枚絵の切り抜きだけでは、隠れている額や口内などは得られないため、描き足しを工程に含める。

## 3. 外観の制作方針

### 採用した外観参考

**現在の制作基準：素材v2の基準画像（第12節）。外観参考v1は、鼻・肌の方針の出典として残す。**
レイヤー数・保存・再読み込みの成功はファイル処理の検証であり、顔立ちの再現品質を保証しない。

2026-10-05、ユーザーが修正版イラストを今後のプロジェクトの参考として採用した。
基準画像は [シエル外観参考 v1](../assets/ciel/reference/ciel-approved-appearance-v1.png)。新しいセッションでも、この画像を開いてから原画・パーツ制作を進める。
今後の原画・パーツ制作ではこの基準画像を参照し、元イラスト `シエル_正面.png` も顔立ちの補助資料として保持する。
特に控えめな鼻と滑らかな白磁の肌を引き継ぎ、黒い犬型の鼻や人間らしい血色へ戻さない。
採用は外観参考としてのもので、パーツ構造・可動域・最終制作原画の承認とは区別する。
この基準画像は `assets/ciel/reference/` に置き、Git管理・公開リポジトリへの収録対象とする（ユーザー決定）。
コミットを取得すれば別のPCでも同じ画像を参照できる。
再生成できる中間画像・編集原本（PSD/XCF）はGit対象外。再生成の手順は第12節。
この画像はユーザー提供の参考画像をもとに画像生成・編集した外観資料で、PSDやリギング済みモデルではない。
リポジトリへの収録は、キャラクターや画像にコードと同じライセンスを自動適用することを意味しない。

設定文を基本とし、顔立ちは正面画像を参照する。文章と画像の差は原画で比較し、勝手に混ぜて完成仕様にしない。
ただし、鼻と肌は以下のユーザー指定を優先する。鼻は元イラストの控えめな表現とし、犬型の黒い鼻先は採用しない。
肌は一目で人間ではなくヒューマノイドと伝わる、滑らかな陶器のような白磁の白とする。
顔・首・肩・腹部など露出部で色と質感を統一し、肌色・桃色の血色や常時の頬紅を加えない。
立体感は淡い寒色系の陰影と柔らかな光で表現する。白い髪・毛皮とは表面の滑らかさで区別する。
衣装の細部へのこだわりは強くないとの指定により、鼻と肌の再現を優先する。衣装全体の承認を意味するものではない。

| 要素 | 設定資料から引き継ぐ内容 |
|---|---|
| モチーフ | サモエド型ヒューマノイド。厚みのある白い立ち耳とふんわりした毛量 |
| 髪 | 純白〜銀白の長い髪、頭頂のアホ毛、毛先の控えめなシアンの光彩 |
| 目・肌 | シアンの瞳、血色を加えない滑らかな白磁の肌。常時の頬紅なし |
| 口元 | 親しみやすい笑顔、小さな八重歯。閉口時に歯が浮かない |
| 衣装 | フードなしの短い白いパフジャケット、ファー襟、シアンの裏地 |
| 装飾 | シアンのチョーカー、胸のプリズム、暗色の補強部と発光アクセント |

原画確定前の確認事項：

| ID | 確認項目 | 制作案・判断材料 |
|---|---|---|
| D01 | 完成原画の基準 | 設定Ver.2.0に合わせて正面画像を整理する案。顔立ちを維持する |
| D02 | 鼻先の表現（確定） | 元イラストの控えめな線・陰影を採用。犬型の黒い鼻先は不採用 |
| D03 | プリズム・チョーカーの形状 | 設定の六角形と正面絵の見え方、リング・接続部の形を照合する |
| D04 | ファー襟・袖口・毛先の光彩 | 設定に沿った形と量を確定。髪との境界がつぶれないようにする |
| D05 | 上半身の画角 | 耳先から腰付近までの原画。アプリでは胸〜腰の範囲で切り替えられる案 |
| D06 | 尻尾・手の表示 | 初期版は必須にしない。画角に入れる場合だけ必要な部分を追加設計 |

D01〜D05を一枚の原画と4表情のラフで確認してから、清書・レイヤー分割の大きな作業へ進む。
本書の作成自体は、それらの選択肢を確定したことにはならない。

## 4. 原画・PSD制作仕様

### 制作環境と担当範囲

ユーザー指定により、画像編集環境をFireAlpaca案から無料のGIMP 3.2.6へ変更する。Photoshopはインストール済みだがライセンス切れで利用できないため、
再契約やPhotoshop専用の素材分けプラグインを制作の前提にしない。
GIMP 3.2.6のPythonバッチ実行とPSD入出力機能の登録を確認済み。CLIから制作処理を実行し、編集原本はXCF、受け渡しはPSDとする。[公式CLI資料](https://www.gimp.org/man/gimp.html)

| 工程 | 使用環境・方針 |
|---|---|
| 原画・透過パーツの制作補助 | アシスタントが設定・参考画像をもとに画像生成・編集で制作を進め、ユーザーが外観を確認する |
| パーツの合成・調整とPSD作成 | GIMP。編集原本を`.xcf`で保存し、Cubism向けに整理したレイヤー付きPSDを別途出力する |
| リギング・組み込み用書き出し | Cubism Editor。採用版と利用形態は初回試作時に確認する。画像編集環境が無料であることと、Editorの利用条件は別に扱う |
| アプリへの取り込み・検証 | 既存のUnity・Cubism SDK環境とUnity CLIを利用する |

MCPの追加設定は着手条件にしない。反復作業が明確になった時点で、命名・ファイル検査などのスクリプト化や外部連携を検討する。
画像生成ツール単体はレイヤー付きPSDやリギング済みモデルを直接出力しない。生成画像の後処理とPSDの作成はGIMPで行う。
生成・編集したパーツは、共通座標へ配置して合成し、位置・輪郭・塗り・重なりを確認してからPSDにまとめる。
GIMPはPythonバッチでレイヤー編集・保存を自動化する。MCPや画面クリックは不要。Cubism Editorの操作・リギングは別途検証する。

特に、前髪に隠れた肌、目・口の境界、毛束のつなぎ目は、切り抜きや生成だけで完成とせず、描き足しと合成確認を行う。
別々に制作したパーツで顔立ち・線の太さ・色が変わった場合は、基準原画に合わせて修正する。

### 原画と受け渡し形式

以下の数値は本プロジェクトの提案値であり、Cubismの上限・必須値ではない。

| 項目 | 制作案 |
|---|---|
| 原画キャンバス | 素材v2の基準画像は2172×2896px、透明背景。耳・アホ毛・肩が動く余白を確保 |
| 原画の基準姿勢 | 正面、自然に目を開く、口は閉じる、首を傾けない、腕は落ち着いた位置 |
| 色 | RGB・8bit/チャンネル・sRGBを受け渡しの基準にする。色見本は原画確定時に採取 |
| レイヤー | 動かす単位を分離し、各パーツの共通座標と位置を維持する |
| 輪郭・塗り | 白背景を描き込まない。黒・白・灰色背景で縁の白残りや欠けを確認 |
| 納品 | GIMP編集原本（`.xcf`）、Cubismへ読み込む整理済みPSD、統合プレビューPNG |

レイヤー名は英数字・アンダースコアで重複を避ける。`L`／`R`はキャラクター本人の左右とし、
正面から見た画面左は本人の右。必要なら別途対応表を付け、途中で命名基準を変えない。
PSDのレイヤー効果やマスクに依存する表現は、編集原本を残したうえでインポート用に整理し、
Cubism内で元絵と比較する。[公式PSDインポート手順](https://docs.live2d.com/en/cubism-editor-manual/psd-import/)
PSDはCMYKではなくRGB・8bit/チャンネルで保存し、sRGBを基準とする。
初回の顔パーツ試作で、レイヤー名・分離・透明度・色がCubismへの読み込み後も維持されることを確認する。
[公式PSD作成上の注意](https://docs.live2d.com/en/cubism-editor-manual/precautions-for-psd-data/)

個別の透過PNGを受け渡す場合は、原則として原画と同じキャンバス寸法・原点を維持する。
余白を切り詰める場合は配置座標を記録し、中央揃えや個別拡大縮小で位置を合わせない。

### 顔パーツを先行する試作

正面上半身の基準原画と4表情ラフを確認した後、全パーツの清書へ進む前に顔まわりの制作方法を検証する。
顔の土台、前髪、左右の眉・白目・瞳・まぶた、口の輪郭・口内を最小構成とし、必要な歯などを加える。
GIMPで重ねたプレビューとPSDを作り、Cubismでまばたきと口開閉を試す。
開眼・閉眼、閉口・中間・開口で欠けや隙間がないことを確認してから、髪・耳・衣装など上半身全体へ展開する。
試作のためにモデルの初期対象を全身へ拡大しない。

### パーツ分け一覧

部品数は清書時に決める。細かく分けること自体を目標にせず、変形と隠れ部分の補完に必要な単位とする。

| グループ／命名例 | 分割する単位 | 描き足し・注意点 |
|---|---|---|
| `Face_Base` | 顔の土台、必要に応じ鼻・陰影 | 前髪や目の下に隠れる肌も埋める |
| `Eye_L_*`／`Eye_R_*` | 白目、虹彩・瞳孔、ハイライト、上まつげ、下まぶた等 | 視線の端で白目が欠けない。閉眼線を成立させる |
| `Brow_L`／`Brow_R` | 左右の眉 | 前髪の下も描き、困り眉・驚き眉の余白を確保 |
| `Mouth_*` | 上下の輪郭、口内、歯・八重歯、舌 | 口内を顔の土台に焼き込まない。閉口用の形を作る |
| `Cheek_L`／`Cheek_R` | 頬の色 | 当面不採用。追加する場合は白磁の質感を損なわない案を別途確認 |
| `Hair_Front_*` | 前髪を大きな毛束ごとに | 動いた先の額と髪の根元を補完 |
| `Hair_Side_L/R_*` | 顔脇〜肩の毛束 | 首・ファーとの前後関係を決める |
| `Hair_Back_*` | 後ろ髪を揺らす単位で | 顔・首・肩に隠れる部分を連続して描く |
| `Hair_Ahoge` | アホ毛 | 根元の接続を隠せる重なりを確保 |
| `Ear_L/R_*` | 左右の耳、内側の毛、必要なら発光部 | 耳を倒した際の隙間を補完。髪と結合しない |
| `Neck`／`Body_Base` | 首、胴体、インナー | 傾いた顔の下と衣装の下を補完 |
| `Jacket_*`／`Sleeve_L/R_*` | 胴の左右、左右袖、必要なら裏地 | 呼吸と体の傾きで縫い目が切れない |
| `Fur_Collar_*` | 襟の中央・左右など | 毛の一本単位には分割しない。髪との境界を確保 |
| `Choker_*`／`Prism_*` | 本体・金具、発光用レイヤー | 首や胴体と一緒に動き、顔には追従させない |
| `Hand_L/R_*`／`Tail_*` | 採用画角に入る場合のみ | 初期必須ではない。追加時に前後関係から設計 |

重なりは、後ろ髪→胴体・首→衣装→顔→顔の部品→前髪を出発点にする。
耳・横髪・襟・チョーカーは実際の原画に合わせて部位ごとの前後関係を明示する。
モデルを分解表示した確認画像を納品し、隠れ部分まで塗られていることを確認する。

## 5. リギングとパラメーター契約

標準IDはLive2Dの[標準パラメーターリスト](https://docs.live2d.com/en/cubism-editor-manual/standard-parameter-list/)を参照する。
表の範囲は初期制作の提案値。顔角度の値は制御用の数値で、実際に同じ角度の立体回転を保証しない。
モデラーが範囲を変更する場合は、納品時に対応表を更新する。

| ID | 最小／初期／最大 | 用途・主な制御元 |
|---|---|---|
| `ParamAngleX`／`ParamAngleY` | -30／0／30 | 顔の左右・上下。最初は見た目の小さな動きに抑える |
| `ParamAngleZ` | -30／0／30 | 首の傾き。耳先・肩との干渉を確認 |
| `ParamEyeLOpen`／`ParamEyeROpen` | 0／1／1 | まばたき。0で閉眼、1で通常の開眼 |
| `ParamEyeBallX`／`ParamEyeBallY` | -1／0／1 | 視線。カメラ追跡は不要 |
| `ParamBrowLY`／`ParamBrowRY` | -1／0／1 | 眉の上下。4表情を作るための基礎 |
| `ParamBrowLAngle`／`ParamBrowRAngle` | -1／0／1 | 眉の角度。正負の見た目を確認表に記載 |
| `ParamMouthOpenY` | 0／0／1 | 音声の口パク。0で完全に閉じる |
| `ParamMouthForm` | -1／0／1 | 口の形。困り寄り／通常／笑顔寄りを提案 |
| `ParamBodyAngleZ` | -10／0／10 | 上半身の軽い傾き |
| `ParamBreath` | 0／0／1 | 小さな呼吸。体格が変わるほど拡縮しない |
| `ParamCielEarL`／`ParamCielEarR` | -1／0／1 | 独自ID案。耳を軽く伏せる／通常／少し立てる |
| `ParamCielHairSway` | -1／0／1 | 独自ID案。物理演算による軽い揺れの出力 |
| `ParamCielAhoge` | -1／0／1 | 独自ID案・追加。アホ毛の反応 |
| `ParamCielCheek` | 0／0／1 | 独自IDの予約案。当面未実装。頬の色の追加は別途確認 |
| `ParamCielPrismGlow` | 0／0／1 | 独自ID案・追加。基礎光からの発光の追加量 |

独自IDはSDKの標準機能名ではない。髪を複数系統に分ける場合は独自IDを追加して対応表に記録する。
耳の感情反応と物理演算を同じIDへ無条件に上書きしない。初期案では耳は感情制御、髪は物理制御に分ける。

各パラメーターの単独の端点と、顔X×Y、顔の傾き×閉眼、口の形×開閉の組み合わせを確認する。
左右の視線・瞬きで瞳がはみ出さず、口が最大に開いても歯・舌・口内が浮かないこと。

## 6. 表情・待機動作

| アプリ側ID案 | 見た目 | 音声との共存 |
|---|---|---|
| `neutral` | 自然な開眼、穏やかな口元、通常の耳 | 無音なら閉口。接続エラーでも基本はこの表情 |
| `smile` | 口角・眉で笑顔、耳が少し立つ | 閉じ目笑顔は追加案。話していても口パク可能 |
| `troubled` | 困り眉、控えめな口角、軽く伏せた耳 | 視線や表情で表現し、口を常時開けない |
| `surprised` | 眉を上げる、視線を止める、耳が立つ | 目の開きを1より増やす場合はモデル範囲を再定義 |

表情のアセット名と上記IDの対応を納品時に固定する。未実装・不明なIDは通常へ戻す。
表情には寿命を持たせ、期限切れで通常へ戻す。遅延した古い会話世代の表情は適用しない。
初期版では驚きの表情ファイルも `ParamMouthOpenY` を固定せず、発話と停止を優先する。

待機は呼吸・まばたき・小さな姿勢変化を基本とする。会話の開始待ちにも大きく揺れ続けない。
物理演算とアプリ制御で実現できる動きは、同じ動きをモーションへ重複して焼き込まない。
待機モーションファイルを追加する場合も、目の開閉と音声用の口開閉はアプリが制御できる状態にする。

## 7. Unity・音声との接続条件

現在の開発環境はUnity 6000.6.4f1、URP 17.6.0、Cubism R5＋互換修正。
詳細は[SDK導入記録](decisions/sdk-setup.md)を参照する。Cubism Editorの採用版は初回モデルの書き出し・読み込みを確認して記録する。
新しいEditorで作れたことだけをもって、現在のSDKで全機能が使えるとは判断しない。

- 口パクの入力は、端末で実際に再生中の変換後音声の音量。マイク入力や受信しただけの音声ではない。
- 音量を平滑化して0〜1へ対応させる。ゲインや開閉速度は声を聞きながら調整し、固定の音量しきい値をモデル制作時に決めない。
- 割り込み・会話終了・バックグラウンド移行で再生を止めたら、次の描画更新で口開閉の目標値を0へ戻す。
- 表情の口形と、音声の口開閉を別の制御とする。最終更新で口開閉を音声側が決め、待機・表情から上書きしない。
- 目は通常時のまばたきと表情を合成する。固定閉眼を追加した場合に、自動まばたきが強制的に開眼させないよう調整する。
- 接続状態と、聞く／話す反応は分ける。発話中もユーザーの割り込みを受け付ける。
- アプリ用のパラメーター対応表には、ID、範囲、初期値、制御元、欠落時の扱いを記載する。必須の口開閉IDが欠けたモデルは検証失敗とする。

Unityでの見た目は、現行のCubism用URPレンダラー・Gamma色空間・HDR無効で確認する。
これは現プロジェクトの検証条件であり、任意のレンダリング設定で同じ色を保証するものではない。

### 12.1 リポジトリの構成とGit管理の方針

目的は、PCが止まったときや別の人が引き継ぐときに、clone するだけで開発を続けられること。**再生成できない物は Git に入れ、再生成できる中間物は入れない。** 公開範囲はオープンソース（ユーザー決定、2026-10-08）。

| 場所 | 内容 | Git |
|---|---|---|
| `assets/ciel/generated/` | ユーザーが生成した元画像（再生成不可）。内容は変更しない。元のファイル名は `original-names.json` | 管理する |
| `assets/ciel/requests/` | 生成依頼に使った切り抜き `face-crop-1024x576_x598_y762.png` と選択範囲の案内 | 管理する |
| `assets/ciel/reference/` | 外観の参考画像（外観参考v1、承認済みの閉眼デザイン） | 管理する |
| `assets/ciel/rig/` | Cubismの作業モデル `ciel-blink-test.cmo3` | 管理する（節目でのみ更新） |
| `assets/ciel/{master,layers,normalized,psd}/`、`manifest.json` | `scripts/live2d/` が作る中間物 | 管理しない（再生成） |
| `scripts/live2d/` | 素材v2の再生成スクリプト | 管理する |
| `.local/` | 作業用の一時物、インストーラ、スクリーンショット | 管理しない |

`.cmo3` やPSDは、保存のたびに数MB〜数十MBの履歴が増える。毎回コミットせず、動作確認が取れた節目だけコミットする。画像・Live2Dファイルは `.gitattributes` で変換されない。

| `generated/edit-b-eyes-removed.png` | 依頼B：両目（まつ毛・二重の線を含む）を消して肌にした。「目のない顔」の下地 |

**使い方の原則**：生成パーツは基準画像と同じ絵ではない（別々に生成され、目の位置・大きさ、前髪の形が異なる。キャンバスも3種類）。通常表情で見える画素はすべて基準画像から切り出す。生成パーツは基準画像の位置・大きさへ合わせたうえで、隠れる部分（目の下の肌、まぶたに隠れる白目・虹彩）と差分（閉眼まつ毛、開いた口）にだけ使う。隠れる部分を周囲の色から推定する方式は、品質が不足したため採用しない。代わりに、基準画像をユーザーの生成ツールで部分的に描き直した**同じキャンバスの差分画像**（依頼A・B・C・半目）を使う。選択範囲の案内は `requests/generative-fill-guide.png`（A：目にかかる毛束、B：目、C：額の前髪）。

差分画像は、依頼A〜Cと半目とも、基準画像の顔を切り抜いた `requests/face-crop-1024x576_x598_y762.png`（基準画像のオフセット(598, 762)）を編集したもの。再生成スクリプトが、倍率・オフセットを記録した値で基準画像へ貼り込む（境界16pxでなじませる）。

| 段階 | 倍率 | オフセット | 範囲外の差(RMS) |
|---|---|---|---|
| A 毛束なし | 0.7031 | (598, 762) | 1.3 |
| B 目なし | 0.7030 | (597.9, 762) | 0.5 |
| C 瞬き | 横0.6116・縦0.6095 | (598.2, 762.4) | 3.6〜5.7（髪の線がわずかにずれるため、まつ毛と二重の線だけを使う） |
| 半目 | 1.0 | (598, 762) | 髪の細い輪郭のみ |

### 12.3 再生成の手順

リポジトリのルートで実行する。必要なもの：Windows PowerShell 5.1、Python 3（numpy・Pillow）、GIMP 3.2.6。作業場所は `assets/ciel/`。

```powershell
.\scripts\live2d\prepare-source.ps1      # SOURCE_V2_READY       master/ normalized/ manifest.json
.\scripts\live2d\build-eye-layers.ps1    # EYE_LAYERS_READY      layers/eyes/
python -I scripts\live2d\trim-half-eye-layers.py   # HALF_EYE_TRIMMED  半目レイヤーの後処理（必ず build-eye-layers の後に実行）

$env:CIEL_PROJECT_ROOT = (Get-Location).Path
$env:GIMP3_DIRECTORY = Join-Path $env:CIEL_PROJECT_ROOT '.local/gimp-production/profile'
$gimp = Join-Path $env:LOCALAPPDATA 'Programs/GIMP 3/bin/gimp-console-3.2.exe'
foreach ($s in 'build_blink_psd.py', 'build_half_eyes_psd.py') {
  & $gimp --new-instance --no-data --no-fonts --no-splash --console-messages `
    --batch-interpreter=python-fu-eval `
    --batch "exec(open('scripts/live2d/gimp/$s',encoding='utf-8').read())" --quit
}   # SOURCE_V2_BLINK_PSD_READY / SOURCE_V2_HALF_EYES_PSD_READY  psd/
```

終了コードだけで成功と判断せず、各スクリプトの完了表示と、更新された `report.json` を確認する。clone 直後にゼロから再生成して、`master/ciel-upper-body-2x.png` のSHA-256が `7031BA09…` と一致することを確認済み（2026-10-08）。

| `layers/eyes/{R,L}_{lash,crease}_closed.png` | 閉眼のまつ毛と二重の線 |
| `layers/eyes/{R,L}_{sclera,iris,lash,crease}_half.png` | 半目の4レイヤー |

| `psd/ciel-half-eyes.{psd,xcf}` | 8レイヤー：左右の `*_{Sclera,Iris,Lash,Crease}_Half` |

L/R はキャラクターから見た左右（キャラの右目は画面の左側）。重ね順は 目のない顔 < 白目 < 虹彩 < まつ毛 < 二重の線。

目の4レイヤーは、通常の顔と目のない顔の差から色で分類して作る。

| レイヤー | 作り方 |
|---|---|
| `sclera` | 差のある範囲を穴埋めした目の形。まつ毛の上端より上は除く。虹彩・まつ毛の下は見えている白目から補完 |
| `iris` | 白目らしくない色の画素の凸包。まつ毛の下に隠れる上部は楕円の範囲で補完 |
| `lash` | 暗い画素。目のない顔を背景として透明度と色を逆算 |
| `crease` | まつ毛の上の桃色の線（二重の線）。同じく逆算 |

目のない顔に4レイヤーを重ねた結果と通常の顔の差はRMS 2.7（左右とも）。半目も同程度。半目の虹彩は、補完部がまつ毛の上にはみ出し、まつ毛の色にも虹彩の青が混ざるため、`trim-half-eye-layers.py` で削る・置き換える。

### 12.5 Cubismの作業モデル

`assets/ciel/rig/ciel-blink-test.cmo3`（Cubism Editor 5.3.04）。目だけの検証モデルで、体・髪・口は未分離。

**開閉キー**（「左目 開閉」「右目 開閉」、左右同じ。0.0・0.5・1.0 の3点）：

| 部品 | 0.0（閉眼） | 0.5（半目） | 1.0（開眼） |
| --- | --- | --- | --- |
| `*_Sclera/Iris/Lash/Crease`（開眼） | 不透明度0 | 0 | 100 |
| `*_Sclera/Iris/Lash/Crease_Half`（半目） | 0 | 100 | 0 |
| `*_Lash_Closed/Crease_Closed`（閉眼） | 100 | 0 | 0 |

虹彩（`*_Iris`）は左右とも白目（`*_Sclera`）でクリッピング済み。0.0〜0.5 と 0.5〜1.0 の間は不透明度のクロスフェードで、0.25 付近は2つの層が半透明に重なって目がやや薄く見える。

**メッシュ**：開眼の `Sclera`・`Iris`・`Lash` は「変形度合い（大）」（点の間隔25）で生成済み。`Crease`（二重）と閉眼の2枚は絵が非常に細く、自動生成では点が出ないため、取り込み直後の四角形メッシュのまま（変形せず、不透明度の切り替えだけで扱う）。

**確認結果**（2026-10-08、Cubism上）：1.0 は元の目、0.75 は少し細い、0.5 は元画像どおりのジト目で左右対称、0.0 は両目とも閉眼。開眼時に閉眼まつ毛のはみ出しはない。

**モデルへ素材を足す手順**：PSDを再生成したら、既存モデルの元PSDを「差し替え」ず、PSDを開いて既存モデルを選び、「全てのレイヤーを新規アートメッシュとして追加」で取り込む（差し替えるとレイヤーIDがずれ、虹彩などへ別の部品画像が割り当てられた）。追加直後は全レイヤーが表示されるので、表示・不透明度・キーを設定し直す。

### 12.6 Cubism Editorの操作メモ

- **起動**：起動に時間がかかる。多重起動を避けるため、起動の操作は1回だけにして待つ。起動時の「スタート」ダイアログで FREE版 / PRO版のトライアルを選ぶ。毎回出ない設定は見つからなかった。ウィンドウは `java.exe` が所有する。
- **ファイルを開くダイアログ**：パスを入力して Enter では開かない。「開く」ボタンを押すか、一覧をダブルクリックする。PSDから新規モデルを作るときの解像度は、1/2プレビューが推奨。
- **メッシュの自動生成**：メッシュ編集モード（Ctrl+E）でツール詳細の「AUTO」アイコンを押すと、プリセットのポップアップが出るが、生成ボタンはない。**ポップアップのプリセットを、現在と別のものに切り替えた時に生成される**（同じものを選び直しても動かない）。複数レイヤーを選んだまま確定すると、点のないレイヤーがあれば「3点以上の点が必要です」と出て確定できないので、1枚ずつ処理する。非表示のレイヤーにはメッシュが生成されない。
- **キー**：スライダーのクリックでは、キーの位置からわずかにずれ、インスペクタが灰色になる。値欄に数値（0／0.5／1）を直接入力する。非表示（目のアイコンが消えた）レイヤーは「キーの3点追加」の対象外になるので、表示にしてから追加する。スライダー上で右クリックすると、近いキーの位置へ値が吸い付き、「キーフォーム追加（左）／削除（右）」の小さなメニューが出る。
- **複数選択**：複数レイヤーを選んで不透明度を入力すると、選択した全レイヤーに同じ値が入る。
- **表示の更新**：キャンバスの表示は更新が遅れることがある。値を変えたあと、数秒待ってから確認する。
- **クリッピング**：クリッピング欄へ文字を入れるのではなく、欄の右端の一覧を開いて対象にチェックを入れ、実際の表示で確かめる。
- **画面操作で自動化する場合**：画面操作の許可に `Live2D Cubism Editor 5.3` と `java.exe` の両方が必要。表示倍率が125%の環境では、操作座標に注意する。

### 12.7 FREE版とPRO版の制限

FREE版でも、取り込み・メッシュ・パラメーター・保存はできる。**書き出しの前のテクスチャアトラスの作成で止まる**：FREE版は、テクスチャが1モデルにつき1枚、1枚の大きさは2048pxまでで、素材v2の基準画像（2172×2896）は縮小しないと収まらない（公式の比較表とフォーラムの報告による。公式の最新の数値は購入前に確認する）。アートメッシュは100個まで。

素材v2の解像度のまま `.moc3` を書き出すには、PRO版（42日間のトライアルがある。1台1回、FREE版へ戻してもカウントは止まらない）を使う。トライアルは、書き出しの準備が整ってから始める。期限後にFREE版へ戻ると、2048pxを超えるモデルの保存・書き出しができなくなる報告があるので、期限前に書き出しまで済ませ、保存した `.cmo3` と書き出し物を複数残す。商用利用は、FREE版は年間売上1,000万円未満の個人・小規模事業者に限られる（公式の記載）。

### 12.18 Gitの容量とUnityへの組み込み（2026-10-08）

`rig/ciel-blink-test.cmo3` が50MBを超え、GitHubの推奨上限に触れたため、**作業モデル（`.cmo3`・`.can3`）は Git LFS で管理する**（`.gitattributes`）。履歴は書き換えない（既存の1回分は通常のGitオブジェクトとして残る）。clone後は `git lfs install` を一度実行する（`git lfs pull` で実体を取得）。GitHub無料枠のLFSは容量1GB・転送1GB/月なので、`.cmo3` のコミットは節目（動作確認が取れたとき）だけにする。

**Unityが読むのは、Cubismから書き出した `.moc3`・テクスチャ・`.model3.json` など。`.cmo3` は不要。** 書き出し物は小さいので、通常のGitで `unity/Assets/Characters/Ciel/` に置く（Live2D SDK本体は従来どおりGit除外）。`.cmo3` は、モデルの編集を引き継ぐ人にだけ必要。書き出し（テクスチャアトラス）はPRO版が必要（第12.7節）。

**描画順の設定（2026-10-08）**：取り込んだ11レイヤーに、インスペクタの「描画順」を設定した。目（開眼・半目・閉眼）は500のまま。`Hair_Front` 700／`Face_Skin` 200／`Ear_R`・`Ear_L` 150／`Hair_Under_Ear` 120／`Neck_Gear` 90／`Chest_Gem` 80／`Waist_Belt` 70／`Outer_R`・`Outer_L` 50／`Body_Base` 10（大きいほど手前）。設定後、顔・耳・前髪・目・衣装・体が元の絵のとおりに重なることを確認した。値を入れるたびに画面が約20秒止まるので、入力後は待ってから次へ進む。次の作業：顔の角度のパラメーターで前髪・耳・顔の肌が別に動くことの確認。

### 12.19 顔の角度X（2026-10-08）

ファーを直したPSDは、既存のレイヤーに「差し替え」で反映できた（`ciel-head-body.psd` の差し替え。名前・順序が同じなのでIDはずれず、描画順も保たれた）。顔の4部品（`Hair_Front`・`Face_Skin`・`Ear_L/R`・`Hair_Under_Ear`）を1つのワープデフォーマ `Head_Warp`（5×5分割）に入れ、「角度X」に -30・0・30 の3点キーを付けた。-30 と 30 では、中央の制御点を左右へ動かして、顔の部品が一体で向きを変えることを確認した。**まだ粗い**：制御点の動きが大きく、耳と枠が曲がる。顔の肌・耳・前髪をそれぞれ別の速さで動かす（奥行きの表現）、角度Y・Zのキー、首・体・衣装の追従は未設定。FREE版のデフォーマ数は50個まで（現在1個）。

操作の注意：保存時に「未使用の原画があります。削除しますか？」と出たら、差し替え前の古い原画なので「はい」。パラメーターのキーは「3点追加」で付けた直後の値がずれる（-17など）ので、値欄に数値を入れ直す。キーの上で値を変えてから、デフォーマの制御点を動かす。

### 12.20 Unityでの書き出しの確認（2026-10-08）

PRO版のトライアルで、テクスチャアトラス（4096×4096、1枚）を作り、`unity/Assets/Characters/Ciel/` へ書き出した（`Ciel.moc3`・`Ciel.model3.json`・`Ciel.cdi3.json`・`Ciel.4096/texture_00.png`、合計1.9MB）。Cubism SDKが自動で `Ciel.prefab`・`Ciel.controller`・`Ciel.asset` と `.meta` を作る（これらもGit管理）。テクスチャのインポート設定は最大サイズ 4096（既定の2048だと縮む）。

確認用に `unity/Assets/Editor/CielRenderCheck.cs` を追加した。`Unity.exe -projectPath unity -executeMethod Ciel.EditorTools.CielRenderCheck.Run -logFile <log>`（`-batchmode` は付けない。付けると再生モードへ移れず止まる）で、再生モードに入り、パラメーターを変えて5枚を `.local/render-check/` へ撮影する（`CIEL_RENDER_CHECK_DONE`）。結果：まばたき（半目・閉眼）は設定どおり動く。角度Xは顔・髪・耳が向きを変えるが、旧 `Face_Base`（耳・髪・体を焼き込んだ旧レイヤー）が動かずに残り、耳が二重に見える。次は `Face_Base` の削除。

**アプリからパラメーターを渡す作法**：Cubismは毎フレーム、`CubismParameterStore` が値を保存値へ戻す。外から値を渡すときは `LateUpdate` で設定し、続けて `CubismModel.ForceUpdateNow()` を呼ぶ（設定だけだと描画に反映されない）。エディタの画面で、再生していないときにインスペクタの値を変えても、同じ理由で反映されない（モデルが消えて見えることがある）。

### 12.21 顔の向きの見本（2026-10-09）

顔の向きを平行移動だけで作ると、目が顔から離れ、耳が二重に見える（12.20）。そこで、ユーザーが、同じ切り抜き `requests/face-hair-crop-1536x1536_x318_y236.png` から、顔を左右に向けた見本を生成した（依頼J）。`generated/J3_Viewer_Left_Approx30.png`・`J1_Viewer_Left_Approx15.png`・`J2_Viewer_Right_Approx15.png`・`J4_Viewer_Right_Approx30.png`（1536×1536、「左右」は画面の左右）。**画像全体が描き直されているので、レイヤーには使わず、パーツの動き量を測る見本にする。**

`scripts/live2d/measure-head-turn.py` が、虹彩（青い塊）の位置を測り `assets/ciel/head-turn-measure.json` に保存する（切り抜き内の座標）：

| 向き | 画面左の虹彩x | 画面右の虹彩x | 目の中点x | 目の間隔 |
|---|---|---|---|---|
| 左30 | 446 | 770 | 608 | 324 |
| 左15 | 531 | 896 | 713 | 365 |
| 正面 | 601 | 971 | 786 | 370 |
| 右15 | 697 | 1049 | 873 | 352 |
| 右30 | 877 | 1171 | 1024 | 294 |

顔の中心は、正面から 左30＝−178、左15＝−73、右15＝+87、右30＝+238 px（15度と30度で比例しない）。目の間隔は向きとともに縮み、手前の目は大きく、奥の目は小さくなる（虹彩の面積：手前 約11000、奥 約4300〜5200）。目の高さは 786〜813 でほぼ一定。したがって、目・鼻・口は、横の動きに加えて、**横幅を縮める変形**が要る。Cubismの角度Xは、−30・−15・0・15・30 の5点キーにする。

### 12.22 口と後ろ髪のレイヤー（2026-10-09）

依頼G（口3種）と、後ろ髪だけの透明PNG（`generated/ciel-rear-hair-layer-1536.png`）から、`scripts/live2d/build-mouth-and-hair-layers.py`（`MOUTH_HAIR_LAYERS_READY`）が `layers/head/{Mouth_Closed,Mouth_Small,Mouth_Large,Hair_Back}.png` を作る。

- **口（G1〜G3）**：切り抜き `face-hair-crop-…` の口だけを描き直した部分編集で、口以外の差は 0。大きさ・位置も一致（倍率1.0）。口の範囲（切り抜き内 x681〜895・y940〜1103、余白14px）を、Gの画素のまま切り出す。重ねても継ぎ目は出ない。八重歯は小・大にだけ描かれ、閉じた口（G1）には描かれない。大きい口は幅が広め（動かして気になれば縮める）。
- **後ろ髪**：生成した透明PNG。外形は元の絵と数画素の範囲で一致し（髪の端 y800 で 135/136、1482/1487）、99.9%が元の絵の範囲内。頭頂部の形が少し違うが前髪と耳の後ろに隠れる。依頼Hの「後ろ髪を消した顔」は、全体が描き直されたため使わず、依頼H2（消す）より「後ろ髪だけを描く」方が早かった。**画像全体が描き直されるかは、切り抜きとの差の数値で確かめる。**
- `scripts/live2d/gimp/build_head_body_psd.py` が、後ろ髪・口3種を足した15レイヤーのPSD `psd/ciel-head-body.psd`（約108MB）を出力する（`HEAD_BODY_PSD_READY`）。

次：Cubismへ、既存の `ciel-head-body.psd` を「差し替え」で反映し、`Hair_Back` と口3種を取り込む。口は `ParamMouthOpenY` の 0・0.5・1 に 閉じ・小・大 を割り当てる。後ろ髪が入ったら、旧 `Face_Base` を外す。
