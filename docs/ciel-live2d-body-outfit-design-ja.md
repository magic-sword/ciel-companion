# シエルの腕と上着のモデル設計案

2026-10-15。上着の揺れ、上着の表示切り替え、手のポーズ切り替えに対応するための素材分割とリグの設計案。

基本方針は、上着を外しても成立するインナー姿のボディを先に作り、肌と袖を共通の関節へ接続し、服だけに局所的な揺れを加えること。分割位置は、布の縫い目、関節、前後の重なり、独立して揺らす範囲から決める。

## 制作開始時のモデルの課題（v47）

`assets/ciel/current/layers.json`、`Body.png`、`Jacket_Front.png`、承認済み原画と `assets/ciel/rig/ciel.cmo3` を確認した。

- `Body.png` には胴体と左右の腕の絵が含まれる。ただし独立した腕のメッシュや関節はなく、手はキャンバス下端までの素材では完成していない。
- `Jacket_Front` は左右のファー、袖、装飾をまとめて持つ。`Jacket_Back` と合わせた前後2枚では、左右や袖・襟を別々に制御できない。
- 編集モデルの接続は、上半身の曲面Z → 上半身の曲面Y → 呼吸。その下に `Jacket_Front` と `Jacket_Back` が直接入り、`Body` は「胸の曲面」を経由する。胴・腕が胸の局所変形をまとめて受け、服との追従差が生じる可能性がある。
- 現行ランタイムの物理グループは前髪、横髪・耳、後ろ髪、胸の4つ。上着専用の出力は未設定。

原画では上着の肩が落ち、肩の肌が見えている。この着方を維持する場合、肩位置の支持と垂れたファー・布の動きを分ける必要がある。一般的な肩に密着するジャケットのリグをそのまま当てはめない。

## 公式資料と参考モデルから得られる原則

公式の[イラスト加工チュートリアル](https://docs.live2d.com/4.2/cubism-editor-tutorials/psd/)は、腕を上腕・前腕・手に分けること、隠れている部分を描き足すことを説明している。本文のある4.2版を参照した。最新ページでは主に動画で案内されている。

[親子関係の組み合わせ](https://docs.live2d.com/cubism-editor-manual/combintion-of-parent-child-relation/)では、回転同士の連結を腕の関節に使い、回転の下のワープで形を調整できる。ワープの子にある回転は、親によって移動・回転されるため、胴のワープだけで腕の遠近形状まで作ることはできない。腕自身にも体の向きに対応する補正を持たせる。

手元の公式サンプル `hiyori_pro_t11.cmo3` を既存の `cmo3_tool.py` と `analyze-rig.py` の構造解析関数で読み、次を確認した。参考モデルの絵やモデルデータは流用・再配布しない。

| 観察した構造 | シエルへの適用 |
| --- | --- |
| 呼吸の下で、胴体と左右の肩すくみが分岐する | 腕を胸の局所変形から独立させる |
| 左右とも肩すくみ → 腕位置 → 上腕回転 → 前腕回転 | 共通の関節チェーンを作る |
| 腕Aと腕Bに別の階層・メッシュがある | 大きく異なる腕ポーズには別素材を使う |
| 腕Bには手回転があり、手前・手裏・親指・袖が属する | 手の奥行きや袖口との重なりを個別に扱う |
| 腕位置や一部の上腕ワープにも体の向きのキーがある | 肩位置だけでなく腕の幅・短縮も補正する |

サンプル内の袖が手回転に属する配置は、その絵と動作に合わせた構成。シエルでは袖口の本体を前腕側に置き、手首を回しても袖全体が回りすぎないようにする。ここから先は、上記の原則をシエルに当てはめた提案である。

## 素材の分け方

L/Rはキャラクター自身の左右。現行キャンバス2172×2896と中立姿勢の位置合わせを維持する。手を画面内へ上げる場合は、下端で切れている素材から手首と手を新たに描き起こす。

| 素材 | 分割単位 | 描き足しと用途 |
| --- | --- | --- |
| 胴体 | `Torso_Skin`、`Inner_Top`、`Chest_Gem`、腰・ベルト・スカート | 上着なしで肩・脇・インナーの輪郭が完成する。宝石は布の揺れから独立 |
| 肌の腕 | 左右の `UpperArm`、`Forearm` | 肩・肘の接続を重ねて描く。切断面に外輪郭線を描かない |
| 手 | 左右の `Hand_Relaxed`、`Hand_Open`、`Hand_Fist` | 手首中心と太さを共通化。まず完成した手全体の差分を使う |
| 上着の身頃 | 背面、左右の前身頃 | 動くと見える脇・内側まで描く。左右を個別に変形できるようにする |
| 裏地 | 左右の `Jacket_Lining` | 外側の布の裏として所属。肌の腕や胴体に色を焼き込まない |
| ファー | 左右の根元と必要な垂れ部分、必要なら背面襟 | 支持部と揺れる先端を分ける。首輪とは別の着脱対象 |
| 袖 | 左右の上腕袖・前腕袖 | 肘の縫い目や陰影で分割を隠す。内側を描き足して曲げに対応 |
| 袖口 | 左右の前側・奥側・内側の暗部 | 奥側 → 手首 → 前側の重なりで筒状に見せる |
| 装飾 | 袖の金具・LED、必要ならストラップ | 取り付け先へ追従させる。金属を布と同じように伸縮させない |
| 上着の影 | 肩・腕・インナーへ落ちる影 | 上着と同時に消す。受け側の肌・布にクリップし、追従を調整 |

すべての線・塗りを別メッシュにする必要はない。動き、表示状態、前後関係が同じものはまとめる。裾の小さな変形は身頃の子ワープで作り、独立したフラップだけを素材として分ける。

肌は採用済みのv46の色に合わせる。上着を外した状態でも首輪とインナーを残す。見えない脇や袖裏の描き足しは、既存画像を切るだけでは完成しない。

## デフォーマの親子関係

次は片腕の模式図。反対側にも同じ構成を作る。「補正」はワープ、「回転」は回転デフォーマ。

```text
上半身の曲面Z
└─ 上半身の曲面Y
   └─ 呼吸
      ├─ 胴の向き補正
      │  ├─ 肌・インナーの局所補正
      │  └─ 上着の身頃補正 → 身頃・裏地の局所揺れ
      ├─ 首の位置 → 既存の首・頭の階層
      └─ 肩位置・肩すくみ
         └─ 上腕回転
            ├─ 上腕の肌補正 → UpperArm
            ├─ 上腕袖の姿勢補正 → 袖の局所揺れ → 袖・装飾
            ├─ ファーの支持補正 → ファーの局所揺れ
            └─ 前腕回転
               ├─ 前腕の肌補正 → Forearm
               ├─ 前腕袖の姿勢補正 → 袖の局所揺れ → 袖・装飾
               ├─ 袖口補正 → 袖口の奥側・前側
               └─ 手首回転 → 手の向き補正 → 手ポーズ差分
```

肌と袖は共通の回転を継承し、それぞれ別の子ワープで形を作る。袖の揺れの子に肌や手を入れない。各メッシュの変形親は1つなので、身頃と腕の両方を親にすることはできない。袖の付け根は、身頃側と袖側に同じ肩・腕パラメータによる接続補正を作って整合させる。

肩落ちのファーは、支持位置と胴側の接触位置を姿勢補正で合わせ、垂れ部分だけを揺らす。大きく腕を上げるときは上着のずれ・持ち上がりもキーで作る。

肘や身頃と袖の接続に必要なら[グルー](https://docs.live2d.com/cubism-editor-manual/glue/)を使う。グルーはメッシュの頂点を吸着する機能で、布の衝突判定を行うものではない。まず重なりと形状補正で接続し、隙間が残る縫い合わせに限定する。肌と脱げる服を恒常的に吸着させる構成は避ける。

## 着脱と手の切り替え

変形の親子関係と、表示を管理するパーツの階層を別に設計する。上着の表示管理には身頃、裏地、袖、袖口、ファー、上着専用の金具・影を含め、肌・インナー・首輪・手は含めない。

初期実装は `ParamCielJacketVisible` の0/1で、対象メッシュの不透明度を揃える方式を推奨する。制御側は端点だけを設定し、毎フレームの更新やモーションで値が戻らないようにする。これは上着あり／なしの状態切り替えであり、腕を袖から抜く脱衣アニメーションを作る場合は別の素材と動作設計が必要になる。

手は手首回転の下で完成形の差分を排他的に表示する。3つの手を連続値で切り替えるなら、中間値を手の変形として補間せず、選択状態へ丸める。初期段階は指ごとの関節を作らず、自然手・開き手・握り手から始める。ピースや指差しは必要な時点で追加する。

SDKの[Pose機能](https://docs.live2d.com/cubism-sdk-manual/pose/)はパーツの排他的な表示と連動を扱える。ただし現行 `Ciel.model3.json` にはPose参照がない。採用する場合はUnity側のコントローラ、読み込み、更新順序を確認し、同じ対象を独自の不透明度制御と同時に管理しない。

胸の前に手を出すなど、輪郭・短縮・描画順が大きく変わる動作には腕全体の差分を追加する。ひよりの腕A/Bが参考になる。大きな手の向き変更も、掌・手の甲の素材差分で対応する。

## 上着の物理演算

[公式の物理演算](https://docs.live2d.com/cubism-editor-manual/physics-operation/)は入力パラメータから振り子を計算し、出力パラメータを動かす。シエルでは物理出力を局所揺れ専用にし、関節のポーズを上書きしない。

| 制御 | 提案するパラメータ | 用途 |
| --- | --- | --- |
| 関節 | `ParamCielArmL/R`、`ParamCielElbowL/R`、`ParamCielWristL/R` | モーションまたは操作で設定 |
| 上着の状態 | `ParamCielJacketVisible` | 表示の0/1 |
| 手の状態 | `ParamCielHandPoseL/R` | 排他的な選択 |
| 物理出力 | `ParamCielJacketHemL/R`、`ParamCielSleeveSwingL/R`、`ParamCielFurSwingL/R` | 身頃・袖・ファーの局所揺れ |

左右のファー、左右の身頃下部、左右の袖を初期の揺れ候補とする。身頃は体の傾き、袖は体と腕の動き、ファーは支持位置の動きに応じて入力を調整する。最初は小さな振幅から始める。肩・肘・袖口の接続点は局所揺れでずらさず、中央や末端の布を変形させる。

服と身体の接触は姿勢ごとの補正と揺れの可動域で成立させる。急な腕上げや着脱直後に大きく跳ねないか、EditorとUnityの両方で確認する。表示を消すだけで物理計算は停止するとは限らないため、再表示時の状態も確認する。

## 制作の順番と確認条件

1. 上着なしの中立姿勢を完成させる。胴と腕を分け、肩・脇・肘・手首と手を描き足す。
2. 片腕の肩・肘・手首と3つの手差分を仮実装し、可動範囲と素材分割を確定する。
3. 片側の袖、袖口、ファー、身頃を追加し、肩落ちの着方で接続を調整する。
4. 反対側を作り、上着の一括表示切り替えと影・装飾の所属を確認する。
5. 局所揺れを加え、必要な腕ポーズだけ差分を追加する。
6. 正式採用前に全表情と頭の動きとの組み合わせを確認し、既存のランタイム更新手順でUnityへ反映する。

検証は、上着あり／なし × 手3種 × 左右の腕下げ・肘曲げ・予定する腕上げを基本とする。各状態で体の向き・傾き・呼吸の端点を確認し、複合姿勢と切り替え途中も動かす。可動域は仮実装で決め、素材の描き足し範囲に反映する。

合格条件は、関節の穴・二重輪郭・袖口の隙間がないこと、金具が布と一緒に伸びないこと、脱いだ状態に服の影・ファー・装飾が残らないこと、手首中心が切り替えでずれないこと。胸の局所変形で腕全体が伸びないことと、揺れを最大にしても布が肌を突き抜けて見えないことも確認する。

## 素材生成・切り分けの制作手順（v56以降）

マスター画像を着用完成図とし、服の形状・肩の開口・ファーの内縁・金具の位置を判断する。別の完成図を先に生成する必要はない。緑色の仮身体は任意の作業補助であり、今回の制作では使わない。単色を抜くだけでは、毛先の半透明部分、隠れた布、身体の手前と奥の区別まで解決できない。

### 原画・補完画像・マスクを分ける

1. 原画は変更せず保存し、使用画像とハッシュを記録する。最初に着用状態のまま、身体・上着・髪の境界と前後関係を決める。
2. 可視部分はマスターから抽出する。素材を単独で描き直すと着用時の曲率や肩との関係が変わりやすいため、原画の位置関係を基準にする。
3. 着用状態を参照し、必要な部材の隠れる範囲も含めて生成する。小さな毛束の欠けなら局所補完でよいが、後ろ襟・背面・脇の連続性がない場合は、首の後ろから脇までつながる部材全体を描く。見える細い隙間だけを布の帯で埋めない。対象、カメラ、変えてよい範囲、位置・倍率・輪郭を保持する範囲を明記する。
4. 共通座標へ登録し、原画由来の前面と生成した背面を描画順で合成する。局所補完は必要な領域だけ採用するが、背面部材の隠れる中央部分まで切り捨てない。マスターの可視部分を置き換えた場合は、その場所を来歴へ記録する。「生成は隠れた場所だけ」と誤って記録しない。
5. 原画、生成元、抽出マスク、補完範囲、配置、レイヤー一覧を保存する。生成元ファイルは残し、PSD/XCFとは別に再現可能な入力とスクリプトを持つ。

画像生成の指示例：

> この着用画像の構図・倍率・上着の外形を保つ。前髪に隠れていたファーの短い毛束だけを補完する。肩の開口と中央の胸元は開けたままにする。長い髪をファーとして残さない。前後に同じ布を二重に作らない。合成に必要な素材は透過背景で出力する。

### 所属と前後関係を確認する

色だけで切り分けない。白いファー・白い髪・白い服・明るい肌は近い色になる。身体の切り抜きでも、胸から腰へ引いた大まかなポリゴンが隣の腕を拾うことがある。境界を拡大し、素材を単独表示して腕や髪の断片が残っていないことを確認する。

| 境界 | 決めること | 確認方法 |
| --- | --- | --- |
| 前後ファー | 肩の後ろへ回る範囲と、腕より手前へ出る毛束 | 前・後ファー、上腕を個別に隠し、肩の開口と毛束の接続を比較 |
| 胴体と腕 | 胴体素材へ隣の腕が混入しない範囲 | 胴体だけを表示し、胸の下から腰までの左右の輪郭を確認 |
| 上着の青い面と白い袖 | 連続する一枚の服の表裏と折り返し | 重複した前身頃・裏地を重ねず、単独表示と着用表示を比較 |
| 上着の背面 | 後ろ襟から背中・脇へ回り込む一続きの部材 | 隠れる中央も描いた単独表示と、身体による遮蔽後の着用表示を比較 |

前後ファーは、単に画像を上下や斜線で二分して終わりにしない。身体の裏にした領域が上腕で隠れると、素材の再合成が原画どおりでも着用時に毛束が欠ける。前面の素材とメッシュが肩側まで届くようにし、接続には隠れた重なりを設ける。分割線が見える場所では、前側のアルファも毛束の輪郭に合わせ、メッシュの斜めの切り口がそのまま見えないようにする。後ろ側全体を腕の前へ出すと肩への回り込みが失われるため、変更範囲を接続部分に限定する。

一つの素材を隠しても、同じ場所に別の白い断片が現れる場合がある。そのときは見た目だけで所属を決めず、問題の画素に重なるメッシュ、UV、テクスチャのアルファを調べ、最前面の不透明な素材を特定する。今回の脇腹では、胴体と背面の両方を確認することで、背面に残った旧前縁まで除去できた。

### 登録と検証

素材キャンバスは3000×3800、モデル原点に対するX余白は414px。マスター由来の素材には、以前の生成画像の1.90倍や移動量をもう一度掛けない。CMO内の縮小された画像枠・アトラスのUV・メッシュ頂点・親ワープの座標系を同時に整合させる。原点と表示範囲は別であり、自然な腕をキャンバス内へ縮めない。

検証は次の三つを分けて行う。

- **抽出の一致**：補完前の素材を重ね直して、対象領域の原画画素と一致すること。これは抽出先の正しさや着用時の遮蔽までは証明しない。
- **素材の意味と着用形状**：単独表示、部位を隠した比較、マスターとの同倍率比較で、腕の混入、二重輪郭、肩の穴、ファーの直線的な切れ目を確認する。補完後は変更を許可した範囲外の画素が変わっていないことも調べる。
- **実モデル**：Editorから書き出したSDKで、上着着脱・手3種・腕と肘・揺れの両端・呼吸・既存表情を確認する。メッシュの元頂点・編集頂点・全キーフォーム・UVの要素数と三角形の参照先を照合し、PSD/XCFが最終PNGと一致することを確認する。

v56では、肩側で途切れたファーの局所補完と前後の分割位置を修正した。脇腹の二重輪郭は、旧上着の背面素材に白い前縁・ファー・袖の断片が含まれていたことが主因だった。背面を青い布だけの面へ修正し、胴体の切り抜きに残っていた腕の小さな断片も除く。部位名や描画順だけで正しさを判断せず、実際に手前に出ている画素の所属を調べる。局所補完と背面の修正は見える領域にも使用するため、v55の「マスター領域の全画素が原画と同一」という条件はv56全体の合格条件として引き継がない。

v57では、露出する肩の上をファーの前後分割線が通っていたことを修正した。上腕のマスクに合わせた透過加工を取り除き、前後の接続を肩の露出より上へ移す。境界を見える場所へ置いたままアルファを調整しても、切り口は自然な毛束にならない。右脇の白い三角形は`Hair_Back`であり、胴体の断片ではなかった。背面の布が脇まで届くようにし、髪と衣装の間に布がある前後関係を成立させた。詳細は[v57の比較と検証](../assets/ciel/rig/proofs/body-outfit-v57/README.md)を参照。

### 背面を部材全体で生成する（v58）

v57の青い背面は生成画像の中央を矩形に切り出して拡大しており、布の流れや後ろ襟の形を十分に表現できなかった。ファーの切り分け位置だけを変更しても、首の後ろを包む部材が描かれていなければ連続性は作れない。

v58ではマスターの着用図と試作の着用表示を参照し、連続する白い後ろ襟、青い背中の中央、両脇へ回る布を一つの透過素材として生成した。正面モデルに重ねるため、指示するカメラは「正面から見た、身体に隠れる背面部材の投影」。キャラクターを後ろから見た立ち絵とは異なる。首の後ろのファーを左右の離れた二本にせず、中央までつながる帯として描き、布も中央を透明にしない。肌・髪・インナー・前身頃・袖を含めない。

生成原本は保存し、独立したアルファのごみを除去後、一度の等方拡大と平行移動で登録する。細い布の切り出し拡張や、ファーをプログラムで描き足す処理は行わない。位置合わせは後ろ襟の高さだけで決めず、左右の肩幅と、インナーの裾より下の脇まで同時に確認する。襟の位置が合っていても背面の裾が短ければ、脇の下端で再び髪が露出する。前面ファーや袖は既存素材を保ち、生成した背面を胴体・上腕より奥へ置く。全背面の単独表示、前面ファーを外した身体との表示、通常着用の三つで確認する。身体に隠れて見えなくなる範囲も、実際のSDKで不透明なファー・布が存在することを確認する。

現在の背面は後ろ襟と布が一体の素材・メッシュで、胴体ワープに追従する。後ろ襟へ独立した物理演算を付ける段階では、この完成した形を基準に分離し、布側の隠れる部分を描き足して重なりを確保する。[v58の素材と着用比較](../assets/ciel/rig/proofs/body-outfit-v58/README.md)を参照。

### 脇の接続を隠し代で成立させる（v59）

v58の左右差を調べると、胴体の中心とマスター由来の前面の中心が約28pxずれ、左では前面が胴体へ重なる一方、右では隙間から背面が帯状に見えていた。中心のずれは露出量の差を説明するが、位置を厳密に合わせるだけでは生成素材や動きの差に対して脆い。

v59では、透明な円柱状の身体の奥側を包む面を正面から見た形として、青い背面・側面を一続きで生成する。背中の中央、両脇、手前の布で隠れる範囲まで不透明に描く。見える隙間には滑らかな布の面が続き、外周の輪郭・素材の切り口・裾は身体または手前の上着の下へ隠れる配置にする。側面に独立したフラップや細い縁、縦のパネル線を加えると、それが隙間から別の布として見えるため、奥側の面は広い曲面と控えめな陰影で描く。

ファーはv58の原寸RGBAと位置を保護し、青い布だけを変更する。胴体・腕・手・前面の素材と位置は保ち、広い奥側の面で重なりの余裕を作る。中立姿勢に加え、前面の境界を水平に-40/0/+40pxずらした検査でも、隙間と両端24pxの隠し代が不透明な布で覆われることを確認する。これは境界の余裕の検査であり、大きな腕上げ全体の見た目は別途検証する。[v59の素材・着用比較・検証](../assets/ciel/rig/proofs/body-outfit-v59/README.md)を参照。

### 身体の基準と衣服内の明暗を分ける（v60）

身体の中央は首輪・胸の飾り・腹部を基準として先に決め、衣服をなじませるために身体を横へ動かさない。v59では以前からの胴体中心のずれを残していたため、v60では首輪の軸へ右28.5pxの登録補正を行い、この中央配置を衣服調整の固定基準にする。上着の位置を合わせるための補正ではない。

連続した面と十分な隠し代だけでは、奥側の布が外側と同じ明るさで照らされていると、脇に浮いた円弧や別の板として見える。生成時にも、奥側は身体・手前の衣服に遮られた内側の面、手前側は外光を受ける外側の面として光の役割を指定する。衣服内を示す暗い帯は奥側へ描き、手前の青い面へ重複して焼き込まない。表側に必要な立体面の陰影やファーの落ち影とは分けて扱う。

v60では既存の広い奥側の形・アルファを保持し、青い面だけを内側の陰影へ描き直す。前面も既存の青い領域だけを、暗い内縁帯のない外側の照明へ変更する。生成結果の輪郭や金具を丸ごと置き換えず、元のマスク内へ生成RGBを登録し、余白の発光や他素材の画素を取り込まない。ファー・白い袖・金具・素材のアルファは保護する。

形状と光は別に確認する。中心線に加えて首輪の金具と胸の飾りの画素位置を測り、内側と外側の輝度、前面の旧暗部の改善、マスク外画素の保持をそれぞれ照合する。着用状態・部位別表示・着脱表示の比較も必要。v60の比較と検証（ローカル履歴 `.local/history/assets/ciel/rig/proofs/body-outfit-v60/README.md`）を参照。

この試作は設計の初期実装であり、上着の物理接続・大きな腕上げの姿勢補正・袖口前後や金具の独立化は残っている。正式モデルとUnityの採用データは変更していない。
