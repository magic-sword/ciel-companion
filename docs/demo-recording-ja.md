# 外部紹介用デモの撮影台本

更新：2026-11-08。状態：未収録。READMEの冒頭に置く、音声つきの60〜90秒の実演動画を作る。最初の10秒で「キャラクターと声で話し、一緒に遊べる」が伝わることを目標にする。

## 完成形

- 本編：横1920×1080、30fps、60〜90秒。会話とMinecraftの実プレイを主役にする。
- 冒頭：実際の声かけと返事から始める。タイトルだけの長い導入を挟まない。
- 音声：利用者のマイクとシエルの声。BGMは初版では入れず、会話を聞き取りやすくする。
- 字幕：利用者とシエルを区別する。実際に話した内容を収録後に文字にする。
- 短いプレビュー：本編の実演から6〜10秒をGIFにしてREADME内で見せる。音声つきの本編へのリンクを添える。

## カットと話しかける内容

返答の文章は指定しない。以下の利用者のセリフで実際に動かし、その場の返事・結果を収録する。

| 目安 | 画面 | 利用者のセリフ・操作 | 映したいこと・採用条件 |
|---|---|---|---|
| 0〜12秒 | 日常版のシエルを大きく表示。縦画面を横動画の中央に置く | 「シエル、こんにちは。今日は一緒に遊ぼう」 | 声かけ→返事→口パクと表情が同じ画面でわかる。実際の応答時間を残す |
| 12〜22秒 | 日常版。頬が見える大きさ | 頬を一度つつく。必要なら「ほっぺ、つついてもいい？」 | 押した場所と変形・表情・反応がわかる。カーソルを見えるようにする |
| 22〜37秒 | Minecraftを主画面、シエル映像を右下 | 「シエル、ついてきて」。利用者が数歩移動 | ゲーム内のシエルと、同じ声のキャラクターが実際についてくる |
| 37〜62秒 | Minecraft＋シエル＋目的カード | 「近くのオークの原木を3個集めて」 | 依頼・行動・取得結果がつながる。成功した場合だけ字幕で完了とする |
| 62〜75秒 | 同じゲーム画面。目的カードを読める位置に | 完了報告を待つ | 採集の結果と報告を見せる。長い移動だけを短縮する場合は「移動部分を短縮」と表示 |
| 75〜85秒 | 配信版の操作画面を短く見せ、シエル映像へ戻す | ナレーションまたは字幕「日常の会話にも、ゲーム配信にも」 | 操作画面と視聴者用の映像を分けられること。最後に名前とGitHubリポジトリへの案内 |

Minecraftの実演が成立しない場合は、会話・タッチだけの20〜30秒版を先に公開し、ゲーム編は接続・行動の実機確認後に追加する。YouTubeコメント・人物記憶・議事録・歌の感想は別の短編にすると、初見で主題を追いやすい。

## 収録前に揃えるもの

1. [セットアップ](development-setup-ja.md)に沿って会話を接続し、マイクとシエルの声が聞こえることを確認する。[ビルド手順](build-ja.md)で日常版・配信版を用意する。
2. Minecraft Java版の撮影用ワールドを用意する。明るい時間帯、安全な平地、近くにオークの木を置き、シエルが参加できる状態にする。録画前に同じ依頼を試し、体の接続と結果を確認する。[Minecraftの設計](minecraft-design-ja.md)と[MCP統合の未確認項目](game-environment-mcp-design-ja.md)を参照する。
3. ゲームを使う会話は1つにする。日常版のカットを撮り終えたら切断し、配信版へ移る。スマホ・日常版・配信版はそれぞれ別の会話で、同じゲームの体を同時に操作しない。
4. 配信版でシエル映像と目的カードを開く。[配信ウィンドウの使い方](app-composition-ja.md)に従い、映像上の状態表示と別カードが重複しないよう調整する。
5. 公開用の名前と撮影用ワールドだけを使う。通知を止め、設定画面、接続ID、チャット履歴、他人の声が映り込まない画面を選ぶ。

## OBSの画面と音声

| OBSシーン | 取り込むもの | 配置 |
|---|---|---|
| 会話・タッチ | CIEL Companionのウィンドウキャプチャ | 縦画面を中央。左右の余白に短い紹介字幕 |
| Minecraft | Minecraft、CIEL Broadcastのシエル映像、目的カード | ゲームを全面、シエルを右下、カードを左上。ゲームのHUDと字幕を隠さない |
| 配信の仕組み | CIEL Broadcastの操作画面 | 操作画面を全面で数秒。実演への切り替えはカット編集 |

シエル映像と目的カードはそれぞれ**ウィンドウキャプチャ**で、クライアント領域を取り込む。目的カードにゲームキャプチャを使わない。OBSの操作画面やデスクトップ全体は収録対象にしない。

マイクとアプリ音声をそれぞれ一度だけ取り込む。仮想オーディオ経由とデスクトップ音声を重ねて二重に録らない。ヘッドホンを使い、利用者とシエルが話す10秒の試し録りを再生して、無音・音割れ・エコー・口パクとのずれを確認する。

OBSの録画はMKVで保存し、確認後に「録画の再多重化」でMP4にする。編集用の元動画はローカルの `.local/showcase/` に保存する。録画開始は実演の5秒前、停止は返事・行動完了の5秒後にする。カットごとに録り直せるようファイルを分ける。

## 収録の順番と合格条件

1. 10秒の音声試験を録り、実際に再生する。
2. 日常版の会話とタッチを別々に収録する。
3. 日常版を切断し、配信版とMinecraftを接続する。「ついてきて」を収録する。
4. 原木の採集を、依頼から結果確認まで通して収録する。待ち時間を含む原本を残す。
5. 配信版の操作画面を数秒収録する。
6. 本編を組み、字幕・名前・音声・操作結果を確認する。待ち時間を短縮した箇所は明記する。未実装の応答や進捗を合成しない。

公開前の確認：最初の10秒で音声会話がわかる／シエルとゲームの動きが見える／字幕がスマートフォンでも読める／利用者とシエルの声が両方聞こえる／接続情報や第三者の個人情報が含まれない。

## READMEへの掲載

現在の画面画像は `docs/assets/showcase/`、既存の動作GIFは `assets/ciel/current/proofs/` を参照している。いずれもプレイ動画と混同しない説明を添えている。

収録後は、公開先が決まった音声つき動画へのリンクをREADME冒頭の紹介文直後に置く。GitHub添付動画のURLかYouTubeの公開URLを使い、リンク付きのサムネイルも用意する。GitHub上で再生・遷移できることを実際に確認する。架空のURLや未収録動画へのリンクは置かない。

短いGIFを追加する場合は `docs/assets/showcase/demo.gif` に保存して表示する。元動画はGitに入れず、公開用に編集した素材と撮影情報（収録日、アプリのコミット、実行環境、短縮編集の有無）を残す。収録後にREADMEの「これから収録」の記述を、内容と収録日に置き換える。
