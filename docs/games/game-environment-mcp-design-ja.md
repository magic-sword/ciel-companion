# ゲーム環境のMCP接続

> 責務：環境を追加するためのMCP接続・profile・観測・所有権・通知。

この資料はゲームを追加するときの接続・所有権・resource/prompt/通知の契約を説明する。作業APIのフィールドは[作業契約](game-work-contract-ja.md)、Minecraft固有の実行は[Minecraft](minecraft/minecraft-design-ja.md)、共通の能力選択は[能力カタログ](../conversation/capability-runtime-ja.md)が正本。

## 現在の接続

`game_env.GameEnv`が`CIEL_GAMES`で指定した環境へStreamable HTTPのMCPで接続する。Minecraftの会話用入口はループバック8771の`/mcp`。接続しただけでは体を動かさず、アプリで有効にした会話だけがlinkツールで所有権を取得する。体を動かせる会話は一つ。

| MCPの面 | 内容 |
|---|---|
| `game://profile` | profile 2。ゲームID・表示名・リンク／停止ツール、振り分け用情報、work 1の能力とツール名 |
| `game://state` | 現在の観測、bodyとworkの状態。通知欠落時にも再取得できる |
| prompt `play` | ゲーム側が所有する遊び方・制約。シエル側へレシピを複製しない |
| `tools/call` | 能力の依頼・状態取得・判断回答・取消、公開された観察等 |
| `notifications/resources/updated` | 状態の再取得を促す |
| `notifications/message` | logger=`ciel.event`の出来事。独自通知名でSDKを迂回しない |

未対応のprofile・work版は拒否する。旧profile 1やアプリ側plan/step/repairへの互換経路を追加しない。ゲーム固有の能力・引数はそのまま公開し、すべてのゲームをMinecraftの製作スキーマへ押し込めない。

## 作業・体・出来事を混同しない

profile 2の任意項目`reference_context=true`は、`game://state.references`で利用者の指示対象を供給することを示す。初版は`selection_id`・`points`・`expires_at`・`source`、未選択時はnull。pointsの解釈とIDの解決はゲーム側が担当する。受付は取得成功を確認し、同じ発言の能力選択と対象指定の引数生成・訂正へ同じ参照を渡す。ツールの`_meta.ciel/reference_argument`は参照IDを受ける引数名で、選択時にも公開し、受付がモデル出力と取得済みIDの一致を検証する。この印がない能力の引数生成には参照を渡さない。実行時の期限・対象状態・接続先の検査もゲーム側で行う。参照の取得だけでは操作を開始しない。

workは依頼と結果、bodyは低水準の実行・停止と所有権を表す。完了や停止の正式状態はゲーム側が確定する。状態不明を成功・停止へ読み替えない。共通部は受付・期限・ID・判断を扱い、ゲームの内部段を進めない。

対象の数値をモデルに生成させない能力は、任意メタデータ`ciel/target_binding`を公開する。`kind=reference, argument=selection_id`は取得済み参照ID、`kind=axes, fields={x1:[x,0],x2:[x,1],…}`は明示された各軸の下限・上限への対応。`point=true`は範囲を移動先の一点へ縮めることを禁じる。Minecraft固有の技名・依頼の動詞をホストで判定せず、ゲームが引数への対応を宣言する。

`target_candidates.py`は発言ごとの短い候補IDと非公開の実引数を保持する。現在は、ラベル付き整数座標が明示されていればそれを候補にし、指差しへ代替しない。座標がなければ取得済みの指差し・目線を候補にする。候補と結べない能力を選択一覧から外す。引数生成には数値・UUIDの項目を除いた`target_id`のschemaを渡し、実行直前にシステムが復元して元のMCP schemaでも検証する。モデルから追加の座標や未知の候補IDを受け付けない。正規MCPツールの引数は変更せず、受付内だけの変換とする。

現行の厳密な座標文法は`X=5〜6、Y=64、Z=0〜1`等の軸ラベル付き整数。全角・負数・逆順範囲・単一の高さを扱う。同じ軸の重複、言い直し、欠落、小数等は推測せず確認へ戻す。保護する高さを別途`Y=63`と添えた文も重複として確認が必要。任意の自然言語座標や複数候補間の言い直し解決は未実装。

リアクション用の出来事は`input_v=1`、ID・接続世代・順序・時刻を伴う。旧通知を発話へ使わず、[サービス入力とリアクション](../conversation/service-events-and-reactions-ja.md)へ接続する。正式状態の反映はリアクションキューへ入れず、発話TTLとは独立に処理する。

接続のping・切断・所有者の解放をライフサイクルとして扱う。Minecraft側はアイドル期限でも解放し、ホスト側は会話終了時に監視・待機処理を閉じる。ゲーム側の停止確認が終わるまで次の操作を重ねない。

## 新しい環境を追加する

環境側にprofile、観測状態、能力スキーマ、操作と停止、イベントを実装する。ホストの設定に接続先を加え、権限、版不一致、重複・逆順通知、切断、取消のテストを追加する。ゲーム固有の日本語の名前・レシピ・経路探索・修復理由は環境側で保持する。

アプリの表情や表示操作は`app`の会話専用サービスで扱う。UIの入力捕捉・音声受信までMCPの道具選択待ちにしない。新しいネットワークサービスへ分離する場合は認証と会話の分離を別途実装する。
