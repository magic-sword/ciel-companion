# ゲームの知識の窓口（設計）

状態：試作中（2026-11-07）。facts と search の窓口を作り、開発用の会話サーバーにつないだ（6 章の 1・2）。前提は [マインクラフトで遊ぶ設計](minecraft-design-ja.md)（体）と [会話の組み立て（pipeline）の仕組み](conversation-pipeline-ja.md)（心）。

## 1. 何をするか

シエルが遊ぶゲームの知識（マイクラなら「土の下には石がある」「鉄は石のツルハシ以上で掘る」など）を、要るときに調べられるようにする。知識はゲームの側に置き、会話サーバーは「つながっているゲームの知識の窓口」を使うだけにする。ゲームが増えても、そのゲームの窓口を足すだけで済むようにする。

### きっかけ（2026-11-07）

「石のツルハシを作って」で、シエルは木のツルハシまでは自分で作れたが、丸石が見える所に無く、止まった。ふつうのプレイヤーなら「土の下には石がある」と知っていて掘り下げるが、シエルにはその知識も、調べる手段も無かった。

### 決めたこと（ユーザーと）

- 知識をプロンプトに書かない。世界の作られ方まで書くと量が広すぎて、プロンプトを汚す。分からなければ調べる形にし、プロンプトには「調べてから動く」の 1 行だけを書く。
- 毎回 Web を検索しない。遅く、料金がかかり、今の版（1.21.11）と違う版の情報で思い違いをしやすい。今の版に合った知識を、前もって手元に置いて調べる。
- 知識はシエルの会話サーバーではなく、ゲームの側に置く。シエルがアクセスできる窓口（MCP）にする。

## 2. 知識の元（調べたこと）

| 元 | 中身 | 使うか |
|---|---|---|
| **minecraft-data**（mineflayer の `bot.registry`。体に入っている） | 1.21.11 の正確なデータ：掘るのに要る道具・硬さ・落ちる物（`blockLoot`）・作り方（`recipes`）・食べ物・生き物（敵か・大きさ・落とす物 `entityLoot`）・バイオーム・エンチャント・効果 | **使う**（facts）。体と同じ版で、料金も通信も無い |
| **Minecraft Wiki**（minecraft.wiki、英語） | 世界の作られ方（鉱石の高さ・構造物・バイオームの地形）、仕組み、攻略。CC BY-NC-SA 3.0 | **使う**（search）。1.21.11 が出たころの版を記事ごとに取り出して置く |
| Minecraft Wiki の Kiwix（`minecraft.wiki_en_all_2026-08.zim`、1.8 GB） | Wiki 丸ごと | 使わない。2026-08 時点で、1.21.11 より新しい版の内容が混ざる |
| MineDojo の知識ベース（NVIDIA ほか、2022） | Wiki 約 7,000 ページ（本文・画像・表、32.7 GB。CC BY-NC-SA 3.0）、YouTube 73 万本の字幕、Reddit 34 万投稿 | 使わない。2022 年（1.18〜1.19 のころ）で、1.20 の遺跡・1.21 のトライアルチャンバー・1.21.9 の銅の道具が無い。YouTube・Reddit は古い版や誤りが混ざる。**表も残す**という作り方は取り入れる |

- 1.21.11 は 2025-12-09 に出た。Wiki は記事ごとに版の履歴を持つので、`2025-12-10` の時点の版を取り出す（それより前で最後の版）。
- Wiki の文は CC BY-NC-SA 3.0。手元に写して自分たちだけで使うのは「営利目的でない」使い方。取り出した物は Git にもデプロイにも入れず、自宅サーバーの `data/` に置く。出典（記事の URL と版の番号）を見出しごとに残す。配信で収益が出る場合、Wiki の文をそのまま読み上げると条件に触れるおそれがあるので、シエルは調べた内容を自分の言葉で短く話す（プロンプトにそう書く）。

## 3. 形

```
マイクラの側（自宅サーバー、server/minecraft の一式。profile minecraft）
  ├ minecraft            マイクラのサーバー
  ├ minecraft-body       シエルの体（ws 127.0.0.1:8768。動かす・様子・出来事。今のまま）
  └ minecraft-knowledge  マイクラの知識の窓口（新しく作る。MCP、127.0.0.1:8770）
        道具：search(question) … 手元の Wiki から合う見出しを返す
             facts(kind, name) … minecraft-data から正確な値を返す
        データ：./minecraft/knowledge/data/（Wiki を取り出した物と索引。Git・デプロイの外）

会話サーバー（ゲームのことは知らない）
  └ 設定のゲームの一覧（どのゲームの窓口がどこにあるか）
       「マイクラで一緒に遊ぶ」がオンで、体とつながっている間だけ、その窓口の道具を心に渡す
```

### 3.1 ゲームの知識の窓口の決まり（どのゲームも同じ）

- **MCP**（Model Context Protocol）の窓口にする。会話サーバーの LiveKit Agents（1.8.3）は MCP の窓口につなぐ仕組み（`livekit.agents.llm.mcp`）を持つ（`livekit-agents[mcp]` を入れる）。窓口が道具の名前・説明・引数の形を出すので、会話サーバーはそれを道具として受け取る。
- **つなぎ方**：MCP の HTTP（streamable HTTP）。窓口は自宅サーバーの中（127.0.0.1）だけで開く（体と同じく、host のネットワークで動くので、全部のアドレスで開くと外から見える）。
- **どのゲームも出す道具**（名前はゲームの名前を頭に付けて、会話サーバーの中で重ならないようにする。例 `minecraft_search`）：

| 道具 | 引数 | 返す物 |
|---|---|---|
| `{game}_search` | `question`（英語の短い言葉。例 `stone generation height`） | 合う見出し 3 つまで：`{title, section, text, source}`。text は 1 つ 800 字まで |
| `{game}_facts` | `kind`（そのゲームの種類の一覧から）、`name`（英語の ID） | そのゲームのデータの決まった形（JSON）。無ければ `{found: false, near: [似た名前]}` |

- 説明文（道具の description）は窓口が持つ。会話サーバーのプロンプトには、ゲームをまたいで同じ 1 行だけを書く（4 章）。
- **読むだけ**。窓口からゲームの中を動かしたり、ファイルを書いたりしない。料金もかからない。だから配信のコメントからも使ってよい（体を動かす道具とは分ける）。
- ゲームの版：窓口は `version` を返す道具の説明に書く（例「Minecraft Java 1.21.11 の知識」）。

### 3.2 マイクラの窓口（minecraft-knowledge）

**facts（minecraft-data）**

| kind | 返す物 |
|---|---|
| `block` | 硬さ・掘るのに要る道具（いちばん弱いもの）・落ちる物（シルクタッチの有無）・燃えるか |
| `item` | 積める数・作り方（材料と数。作業台が要るか）・食べ物なら満腹度 |
| `recipe` | `item` と同じ作り方を、何通りあるかも含めて |
| `mob` | 敵か・大きさ・倒すと落とす物 |
| `biome` | 気温・雨が降るか・分類 |
| `effect`・`enchantment` | 説明・最大レベル |

- 体の `planCraft`・`blocksFor`（server/minecraft/src）と同じ部品を使い、答えが体の動きと食い違わないようにする。
- 名前は英語の ID。違ったら `near` に似た ID を返す（`cobble` → `cobblestone`）。

**search（Wiki）**

1. **取り出す**（1 回だけ。手で動かすスクリプト `server/minecraft/knowledge/fetch.js`）
   - 記事の一覧：カテゴリ（Blocks・Items・Mobs・Biomes・Generated structures・Gameplay・Tutorials など）から、Java 版の記事だけを選ぶ。数は取り出す前に数えて決める（数千の見込み）。版ごとの更新記事（`Java Edition 1.x`）・開発版・Bedrock だけの記事は入れない。
   - 版：MediaWiki の API で、各記事の `2025-12-10T00:00:00Z` より前の最後の版（`rvstart`・`rvdir=older`）の番号を引き、その版を描き出した HTML（`action=parse&oldid=`）を取る。
   - 負担をかけない：1 秒に 1 回まで、User-Agent に用途を書く（連絡先にユーザーのメールは入れない）、途中で止まったら続きから。
2. **整える**
   - HTML から本文を文字にする。**表も文字に直して残す**（行ごとに「見出し：値」。鉱石の高さごとの出やすさ、宝箱の中身、作り方の表など）。インフォボックス（右の枠）も同じ。
   - 版の歴史（History）・ギャラリー・脚注・ナビゲーションの枠は落とす。
   - 見出し（`==`）ごとに区切る。長ければ 800 字ほどで分ける。各かたまりに `title・section・source（記事の URL と oldid）` を付ける。
3. **索引**：SQLite の全文検索（FTS5、BM25）。題・見出しを重くする。英語のみ。意味で探す（埋め込み）は、全文検索で外すことが多ければ足す。
4. **置き場**：`server/minecraft/knowledge/data/wiki.sqlite`（Git・デプロイの外）。取り出した日・件数・取り出した版の日付を `meta` に残す。

**窓口の中身**：Node（体と同じく mineflayer の部品が使える）。MCP の公式 SDK（`@modelcontextprotocol/sdk`）で、HTTP の窓口を 127.0.0.1:8770 に開く。SQLite は `better-sqlite3`。体とは別のコンテナ（体を入れ直しても知識は止まらない。知識を入れ直しても体はマイクラから抜けない）。

### 3.3 会話サーバーのつなぎ方

- **設定**：ゲームの一覧を環境変数で持つ。`CIEL_GAME_KNOWLEDGE=minecraft=http://127.0.0.1:8770/mcp`（ゲームが増えたら `,` で足す）。空なら知識の道具は無し。
- **いつ渡すか**：今の体の道具と同じ仕分け（`mind.py` の `tools_for`）に乗せ、そのゲームの「一緒に遊ぶ」がオンで体とつながっている間だけ、心に渡す。小脳（talker）には渡さない（道具を使うのは心）。
- **確かめが要ること**：シエルの心は LiveKit の道具を自分で仕分けて OpenAI へ渡している。LiveKit の MCP の道具（`MCPServerHTTP` が出す道具）を、この仕分けに混ぜて渡せるかを最初に試す。だめなら、会話サーバーの側に小さな MCP の受け手を書き、窓口の道具をふつうの道具（`function_tool`）に包む。
- **配信のコメントから**：使ってよい（`FROM_COMMENTS` を True）。
- **つながらないとき**：窓口が止まっていたら、道具は `{status: 'unavailable'}` を返し、会話は続ける。

## 4. 心の使い方（プロンプト）

`config/prompts/minecraft.md`（ゲームごとのプロンプト）に、知識そのものは書かない。ゲームをまたいで同じ形の 1〜2 行だけを書く：

- 「ゲームの世界のこと（どこに何があるか・どうすれば手に入るか・仕組み）で分からないことは、動く前に `{game}_search` で調べる。数・作り方・要る道具は `{game}_facts` で確かめる。調べた内容は自分の言葉で短く話し、文をそのまま読み上げない」

## 5. 料金・重さ

- 窓口は料金がかからない（手元で調べるだけ）。心が道具を 1 回呼ぶ分の入力（返す文 2,400 字まで）が増える。
- Wiki の取り出しは 1 回だけ（数千記事を 1 秒 1 件で 1〜2 時間ほど）。置き場は数十〜数百 MB の見込み（画像は取らない）。
- コンテナが 1 つ増える（Node と SQLite。メモリーは 100 MB ほどの見込み）。

## 6. 進め方

1. **試作**（作った。2026-11-07）：minecraft-knowledge の窓口を facts だけで作り、会話サーバーにつないだ。
   - 窓口：`server/minecraft/src/knowledge/`（`main.js`・`facts.js`）。体と同じイメージの別のコンテナ `minecraft-knowledge`。作る手順の決め方は体と同じ `src/craft-plan.js`。
   - 会話サーバー：`game_knowledge.py`。LiveKit の `Agent(mcp_servers=...)` に窓口を渡すと、LiveKit が道具を 1 つずつに広げて心の `llm_node` へ渡すので、今の仕分け（`mind.py` の `tools_for`）に名前（`minecraft_` で始まる）で乗った。3.3 の「確かめが要ること」は、包み直さずに済んだ。窓口の用意に失敗しても、LiveKit はほかの道具で続ける。
   - 部品：`livekit-agents[mcp]` と `mcp==1.30.0`（会話サーバー）、`@modelcontextprotocol/sdk@1.32.2` と `zod@4.6.7`（窓口）。
   - 確かめた：手元で LiveKit の MCP の部品から窓口の道具を受け取り、`stone_pickaxe` の作り方を引けた。自宅サーバーで窓口が 127.0.0.1:8770 だけで開き、開発用の会話サーバーに `mcp` が入った。
   - まだ：声で「丸石は何で取れる？」と聞いて、心が facts を呼ぶかを確かめる。
2. **Wiki を取り出す**（作った。2026-11-07）：`src/knowledge/wiki-fetch.js`（取り出す）・`wiki-text.js`（HTML を見出しごとのかたまりにする。表は「見出し：値」の行に）・`wiki-index.js`（SQLite の FTS5。node:sqlite）。
   - 記事の一覧：17 のカテゴリ（Blocks・Items・Mobs・Biomes・Generated structures・Gameplay・Tutorials など）から 2 段下まで。2,548 記事から、スキンパック・LEGO・映画・予告編・データの形式などを外して約 2,400 記事。
   - 置き場：自宅サーバーの `server/minecraft/knowledge/data/wiki.sqlite`（コンテナの `/app/knowledge-data`。Git・デプロイ・イメージの外）。取り出しの記録は同じ場所の `fetch.log`。
   - 手元の Node（22.14）の SQLite には FTS5 が無いので、索引の試験はコンテナ（Node 22.23）の中で回す。
   - 気づいたこと：2025-12 の版でも、次の版で足される物への言及が少し混ざる（鉄の鉱石の表に「Sulfur cube archetype」）。版の日付で切っても、Wiki が先に書いた予告は残る。
3. **search をつなぐ**：プロンプトの 1 行を足し、「石のツルハシを作って」で、心が「土の下に石がある」を調べてから動くかを確かめる（体の「掘り下げる」技は、[マインクラフトで遊ぶ設計](minecraft-design-ja.md) の別の直しとして足す）。
4. 次のゲームを足すときは、そのゲームの窓口を 3.1 の決まりで作り、`CIEL_GAME_KNOWLEDGE` に 1 つ足す。

## 7. あとで考えること

- 体を動かす道具も MCP の窓口に寄せるか。今の体の ws は、体からの出来事（倒れた・敵が来た）を送ってくる流れなので、呼ばれて答える MCP だけでは足りない。動かす道具だけを MCP に寄せ、出来事は ws のまま、という分け方もある。
- 日本語の Wiki（ja）も入れるか。英語の記事のほうが詳しく、心は英語で調べられるので、まずは英語だけ。
- 足りない技をゲームの側で作り足す（Claude Code に体の直しを頼む「改造の依頼」）。この窓口ができたら、同じ「ゲームの側に置く」考えで設計する。
