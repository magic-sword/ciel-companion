# 作業契約への移行と実機検証

2026-11-09。[再設計](minecraft-execution-redesign-ja.md)に沿って、ゲーム側の計画・実行とシエル側の作業管理を分離した。共有GPUのローカルモデルを使った7課題一巡で、期待行動は **7/7合格**。準備・片付け込み **5分20.982秒**、runnerは **4分45.090秒**。専用環境だけに反映し、本番サービスは更新していない。

## 実装した構成

- Minecraft側の `ciel/tasks.js` が、既存レシピ計画と技を使って実行・確認・修復する。中止・期限・重複排除もゲーム側で保証する。
- Pythonの `goals.py` はゲーム非依存の作業クライアントへ置き換えた。`GoalsAdapter` と会話側の子目標ツリーを撤去した。
- `game_intake.py` は公開された能力から構造化した依頼を作る。必須制約が欠けた受付拒否は同じ期限内に1回だけ修正し、自由文や疑似的な道具タグは実行しない。
- ゲーム中は道具を扱える判断経路を使い、小脳から心への約束再実行と意味ルーターの起動を外した。作業結果はゲームの実状態から作った短い通知を使う。
- MCPはprofile 2 / work 1。旧 `minecraft_goal_plan/step/repair` と直接の採集・製作ツールを撤去した。詳細は [作業契約](game-work-contract-ja.md)。
- Unityの作業表示にはtask_idと、判断待ちだけの再開ボタンを追加した。停止未確認を成功や停止済みに見せない。

ADK本体や新しい常駐モデル・サービスは追加していない。共通部は既存のMCP接続を使い、ゲーム内の段進行を持たない。ADK実装との性能比較は未実施。

同じ7課題・配置11の [改修前一巡](minecraft-benchmark-gpu-shared-2026-11-09-ja.md)は3/7合格、全体6分2.918秒だった。今回の課題は調整にも使用している。単一配置・各1回であり、未使用の課題への汎化や統計的な成功率、GPUだけの効果を示す値ではない。プロンプト接頭辞とキャッシュの条件も変わっている。

最終採点は従来どおりRCONの実状態を使う。新しい実行経路の `work_action` を操作発行として追跡し、状態監視の `status_polls` と技の `work_actions` を分けて記録した。MCPの要求数を旧APIの要求数とそのまま速度・効率の指標として比較しない。作業台等の進捗oracleの見落としは今回の変更範囲に含めず、評価器変更時は旧アプリも同じ評価器で測り直す。

## 完了通知の追加修正

7課題一巡では石の実物達成に合格したが、5秒以内の完了返答は未確認だった。ログでは作業途中に開始した自発的な会話生成が残り、Mouthの空き待ちが結果通知を待たせていた。

その後、作業中の任意の話しかけを `[silent]` で抑止し、結果通知があれば優先するよう変更した。利用者からの会話は受け付ける。構造修正を再依頼した場合の推論時間も、要求ごとに計測するよう修正した。

修正後は石の課題だけを1回検証した。`smoke-conversation-1794233611001064801` は評価63.563秒、実物到達59.477秒、達成後5秒以内の完了返答を確認した。7課題一巡とこの単発はソースが異なるので、最終ソース全体を再び7課題測定済みとは扱わない。
