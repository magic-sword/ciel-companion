# 自発会話の継続ループ評価

> 責務：単一のsay/actループの実験条件、課題、品質採点、対応比較と採用条件。

実験ブランチは `experiment/conversation-continuation`。基点は `c7cf369a8fbae16fea1c248e30ae1da6dd937ad4`。設計は[会話pipeline](../conversation/conversation-pipeline-ja.md#単一ループの実験)、実測は[能力・会話の結果](capability-results-ja.md#単一ループの自発会話実験)を参照する。本番の自発判断と、この模擬実行器の対照条件を同じものとして扱わない。

## 研究から借りるもの

[Proactive Conversational Agents with Inner Thoughts](https://arxiv.org/html/2501.00383v1) の §6 / Table 3 は、自然さ、一貫性、参加の感じられ方、知的な貢献、発言タイミング、自発性、適応性の7観点を1〜7で評定する。比較する会話の提示順を変え、具体的に不自然だった箇所も集める。この観点と比較方法を参考にする。論文の実験は複数人のテキスト会話であり、音声の割り込み・ゲームの実行成功・小型サーバーの速度が改善する根拠として転用しない。

発話回数・質問数・continue回数は動作の記述量であり、良さの得点ではない。推論中の文章やmemoから、人間のような内面が生まれたと判定しない。観測できる会話と行動の改善を測る。

## 比較条件

| 条件 | 内容 | 目的 |
|---|---|---|
| control | 現行ToolDecisionを使い、終端の発話で待機。操作後の結果確認は続ける | 継続機構の有無を比較する対照。現行Initiativeの再現ではない |
| loop | nextをsay/actより先に出力し、今回の発話後に話す番を決める。別の思考生成・評価呼出しなし | 回答待ちと必要な続きを両立する効果 |
| memo | loopに任意の短い継続メモを追加 | メモの追加が本当に必要かの切り分け |
| baseline | 指定Git版の継続promptとsay/act/next順。実行・採点基盤は候補と共用 | 前回の実験版との対応比較。ホスト全体の再現ではない |
| chunked | loopに1回1項目・120文字の発話枠と、確認質問等の基盤による待機を追加 | 小さい生成上限での途中切れと、継続指定の矛盾を改善できるか |

初回はcontrol/loopの開発課題を各1回、温度0で動作確認する。次に同じ課題・モデル・出力上限で3反復以上、温度0.3、対応するseedで試す。温度0でseedを変えた反復を、多様な会話の標本とは呼ばない。対照→候補と候補→対照を課題・反復ごとに交替する。候補を確定するまでholdoutは実行せず、最終比較で双方を同条件で測る。memoの比較はloopとの差だけを採点する。

最終採用前には基点コミットの実ホストと候補の実ホストを比較する。共通の音声・Mouth・入力イベント経路を使い、8秒/30秒の待機を持つ現在の方式との差を測る。通常ホストへの候補接続は実装済みだが、この実ホスト比較は未実施。現在の実験結果を本番より自然になったという証拠にしない。

## 課題と実行範囲

追跡する課題定義は `server/benchmark/continuation_cases.json`。開発7課題は直接質問のない開花の観測、雑談、集中中の沈黙、質問と回答、続けてよい物語、段階ロードと検索、検索失敗。holdoutは保留話題の再開、解決済み話題の更新、検索を含む引用文の翻訳。難易度は単一の会話判断、複数ターン/実行結果、時間をまたぐ関心の更新の3段階。

検索は決定的な模擬結果で、外部検索や実ゲームを操作しない。ToolDecisionの段階ロード、スキーマ・権限の検査、重複防止、結果根拠を共用する。検索結果の本文の正しさ、検索サービスやMinecraftの性能は測らない。確定したイベントを順番に投入し、発話の配信を即時完了と扱う。実音声のタイミングや途中割り込みはこの試験の測定対象外。

今後の実ホスト課題は、発話途中の訂正、相手が話し始めた瞬間の推論取消、遅れて届く操作結果、複数人の会話、10分の雑談と集中作業の交替。声の時刻や実機遅延は[音声ベンチマーク](voice-benchmark-ja.md)、ゲームの成果は[ゲーム評価](../games/minecraft/minecraft-benchmark-ja.md)の専用環境で測る。

## 採点の契約

品質は会話エピソード単位で、候補名を隠して採点する。7観点は別々に保持し、重み付き総合点へまとめない。rubric版は `continuation-v1`。発言・イベントの番号と具体的な根拠、評価者IDを残す。

| 観点 | 1点 | 4点 | 7点 |
|---|---|---|---|
| 自然さ | 定型の説明や反復で会話が成立しない | 意味は通るが不自然な言い回しが残る | 文脈に合う自然なやり取り |
| 一貫性 | 話題や事実が矛盾する | 主題は保つが接続や内容に欠落 | 必要な話題を一貫して発展・終了 |
| 参加 | 相手の発言を無視する | 一部を受け取って応答 | 相手の関心・反応を十分に受け取る |
| 貢献 | 無内容・誤りで役に立たない | 一部有用だが不足 | 必要な情報・感想・提案で会話に貢献 |
| 発言タイミング | 待つ場面で独走・必要時に無反応 | ときどき不要発話や取りこぼし | 発言機会と沈黙を適切に選ぶ |
| 自発性 | 機会があっても参加しない | 有用なきっかけを一部作る | 機会に合った話題・質問・行動を起こす |
| 適応性 | 訂正や状況変化を無視 | 一部を取り入れるが古い状態が残る | 新しい状況に合わせて意図を更新・終了 |

2/3/5/6点は隣接アンカー間の根拠を記す。対象機会のない観点はN/A。例えば「静かにしていて」のみの課題の自発性はN/Aで、黙ったことを低得点にしない。未採点・生成失敗も0点や満点に変換せず欠測理由を残す。処理失敗は別の失敗率として必ず報告する。

初期は人による採点とする。自然な回答、少し冗長な回答、連続質問、操作を約束しただけの回答、適切な沈黙、途中打切りの例で尺度の感度を確認する。少なくとも一部を2名で採点し、差が2点以上の箇所は根拠と不一致を残す。実行モデル自身の採点は採用判定に使わない。LLM採点を導入する場合はモデル・プロンプトを固定し、人の採点との一致を先に調べる。

| 別途測る量 | 証拠・単位 | 改善方向と欠測 |
|---|---|---|
| 操作達成 | ロード、正しい引数の実呼出し、成功結果、結果に沿う報告を各0/1。分母は操作要求数 | 各段階の達成率が高い。callだけで完遂扱いにしない。報告の正しさはレビュー |
| 不要操作 | 無操作課題でのロード数/実呼出し数 | 少ない。未実行課題は分母に入れない |
| 回答待ち | 質問後〜ユーザー回答前の追加発話、勝手な回答、追加操作 | 不要なものが少ない。意味判断はレビュー |
| 保留・更新 | 有効な話題の再開、解決済み話題の再質問 | 機会別の成功率。保持メモの存在自体は加点しない |
| 取消 | 発話開始→停止、入力確定→返答開始、取消後の古い出力/二重操作 | 実ホストでmsと件数。現在は未測定 |
| 負荷 | 推論回数、入出力token、キャッシュtoken、要求完了時間 | 品質を維持した削減。キャッシュ未取得はnull。HTTP完了時間をTTFTと呼ばない |

課題ID・反復・観点を対応づけ、候補−対照、改善/同点/悪化数、欠測数、難易度別の内訳を示す。課題を等重みにし、長い話ほど有利なターン平均にしない。反復差とケース単位のばらつきを残す。小規模試験の数点差を統計的な改善と断定しない。

## 実行

```powershell
# 既存のSSH設定を使い、共有8094へ一時トンネル。モード変更・配布・実サービス操作なし
.\.venv\Scripts\python.exe scripts/server/benchmark-continuation-home.py --output server/benchmark/data/continuation/pilot.json --budget 600
# メモの効果を別に比較（初回は開発課題のみ）
.\.venv\Scripts\python.exe scripts/server/benchmark-continuation-home.py --variants loop,memo --temperature 0.3 --repeats 3 --output server/benchmark/data/continuation/memo.json --budget 600
```

直接接続は `server/benchmark/continuation.py --base-url http://127.0.0.1:18094 --output ...`。既定は開発課題のみ。holdoutの実行は `--cases deferred,resolved,no_search` を明示する。1要求最大90秒、1イベント8推論、全体既定600秒。個別の生成失敗は保存して独立した次の試行へ進み、失敗があれば終了コード2。全体期限では停止する。失敗を再試行して上書きせず、期限超過を延長して完走扱いにしない。

前回候補との比較は `--variants baseline,loop --baseline-ref 17c8bf3 --temperature 0.3 --repeats 3` を指定する。baselineは継続指示と出力順だけを旧版に戻す比較であり、他の人格や実行器は共通。採点を含む基盤の変更は双方に適用する。

chunkedの120文字は試験用の生成枠であり、生成後の文字列切り捨てではない。長い内容は複数の決定で渡す。通常の生成上限300tokenは全条件で維持し、長文を短くしただけで品質改善とは扱わない。物語の出会い・助け・結末の充足と、推論回数や発話間の遅延を別々に確認する。clarify/blocked/acceptedでは基盤が待機し、モデルがcontinueを併記してももう一度生成しない。その矛盾はterminal_overrideとして数え、モデルの判断が正しくなったとは報告しない。baseline/loopの比較用条件は矛盾をエラーにする前回の挙動を維持する。

対応比較と匿名のレビュー素材は次で作る。`comparison.json` は課題・反復ごとの差分、`review.json` は条件名と制御出力を隠した会話、`review-key.json` は照合用で評価者には渡さない。品質点は未採点のまま出力する。失敗・欠測の組の差分はnullとし、速い失敗を改善扱いにしない。

```powershell
.\.venv\Scripts\python.exe server/benchmark/continuation_report.py server/benchmark/data/continuation/turn-first-dev-complete.json --output server/benchmark/data/continuation/turn-first-review
```

レポートはsuite/ソース/固定prompt/要求/応答の指紋、基点コミット、seed、モデル、API情報、呼出し・模擬結果・全文を保存する。生データはGit対象外。`quality_review`の未入力値は未採点。キャッシュ量はAPIから得られた場合のみ記録する。共有GPUモードはSSHラッパーが前後を保存する。途中の切替・同時負荷の完全な時系列は未観測のため性能の限界として明示する。

## 採用条件

制御テストと従来のToolDecision回帰が通ることに加え、質問後の独走、不要操作、虚偽の完了、取消後の実行を退行条件として個別に確認する。自然さ・自発性・適応性の対応比較で利益があり、通常応答の遅延を悪化させないことを実ホストで確かめてから採用する。初期データ取得前なので、任意の速度目標や品質点差を達成済みとしない。通常ホストへの接続と制御回帰を実施し、利用者の依頼で配布する。音声・ゲームの品質比較は未実施。通常ホストは操作引数のため出力上限600tokenであり、文字ベンチマークの300tokenと異なる。配布結果は[確認状況](verification-status-ja.md)を参照する。
