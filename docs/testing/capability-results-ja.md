## 現在の判断

段階的ロードを維持する。全サービスの説明を最初から公開する方式への移行を目的にしない。現在の少数の即時操作と探索・実行入口は、旧方式への互換経路を併設するためではなく、停止などの即時性と必要な説明だけを読むことを両立する構成である。通常経路へ採用した変更は、モデルに見えなくなった定義の取得済み状態も失効させる整合性の修正。構造化した実行ループは比較後、利用者の指定により通常音声にも接続する。概要の絞り込みと読み込み引数の追加は退行があり撤回した。トリガー精度・実用性の安定した改善はまだ確認できていない。

## 単一ループの自発会話実験

実験ブランチ `experiment/conversation-continuation`。前回候補 `17c8bf3` の継続指示とsay/act/next順をbaselineとし、同じToolDecision・模擬ツールで比較した。通常ホストへは未接続・未配布。評価の正本は[自発会話ベンチマーク](continuation-benchmark-ja.md)。前回の温度0・各1回の予備測定はGit `17c8bf3` と `server/benchmark/data/continuation/pilot-final.json` から参照する。

### 条件と設計の切り分け

共有Qwen3.5-35B-A3B-Q4_K_M、RTX A2000、GPUモード、32,768×2、ubatch512。温度0.3、seed1729〜1731の3反復。1要求300出力token、イベントごと8推論、各実験600秒。条件の順序を課題・反復ごとに交替し、同じケース・seedを対応づける。本文・要求・ソースの指紋と応答全文、APIの状態は各レポートに保存する。自然さの盲検人手評定は未実施。以下の内容確認はCodexによる条件を知った確認であり、人の自然さ評定に代えない。

1. `baseline → loop`：話す番をnextで先に決め、その選択に合わせてsayを書く。指示とフィールド順をまとめた介入で、それぞれ単独の効果は未分離。
2. `loop → chunked`：1回のsayを1項目・120文字以内の生成スキーマにする。長文は内容の区切りで継続する。生成後の切り捨てはしない。
3. 最終候補：chunkedに、clarify/blocked/acceptedなら実行基盤が待機する処理を加える。モデルのcontinueとの矛盾はterminal_overrideへ記録し、正しく判断できた扱いにしない。道具結果を受けた再判断は従来どおり必ず行う。

## say-actによる実行ループの比較

2026-11-16、ゲームと同じ`say`・`act`の分離を通常会話で試すため、評価用の制御器を追加した。`load → call → 結果 → 次の決定`を繰り返し、最初の`none`、確認が必要な`clarify`、実行不能の`blocked`を選べる。完了・受付には非エラーの操作結果IDが必要だが、その結果が依頼を満たしたかは別に採点する。仕様は[構造化判断ループ](../conversation/capability-runtime-ja.md#通常会話の構造化判断ループ)。以下は通常音声への接続前の比較。現在の接続仕様は能力公開の契約を参照。

比較基準は`bf4a990`の通常判断。実pipelineと実MCPを使い、履歴検索は実処理、議事録は送信しないfixture。従来の14ターンに、候補生成前に固定した言い換え・条件文・引用の6ターンを加えた20ターンを各3反復する。操作要求33、操作不要・不許可27。各系列の返答を次の履歴へ保持する。新規6ターンは最終候補まで未使用で、途中の短い試行には使っていない。

共有Qwen3.5-35B-A3B-Q4_K_M、RTX A2000、GPUモード、32,768×2枠、ubatch512、温度0、seed1729、最大600出力トークン、最大8推論。観測したモデル世代はa9d0a827094f4792b258c1a3ae7e0567。両方式とも実行エラーを結果として返す。従来の350トークン・最大5推論・最初の実行エラーで終了する比較とは条件が違うため、基準も60ターン測り直した。候補だけは推論の前後で120秒の予算も検査する。基準→候補の順で、共有負荷を固定した交互試験ではない。
