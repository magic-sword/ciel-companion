# CIEL Companion アプリケーション仕様書

- 作成日：2026-10-05（日本時間）
- バージョン：0.1
- 状態：初期仕様。採用方針と実装提案を整理したもので、実装・性能検証は未実施。
- リポジトリ：https://github.com/magic-sword/ciel-companion

## 1. 目的と採用方針

シエル（CIEL）を画面に表示し、自然な音声会話と表情・しぐさを通じて一緒に過ごせるスマートフォンアプリを作る。アプリ表示名は「CIEL Companion」、日本語の紹介名は「シエルとおしゃべり」とする。

ユーザーが採用した音声構成は **OpenAI Realtime／GPT-Live＋Seed-VC**。会話AIが生成する音声をSeed-VCでシエルの声へ変換して再生する。ChatGPTの画面や契約をアプリに組み込む方式ではなく、開発者向けAPIを利用する。

以下は初期実装の提案として採用する。
- クライアント：Unity＋Live2D Cubism SDK for Unity
- 音声・イベント通信：LiveKit
- 会話・音声変換：サーバー側。Seed-VCはGPUワーカーで処理
- 対象：Android・iOS。先行検証端末とOS最低バージョンは実装開始時に決定
- 会話言語：日本語
- Irodori-TTSは初期版の主経路には含めない

RealtimeとGPT-Liveは同一APIとして扱わない。初期の接続検証はRealtimeで行い、GPT-Liveは利用権限と音声変換との整合性を確認して別アダプターで比較する。最終選定は応答速度・割り込み・日本語会話品質の実測で決める。

## 2. 初期版の範囲

| 機能 | 初期版 |
|---|---|
| シエルの表示 | Live2Dモデルの上半身表示、まばたき、呼吸、軽い揺れ |
| 音声会話 | マイク入力、ストリーミング応答、Seed-VCで変換した音声の再生 |
| 口パク | 実際に再生する変換後音声の音量から制御 |
| 表情 | 通常・笑顔・困り・驚き。未用意の差分は通常へ戻す |
| 操作 | 会話開始／終了、マイクミュート、音量、接続状態、再接続 |
| 割り込み | ユーザー発話検知時に古い応答と変換・再生キューを停止 |
| 会話の文脈 | 接続中のセッション内で保持 |
| デバッグ | 既定音声との比較、遅延・キュー・エラーの計測 |
| 将来拡張 | 永続記憶、好感度、通知、外部ツール、複数衣装、オフライン推論 |

長期記憶、課金、一般公開向けアカウント管理は初期版の必須条件にしない。ただし、サーバーアクセスの認証と利用上限は初期版でも設ける。

## 3. 構成と処理の分担

| 部分 | 責務 |
|---|---|
| Unityアプリ | 描画、操作、マイク許可、録音、音声再生、口パク、状態表示 |
| LiveKit | スマホとサーバー間の音声トラックとデータメッセージ |
| セッションAPI | 認証、短期接続トークン発行、セッション開始／終了、利用上限 |
| 会話ワーカー | OpenAI接続、入力音声送信、出力音声受信、応答管理 |
| Seed-VCワーカー | 参照音声の事前準備、継続音声変換、キャンセル、変換後PCM出力 |
| 設定管理 | シエルの会話指示、モデルID、参照音声ID、変換設定、ログ設定 |

音声の流れは「マイク → LiveKit → 会話ワーカー → OpenAI → Seed-VC → LiveKit → Unityのスピーカー」とする。生のAI出力と変換後音声を同時にユーザーへ再生しない。

Seed-VCとLiveKitの接続は独自実装であり、公式の完成済み統合を前提にしない。LiveKit Agentsの出力処理または独自ワーカーで実装し、音声形式・割り込み・バックプレッシャーを検証する。

OpenAI、LiveKit、Seed-VCの入出力サンプルレートは固定値を推測せず、採用モデル・SDKの仕様で決める。モノラルPCMを内部共通形式とし、境界でリサンプリングする。量子化形式、フレーム長、チャンク長を設定として明示する。

## 4. 会話とキャラクター表示

### 4.1 会話体験

1. 起動するとシエルと会話開始ボタンを表示する。
2. 初回はマイク利用と外部サーバーへの音声送信を説明し、OSの許可を求める。
3. 接続・モデル準備中は状態を表示する。準備が完了してから録音を始める。
4. ユーザーが話すとシエルが聞く反応を示し、返答音声に合わせて口を動かす。
5. 発話途中でもユーザーが話し始めたら応答を止め、新しい発話を受け付ける。
6. 終了時は録音、音声再生、通信、GPUセッションを解放する。

マイクミュートは入力送信を止める。会話終了はセッション自体を閉じる。アプリがバックグラウンドへ移動した場合は初期版では録音を止め、復帰時に明示的に再接続する。

### 4.2 シエルの人格と素材

シエルとして話し、親しみやすく好奇心のある応答を目指す。通常の返答は短くし、ユーザーが詳しい説明を求めた場合に伸ばす。

既存のCIEL企画設定がキャラクターの正式な情報源となる。設定を確認するまでは詳細な口調・一人称・過去エピソードを確定しない。設定資料をアプリに直接すべて埋め込まず、承認した会話用プロフィールに整理する。

Live2D用にはパーツ分けとリギングを行ったモデルが必要。立ち絵PNGや三面図だけでは動作しない。目・口・呼吸・角度などのパラメーターはモデルごとの設定ファイルに対応付ける。表情は許可したIDのみ扱い、不明な指示は無視する。

### 4.3 表示状態

接続状態は disconnected／connecting／ready／reconnecting／error、表示反応は idle／listening／thinking／speaking を基本とする。全二重会話ではlisteningとspeakingが同時に成立し得るため、単一の排他的な会話状態で入力を止めない。

口パクは受信時刻ではなく、再生位置を基準に変換後音声の振幅を読む。再生停止時は口を閉じる。表情イベントが遅れたり欠けたりしても音声再生を待たせない。

## 5. ストリーミング音声と割り込み

### 5.1 音声変換

- 参照音声と必要なモデルを会話開始前に読み込み、GPUをウォームアップする。
- 応答全文や全音声の完成を待たず、連続した音声チャンクを順次変換する。
- チャンク境界のクリックや声質変化を抑えるため、コンテキスト・オーバーラップを維持する。
- セッション間で変換コンテキストを混ぜない。
- 変換キューに上限を設け、積み残しで遅延が増え続ける状態を検知する。
- Seed-VC停止時に無断で別の声へ切り替えない。音声を停止して再試行を案内する。既定音声への切り替えは検証用の明示操作とする。

### 5.2 割り込みと会話履歴の同期

すべての音声・イベントにsession_id、utterance_id、generation_idを付ける。キャンセル時はgeneration_idを更新し、古い世代の音声を各段階で破棄する。

割り込み時には、AIへのキャンセル、Seed-VCの入力・出力キューの破棄、LiveKit送信キューとUnity再生バッファの停止を行う。キャンセル不能な推論が後から完了しても、その結果を再生しない。

Realtimeではサーバーの生成完了と端末の再生完了が一致しない。変換前音声と変換後音声の時刻対応を保持し、端末が実際に再生した地点を基に、公式APIの履歴切り詰め処理へ反映する。変換後のミリ秒値をそのまま変換前の音声へ当てはめない。

GPT-Liveでは専用のセッション制御へ対応付ける。Realtimeのイベント名を流用しない。後段変換による再生遅延が全二重会話のタイミングに与える影響を検証対象にする。

端末のスピーカー音が再入力されないよう、SDK・OSのエコーキャンセル機能を確認する。標準のUnityマイク録音だけで十分なAECが動くとは想定せず、スピーカー・イヤホン・Bluetoothごとに評価する。

## 6. アプリ内イベント契約（提案）

以下はプロジェクト内部のイベント名で、外部APIの正式なイベント名ではない。

| イベント | 主な値 | 用途 |
|---|---|---|
| session.state | session_id、state、reason | 接続状態通知 |
| character.expression | generation_id、expression、intensity、ttl_ms | 一時的な表情 |
| speech.started | generation_id、utterance_id | 応答開始通知 |
| speech.cancelled | generation_id、utterance_id | 古い音声の破棄 |
| playback.progress | utterance_id、played_samples、sample_rate | 実再生位置の報告 |
| session.error | code、retryable、user_message | エラー表示 |

イベントにはスキーマバージョンと連番を付ける。音声トラックとは別にイベントを送り、イベントの遅延で音声をブロックしない。表情の寿命が切れたら通常へ戻す。診断用の内部詳細をユーザー向けエラーメッセージへ混ぜない。

## 7. 性能の測定と暫定目標

数値は製品保証や既存技術の性能値ではなく、本プロジェクトの検証用目標。日本語、実機、ウォームアップ済みGPU、安定した回線で測定する。

| 指標 | 暫定目標 |
|---|---|
| 発話終了から変換後音声の再生開始 | p50 1.5秒以内、p95 2.5秒以内 |
| 割り込み検知から端末の再生停止 | p95 200ms以内 |
| 変換の処理能力 | 継続処理で実時間比RTF 1未満 |
| 描画 | 基準端末で30fps以上 |
| 継続会話 | 10分間でクラッシュ・無制限のキュー増加がない |

計測点は、端末入力、発話終了検知、AI初回音声受信、変換初回出力、端末初回再生、キャンセル検知、端末停止。異なるマシンの時計を単純に引き算せず、端末側の全体計測と各サーバーの単調時計による処理時間を分けて記録する。

変換追加遅延は同じ入力と条件でSeed-VC有効／無効を比較する。GPU機種、モデル版、チャンク長、同時接続数、回線、端末、音声経路も記録する。目標未達の場合は変換設定やGPU構成を調整し、会話品質との妥協点を判断する。

## 8. セキュリティ・データ・費用

- OpenAI APIキー、LiveKit API secret等をアプリやGitへ含めない。サーバーの秘密管理で保管する。
- アプリには認証済みセッションに限定した短期LiveKitトークンを発行する。
- TLS通信、セッションの有効期限、同時接続制限、アイドル終了、利用時間上限を設ける。
- 初期版ではユーザー音声と会話全文を自前の永続ログへ保存しない。API事業者側の保持は別途公式条件を確認し、ユーザーへ説明する。
- 診断ログはID、時間、キュー長、エラーコードを中心とし、秘密・生音声・個人情報を出力しない。
- シエルの声には利用権限のある参照音声を使う。参照音声・モデル重量の公開可否を確認し、必要ならGit外へ保管する。
- 運用費はOpenAI音声利用、LiveKit通信、GPU稼働、その他サーバーに分け、会話1分あたりと月額で測る。価格は仕様書へ固定せず採用時の公式料金を参照する。

## 9. 開発順序と受け入れ条件

### フェーズ1：表示と音声基盤
Live2D表示、マイク入力、LiveKit接続、既定音声によるRealtime会話、実再生ベースの口パクと割り込みを実装する。

### フェーズ2：シエル音声
Seed-VCを組み込み、参照音声の読み込み、チャンク連続性、変換キュー、キャンセル、再生位置対応を検証する。既定音声と同じ会話で速度と声質を比較する。

### フェーズ3：会話演出とAPI比較
表情・人格設定を整え、GPT-Liveアダプターを比較検証する。全二重会話の利点と音声変換後の遅延を評価して採用APIを決める。

### フェーズ4：実機安定化
Android・iOS、スピーカー・イヤホン・Bluetooth、通信切断、バックグラウンド移行、権限拒否、GPU障害、利用上限を確認する。

初期版の完了条件：
- 日本語でシエル音声による10分以上の連続会話ができる。
- 連続した割り込みでも古い応答が後から再生されない。
- 音声の停止と口パクの停止が一致し、自己音声で会話が暴走しない。
- 通信切断・権限拒否・変換障害から終了または再試行できる。
- 暫定性能目標の達否と、声質の主観評価結果を記録する。
- APK／iOSビルドとリポジトリにサーバー秘密情報が含まれない。
