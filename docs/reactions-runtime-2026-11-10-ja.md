# 共通反応基盤の実装・検証記録

実施日：2026-11-10。[設計方針](design-policy-ja.md)と[サービス入力・リアクションの仕様](service-events-and-reactions-ja.md)に基づく初版。標準のpipeline・Irodori構成を対象とする。本番には反映していない。

## 実装

`reactions.py`へ、内部v1イベント、接続世代、順序、発行時刻、IDによる重複排除、期限、優先順位、有界キューを実装した。能力ロードとは独立に入力を受ける。分類用のLLM呼び出しは追加していない。

接触、ゲーム、作業結果、コメント、歌の途中反応に加えて、議事録・調査結果・画像入力も同じキューへ接続した。Mouthの旧通知キューとタッチの旧待機タイマーは撤去した。サービスの処理や正式な作業状態の確定は、反応キューの前に行う。

表情と発話を分け、強い接触の既存の即時表情を維持する。大きな被ダメージではLLMを待たず表情を送信する。通常のLLM表情や歌の表情が痛がる表情を上書きしないよう、ホストとUnityに優先度・有効期限を設けた。

発話の待機では、単に到着から一定時間待つだけでなく、連続した会話の切れ目を確認する。生成・音声出力でも期限と割り込みを確認し、期限切れのストリームを閉じる。低優先度の反応が生成中に重要な入力が来た場合は、その反応を中断する。通常の持ち主の会話は共通キューから強制中断しない。

発話ハンドルが終了しただけでは発話済みにしない。空でない助手発言と割り込みなしを確認し、確認できなければ`unconfirmed`とする。コメントへの返答数も完了後に更新する。会話へ添えた通知は対応するIDで管理し、その返答中に新しく届いた通知を消費しない。

ゲームの作業通知が被ダメージを置き換えるpipelineの先行returnを修正した。期限切れの作業通知を後から自発発話で再生する経路も閉じた。正式な作業状態・取消確認は発話の有効期限と独立に維持する。

歌唱中は通常の反応音声を保留・失効させ、歌の変化は表情・メーターへ渡す。重大事態の初期規則として、所有中のゲームの`died`だけが歌の捕捉・分析・歌用発話を停止する。マイクを戻し、重複した歌の停止アナウンスを追加しない。旧曲の解析や後処理が、再開した新しい曲の状態を上書きしないよう世代で保護した。

## 通信の更新

| 対象 | 現在の契約 |
|---|---|
| `user.touch` | v2。発行ID・世代・順序・UTC発生時刻を追加。Unity送信とagent受信を更新 |
| `character.expression` | v2。優先度・絶対期限を追加。期限切れ・旧版・大きな時計ずれはUnityで拒否 |
| ゲームMCPの`ciel.event` | `input_v=1`と発行ID・世代・順序・時刻を追加。無い通知は体感反応に使わない |
| ゲーム作業状態 | profile 2 / work 1を維持。反応通知の期限や破棄で状態を失わない |

ゲームは現在のMCP接続だけから通知を受け、初期化中・旧接続・終了後の通知を遮断する。体を受け持っていない接続からは体感の発話・出来事の記憶を作らない。

`reaction`・`reaction_rejected`にID、発生元、種別、段階、時刻、破棄理由を記録する。`model_request.reaction_id`でモデル要求と対応付ける。通常の計測へ本文、画像、記憶、APIキーを追加しない。

共通基盤の20テストでは、未ロードサービス、優先順位、重複・世代・順序・期限、表情の競合、歌唱中の抑制、キュー満杯、発話の中断、空出力、旧タッチの拒否、接触の文脈追加、通知の接続ライフサイクルなどを確認した。Mouthでは応答へ渡したIDだけを消費すること、SongListenerでは緊急停止と再開時の世代保護を追加確認した。

Nodeの追加テストは、実際のCielLink→Hubの通知で発行情報と受け持ち変更による世代更新を確認する。既存の模擬MCPサーバーとPython側のfixtureも新しい通知形式へ更新した。

Git管理外のレポート・ログは`server/benchmark/data/reactions-final-validated-20261110/`、`reactions-node-release-20261110.log`、`reactions-csharp-complete-20261110.log`などに保存した。Nodeのskipはこの端末のSQLiteにFTS5が無いことによるもので、全件合格と表記しない。

## 未実施と反映時の条件

Unity Editorでのシーン動作・プレイヤービルド、頬を引っ張ったときの実際の表情・声、Minecraftでの実被ダメージ、実YouTube、実歌唱、共有GPU下での遅延測定、本番反映は未実施。今回はDBスキーマを変更せず、DB結合試験も再実行していない。以前のDB9件やMinecraftのベンチマークを今回の実機結果とは扱わない。

表情の送信要求・端末の即時反応の対応付けは記録するが、表示適用や物理スピーカーの再生ACKは未実装。UTCの時計同期を前提とし、時計差の自動推定は行わない。実モデルが常に期待する言葉で反応することも、オフライン試験では保証しない。

旧タッチ・表情・ゲーム通知への無言のフォールバックはない。反映時は確認済みコミットのagent・minecraft-body・Unityアプリを一式でビルド・更新し、必要な再起動と接続確認を行う。ソースとC#コンパイルの更新だけで、起動中のサービスや配布済みアプリが更新されたとは扱わない。
