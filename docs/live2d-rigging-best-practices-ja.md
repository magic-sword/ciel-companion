# Live2Dの素材分離・目口調整：調査とシエルへの適用

- 調査日：2026-10-06（日本時間）
- 対象：シエルの視線・瞬き・口の開閉、髪との重なり、Cubismへの移行。
- 関連：[制作仕様書](ciel-live2d-production-spec-ja.md)、[現在のリメイク試作](assets/ciel/production/ciel-gaze-preview.html)。
- 資料の扱い：Live2D公式の現行マニュアルを主資料とし、旧4.2版は具体的な基礎手順の補足として明示する。掲載動画を全編視聴した調査ではなく、公開ページ本文を確認した調査。

## 1. 結論と「業界標準」の範囲

今回必要なのは、フレーム数やぼかし量の追加より先に、**髪・まぶた・白目・虹彩・影を別の意味を持つ部品として整理すること**である。完成した顔画像を広い肌色領域で塗り替える方式では、髪の前後関係を維持できない。現行工程では部品を分離し、前景の髪を最後に合成している。

公式の基本工程は、素材の加工・分離、PSDの取り込みとメッシュ作成、パラメータによる表情付けへ進む構成である。[公式：イラストの加工](https://docs.live2d.com/cubism-editor-tutorials/psd/)、[公式：イラストを動かす準備](https://docs.live2d.com/en/cubism-editor-tutorials/import/)

本書でいう標準的な作り方は、この公式ワークフローに基づく。全制作者共通のレイヤー数・メッシュ密度・瞬き時間などを定める統一規格を確認したわけではない。「公式で確認できる事項」「今回の実装で確認した事実」「シエルへの制作提案」を区別する。独自の数値を業界標準と呼ばない。

## 2. 旧試作で確認した不自然さの原因

調査時のユーザー提示画像では、視線移動時の目の上端の明部のずれと、閉眼途中で髪を覆う肌色領域が確認できる。現在のブラウザープレビューはGIMPで生成した画像の切替であり、Cubismのメッシュ・描画順・クリッピングを動かした結果ではない。したがって、この画像からCubism SDKの不具合を推定しない。

| 症状 | 実装で確認したこと | 判断・対処 |
|---|---|---|
| 閉眼時、肌が髪を覆う | 旧試作は目周辺の領域を頬から補間した肌で置換していた。髪の独立した前景レイヤーを最後に再合成していない | 重なり構造の欠落。肌マスクをぼかすだけでは直らない。前髪・横髪を分離し、まぶたより手前で合成する |
| 目の上端の明部がずれる | 旧試作は座標・RGB閾値で虹彩、ハイライト、固定上端を分類していた。`UpperOcclusion_Visible` は不透明な固定画素であり、透過した影の復元ではない | 分類境界に別部品の画素が混ざっている可能性が高い。虹彩の色、眼球ハイライト、まつげの反射、落ち影を目視で区別して切り分ける |
| 通常顔は一致するのに、動かすと破綻する | 通常状態でしか見えない画素配置と、補完部分・仮マスクの構造を別々に検証していなかった | 通常顔一致は必要な回帰検査だが、動作品質の合格条件には足りない |
| 425通りの検査が通っても髪が消える | 対象の目領域内なら、髪を肌へ置換しても領域外変更数は0になる。全面が不透明なら「穴なし」も通る | 髪など部品の意味と遮蔽を検査する必要がある。組み合わせ数を増やすだけでは検出できない |
| 拡大すると輪郭が粗い | 元の顔領域は280×195px。細い線を色閾値で分け、拡大している | 拡大は描画情報を増やさない。高解像度で素材を描き直す工程と、元解像度の動作試験を分ける |

この表は旧実装を調査した際の診断を残したものである。旧試作ファイルは作業ツリーから削除し、過去の実装はGit履歴で参照する。現行の素材生成・検証対象は [制作仕様書の第12節](ciel-live2d-production-spec-ja.md#12-現行の制作工程2026-10-06) を参照。ブラウザー試作の成功をCubism・Unityでの動作保証とは扱わない。

## 3. 素材分離と描画順

### 公式で確認できること

素材分けでは元の絵を残し、マスクで部品を切り出し、動かすと露出する領域を別レイヤーに描き足す。編集用とインポート用を分け、後者は部品ごとに整理する。[公式：素材分けについて](https://docs.live2d.com/cubism-editor-manual/divide-the-material/)

Cubismの描画順は値が大きいほど手前であり、同値の場合はパーツの並びも影響する。パラメータによって描画順を変えることもできる。[公式：描画順について](https://docs.live2d.com/cubism-editor-manual/draworder/)

### シエルの素材構成案

| 部品 | 独立させる理由 | 隠れ部分・注意 |
|---|---|---|
| 前髪・顔にかかる横髪 | まぶたの処理から保護する | 顔との境界、毛先の半透明画素を保つ。髪の背後の額は顔側に用意する |
| 顔の土台・まぶたの肌 | 目の開閉で見える肌を支える | 鼻や頬を巻き込む大きな上書きパッチにしない。白磁の色を維持 |
| 上まつげ・下まつげ／下まぶた | 線の太さと目尻の形を調整する | 目頭・目尻の位置と元の線の特徴を残す |
| 白目 | 見える眼球領域とクリッピングの基準 | 虹彩の裏まで描き足す |
| 虹彩・瞳孔 | 視線移動の中心になる | 上まぶたの裏を含む形状を用意。まぶたの影を焼き込んだまま動かさない |
| 眼球ハイライト | 虹彩との相対位置を管理する | まつげ上の反射とは区別する |
| 上まぶた由来の影 | 眼球の模様と別の動きをさせる | 不透明な元画素の帯を固定する方式から、独立した影素材へ移行する |
| 上唇・下唇、口内、必要に応じて舌・歯 | 開閉と口形を分けて調整する | 閉口時に口内が残らないようにする。歯は必要な表情に限る |

次の表は今回の前後関係の目安であり、全モデル共通の固定順序ではない。影とハイライトの相互順序は元の絵に合わせる。

| 手前から奥へ | 守る関係 |
|---|---|
| 前髪・前側の横髪 | 目を閉じても、まぶたの肌が髪より手前へ出ない |
| まつげ・まぶたの縁 | 白目や虹彩の切断面を自然に隠す |
| まぶたの肌・影 | 肌の広がりを目周辺に限定。影は眼球領域へ制限 |
| ハイライト・虹彩・瞳孔 | 白目／眼球用マスク内で表示する |
| 白目 | 見える目の開口を構成する |
| 顔の土台 | 全体の白磁の肌を支える |

「白目のマスクで虹彩を切る」関係と「髪がまぶたより手前にある」関係は別の制御である。前者だけを実装しても後者は直らない。

## 4. 視線・ハイライト・瞬きの調整

### クリッピング

公式は白目のアートメッシュを使って黒目側をクリッピングする手順を示している。輪郭に白い縁が出る場合は半透明境界の重なりが原因になり得る。必要に応じ、表示用の白目と専用のマスクを分ける対策も公式に記載されている。境界を一律にぼかすのではなく、まずマスクの形・表示用素材との役割を確認する。[公式：クリッピングマスク](https://docs.live2d.com/cubism-editor-manual/clipping-mask/)

### 親子関係と動きの担当

デフォーマは親の変形を子へ伝える。描画順とデフォーマの親子関係は別に設計する。[公式：親子関係の仕組み](https://docs.live2d.com/cubism-editor-manual/system-of-parent-child-relation/)

シエルでは、虹彩・瞳孔・眼球ハイライトを共通の視線用デフォーマ配下に置く案を第一候補とする。ハイライトを独立して揺らす演出は、相対位置が安定してから追加する。まつげの反射はまつげ側へ、まぶたが落とす影はまぶた側へ追従させる。これらは今回の設計提案であり、反射表現を一律に固定する公式規則ではない。

```text
頭部の変形
├─ 前髪・横髪の変形             ← 瞬きでは動かさない
└─ 目の配置（左右で別系統）
   ├─ 開閉の変形：まつげ・まぶた・白目／マスク
   ├─ 視線の変形：虹彩・瞳孔・眼球ハイライト
   └─ まぶたの影：開閉に追従、眼球領域へクリップ
```

### 目の開閉

旧4.2版の公式手順は、まつげの閉じ形を作り、白目を変形してまつげの裏に収め、クリッピングされた黒目が見えなくなるように調整する。開閉の途中もパラメータを動かして確認する。これは現在のクリッピング機構とも整合する基本的な考え方である。[公式・旧4.2：表情の動き付け](https://docs.live2d.com/4.2/cubism-editor-tutorials/expression/)

シエルへの適用手順：

1. 通常の開き目を基準に、元の上まつげの線・目尻を保つ閉眼形状を作る。
2. 白目／マスクの開口を上下まぶたに合わせる。閉じ切ったときに白目・虹彩・ハイライトが残らないことを確認する。
3. 虹彩そのものを縦につぶして閉眼を表現しない。
4. 半目で上まつげの線幅、下まぶたとの間隔、影の位置を調整する。必要な箇所に中間キーを追加する。
5. 左・中央・右の視線をそれぞれ保持して開閉し、最後に連続動作で確認する。

まつげや口の細かな変形には、公式も変形に適した手動メッシュ編集を推奨している。自動分割は出発点とし、線を横切る頂点配置や変形方向を確認する。[公式：メッシュの手動編集](https://docs.live2d.com/cubism-editor-manual/mesh-edit-manual/)

## 5. 口の形と標準パラメータ

口は開口量だけでなく口形も分ける。上下唇と口内を分離し、必要な余白を描く考え方は旧版公式の素材加工手順にも示されている。肌色を持つ唇素材が必要になる場合もあるが、それを顔や髪へ無制限にかぶせる意味ではない。[公式・旧4.2：イラストの加工](https://docs.live2d.com/4.2/cubism-editor-tutorials/psd/)

以下は公式標準リストに掲載されている基準値。実際の可動量と追加キーはモデルに合わせて決める。[公式：標準パラメータリスト](https://docs.live2d.com/cubism-editor-manual/standard-parameter-list/)

| ID | 基準範囲／初期値 | シエルへの適用 |
|---|---|---|
| `ParamEyeLOpen` / `ParamEyeROpen` | 0〜1／1 | 0が閉眼。現在のUIの閉眼率とは向きが逆 |
| `ParamEyeBallX` / `ParamEyeBallY` | −1〜1／0 | 現在の±4pxをそのまま標準の可動量とはみなさない |
| `ParamMouthOpenY` | 0〜1／0 | 閉口・小開口・大開口の形を確認 |
| `ParamMouthForm` | −1〜1／0 | 開口量と分けて、通常・笑顔などの口形を調整 |

シエルではまず閉口、小さな開口、通常の発話口を完成させる。現在の楕円と舌の描画は仮形状で、正式な口のデザインではない。口角の不連続、閉じた際の口内残り、開いた際の四角い肌パッチを不合格とする。

SDKで瞬きを使う場合は、Editor側で対象パラメータを設定する。Unity側には瞬き・リップシンク用の制御があり、複数処理が同じ値を書き換える場合の実行順やブレンドにも注意が必要である。[公式：瞬き設定](https://docs.live2d.com/en/cubism-editor-manual/eye-blink-settings/)、[公式：Unity EyeBlink](https://docs.live2d.com/en/cubism-sdk-manual/eyeblink-unity/)、[公式：リップシンク設定](https://docs.live2d.com/en/cubism-sdk-tutorials/lipsync/)

## 6. GIMPからCubismへ渡す際の確認

GIMPは編集原本の制作に継続使用する。ただし、Live2D公式がPSD制作の推奨・動作保証対象として挙げるのはPhotoshopとCLIP STUDIO PAINTであり、GIMPでの再読み込み成功をCubismでの正常取り込みと同一視しない。[公式：素材分けについて](https://docs.live2d.com/cubism-editor-manual/divide-the-material/)

インポート用PSDはRGB・8bit/チャンネルとし、sRGB、重複しないレイヤー名、マスク・効果を反映した部品単位の画像を確認する。GIMPの編集用XCFはマスクや補完レイヤーを残し、インポート用PSDと分ける。[公式：PSD作成上の注意点](https://docs.live2d.com/cubism-editor-manual/precautions-for-psd-data/)

シエルでの確認順は、GIMP内の見た目→書き出したPSD→Cubismに取り込んだ見た目→動かした状態→Unityでの表示。`.xcf`やPSDのレイヤー数が多いことだけで、モデルの可動用パーツが完成したとは判断しない。

UnityにはEditorから出力した組み込み用モデルとテクスチャを渡す。HTMLの画像切替試作が成功しても、この経路の検証を代替しない。[公式：モデルのインポート](https://docs.live2d.com/en/cubism-sdk-tutorials/getting-started/)

## 7. 今回追加する合格条件

以下はプロジェクト用の受け入れ条件。公式が定める数値規格ではない。

| 検査 | 合格条件 |
|---|---|
| 通常顔 | 現在の原寸試作は従来どおり画素一致。高解像度原画・Cubismでは描き直しや描画方式の差を分けて評価し、顔立ちの承認を取る |
| 髪の遮蔽 | 瞬きだけで髪の形・透明度・描画順が変わらない。肌が髪の不透明部分を覆わない |
| 髪の半透明境界 | 下のまぶたの色が変わること自体は自然。境界の全画素固定ではなく、元の髪のアルファで正しく合成されることを確認 |
| 虹彩・明部 | 視線の端でも虹彩、眼球ハイライト、まつげの反射が意図せず分裂・残留しない |
| 半目・閉眼 | まつげの太さが急変せず、目尻が飛ばない。閉眼時に白目・虹彩・ハイライトが漏れない |
| 部品単体 | 透明背景上で確認し、元背景色の縁取りや他部品の画素が混ざっていない。部品の透明部分は正常であり「全画素不透明」を要求しない |
| パラメータの組み合わせ | 視線の端×半目×開口を必須ケースにする。単独、組み合わせ、通常へ戻す順に検査 |
| 連続動作 | 離散キーだけでなくキー間を低速で往復し、飛び・ちらつき・描画順の逆転を確認 |
| 表示環境 | 原寸、拡大、実際のアプリ表示サイズ、EditorとUnityで確認 |

現行の自動検査では、髪マット・固定輪郭・ハイライトの追従も検査する。外接矩形の外の画素一致は補助検査として扱う。画像保存・操作・画素一致の成功と、見た目の合格は別項目で記録する。

## 8. 制作順序と現行工程への適用

承認済みの閉眼見本と、開眼・閉眼を分離した26レイヤー素材を用意し、GIMP・ブラウザーで検証した。ここからは次の順で進める。

1. **高解像度の素材を仕上げる**：原寸試作で確認した顔立ちと閉眼の毛束を維持し、髪・まつ毛・肌・眼球の独立した部品構成を制作解像度で整える。
2. **Cubismで最小検証**：髪＋顔＋片目でPSDの互換性、描画順、クリッピング、視線と開閉の親子関係を確認する。開眼・閉眼を見本に合わせ、中間も低速で確認する。
3. **もう片目と口へ展開**：左右差を残し、口は上下唇と口内の構造へ移行する。
4. **組み合わせと実機表示を確認**：端の視線×半目×開口、通常への復帰、連続動作を検査し、SDK向けに書き出してUnityでも確認する。

自動生成は補助に使い、意味のある素材分離と外観確認を省略しない。GIMP・HTMLでの検査はCubism・Unityの検査を代替しない。

## 9. 閉眼ののっぺり感と、完成見本を先に作る工程（追加調査：2026-10-06）

### 結論

**シエルは、閉眼と半目の完成見本を先に決め、その絵に合わせてパーツとリグを作り直す。** 閉眼イラストの別途制作やAI生成がLive2Dの必須条件という意味ではない。今回、目標となる閉眼の絵を確定しないまま補間・マスク調整を繰り返していたため、制作順序を修正する。第8節の片目制作へ入る前にこの外観設計を行い、目周辺の描き込みを最後の高解像度化まで先送りしない。

### 提示画像と実装から分かること

追加調査時に提示された比較画像はGIMPで生成したソフトウェア描画であり、保存済みCubismモデルのスクリーンショットではない。

- 開眼時にあるまつ毛の厚み・目尻の形・色の変化が、閉眼では単純な弧へ置き換わっている。まぶたの面を感じさせる情報も乏しく、開眼との絵柄の差が大きい。これは提示画像の目視所見。
- 旧試作は閉眼線を正弦曲線で作り、開閉量の二乗を重みとして元のまつ毛画像から描画線へ移行していた。完全閉眼で元のまつ毛テクスチャが消える原因だった。現行工程は承認見本のまつ毛素材を用いる。
- まぶたの肌は周辺画素から作った `Skin_Backfill` を使う。閉眼用に描いた面の陰影ではない。当時の候補処理は閉眼途中の範囲に限られ、完全閉眼の絵を改善していなかった。

したがって、下縁のアンチエイリアスだけでは今回の違和感を解消できない。陶器のような白い肌そのものを問題視せず、まず閉じたまつ毛の形と厚みを整える。強い影や写実的なしわの追加は必須ではなく、シエルの絵柄に合う最小限の面表現を選ぶ。

| [公式・イラストの加工（4.2以前）](https://docs.live2d.com/4.2/cubism-editor-tutorials/psd/) | 目尻の跳ねたまつ毛を分離すると変形しやすい。隠れた白目を描き足す | まつ毛の特徴を残せる素材構成を先に用意する |
| [公式・下絵の配置](https://docs.live2d.com/cubism-editor-manual/sketch/) | PNG・JPGを下絵として配置でき、位置・サイズ・不透明度を調整できる | 閉眼見本を同じ座標で重ね、リグの到達形状を照合できる |
| [公式・下絵パーツ](https://docs.live2d.com/cubism-editor-manual/edit-parts-sketch/) | 下絵を含めない書き出し設定がある | 見本画像と実際に動かす素材を分けて管理できる |
| [公式・インスペクタ](https://docs.live2d.com/cubism-editor-manual/inspector-palette/) | 不透明度・描画順・クリッピングなどを設定できる | 補助素材を使う場合も、表示と重なりを明示的に設計する |

以上は公式の基礎工程と機能の確認であり、全制作会社に共通する規格や制作方式の普及率を示す調査ではない。閉眼画像の事前生成、しわの本数、陰影の濃さについて統一基準は確認できなかった。以下はシエルの品質上の課題に対する制作提案。

### 「閉眼画像を作る」の3つの意味

| 用途 | 方針 |
|---|---|
| 完成見本・下絵 | **先に作る。** 通常顔と同じ位置・比率で閉眼の見た目を確定し、合格基準として使う。手描き・画像編集・生成補助のどれでもよく、AI生成自体は必須ではない |
| 閉眼専用の部分素材 | 元のまつ毛の変形だけでは形を保てない場合に検討。目尻の毛束、閉眼のまつ毛、必要な陰影などを分け、開閉との表示切替・位置を調整する。途中で二重線や濃度の跳ねが出ないか検証する |
| 顔全体の画像差し替え | 今回の本制作では採らない。別画像の髪・鼻・肌まで変わると通常顔との連続性を維持しにくい。完成見本の一枚絵をそのままリグ素材として扱わない |

通常は既存まつ毛の変形を先に検証し、必要なら補助素材を併用する。閉眼専用素材の使用を全モデルの必須工程とはしない。また、別素材を用意しても途中の形状調整は必要であり、2枚の不透明度を逆方向に変えるだけで自然な瞬きになるとは限らない。

### シエルの制作指示

1. 承認済みの顔を基準に、同じキャンバス上で**通常・半目・自然な両目閉眼**を並べる。片目の検証は残しつつ、顔全体で見たときの印象も確認する。笑顔の閉じ目や強い目つぶりは別の表情として扱い、通常の瞬きと混ぜない。
2. 閉眼では、まつ毛の根元の厚み、先端の細さ、目尻の毛束、目頭から目尻への流れを設計する。開眼の目の形を機械的に押し潰さず、元の絵柄と同じ線の密度に整える。
3. まぶたの面は白磁の肌を維持し、必要なら淡い寒色の影・短い折れ線などを試す。濃い肌色、大きな影の帯、写実的なしわで埋めない。髪の影とまぶたの影を区別する。
4. 生成画像を使う場合は目周辺の候補作成に限定し、目の間隔、輪郭、小さな鼻、髪、肌色を元画像と照合する。生成結果の位置ずれや別人化をGIMPで修正してから見本とする。新しい見本はユーザーの外観確認前に承認済み扱いにしない。
5. 見本に必要な描き込みを含む制作解像度で、まつ毛本体・目尻・肌・必要な陰影を分離する。280×195の試作用切り出しを拡大するだけでは細部を復元できない。GIMP編集原稿とCubism用PSDを分け、読み込み結果を確認する。
6. 見本をCubismの下絵に置き、開眼1・半目0.5・閉眼0を出発点として形を合わせる。この3値は今回の開始点であり、十分なキー数を保証する標準ではない。必要な中間形状を追加し、低速で往復して形の飛びや線の二重化を直す。

### 外観の合格条件を追加する

- 閉眼を静止させても、まつ毛の描き込みと肌の質感が通常顔と同じ絵柄に見える。
- 自然な閉眼として見え、意図しない笑顔・眠そうな半目・目を強くつぶった表情にならない。
- 半目から閉眼の間で、目尻の毛束やまつ毛の厚みが突然消えない。元の開眼線や眼球の明部が残らない。
- まぶたの補完部分にパッチ状の境界がなく、髪を覆わない。立体感を足すために白磁の肌色を変更しない。
- 原寸とアプリ表示サイズで確認した後、拡大表示で素材の縁を点検する。画素一致・閉眼時の漏れゼロだけを完成判定にしない。

調査後に [閉眼の見本](assets/ciel/production/ciel-eye-appearance-study-v1.png) がユーザーに承認され、その素材を使う [現行プレビュー](assets/ciel/production/ciel-gaze-preview.html) へ移行した。到達点と未完了範囲は制作仕様書に集約する。

## 10. 髪と閉眼境界の追補（2026-10-06）

閉眼見本の採用後も、目の上に丸い肌の境界が見えるとの指摘があった。画像上の所見と実装から、髪の分離漏れと肌の補完境界を候補として調べる。原因の確定や修正完了を意味しない。

`eye_material_core.py` の髪抽出は限定した多角形内に明るさの条件を適用している。`build_approved_eye_motion.py` は目の編集領域を補完した肌で描画した後、その髪画素だけを再合成する。したがって「登録済みの髪の保持」は「本来の毛先をすべて分離できたこと」を保証しない。過去の組み合わせ検査の成功と今回の外観指摘は両立する。

| 公式で確認した工程・機能 | シエルへの適用案 |
|---|---|
| 前髪・横髪・後ろ髪を分け、隠れた部分を描き足す。[具体例は4.2版](https://docs.live2d.com/4.2/cubism-editor-tutorials/psd/)、[現行の素材分けマニュアル](https://docs.live2d.com/cubism-editor-manual/divide-the-material/) | 毛先の線まで保つ前髪パーツと、その背後の顔を用意する。元絵にない毛先を単なる切り抜きで復元できるとは考えない |
| 描画順で前後関係を設定できる。[公式：描画順](https://docs.live2d.com/cubism-editor-manual/draworder/) | 前髪をまぶた・肌より手前に置く。髪とまぶたの部品が混在した素材は、描画順だけでは直せない |
| 他のアートメッシュの形を使って表示を制限できる。[公式：クリッピング](https://docs.live2d.com/cubism-editor-manual/clipping-mask/) | 虹彩を眼球の範囲に制限する。髪の抽出漏れや肌の色差の修正とは別の処理として扱う |
| デフォーマで髪の動きを作り、物理演算で顔の動きに応じた揺れを設定できる。[公式：動き付け](https://docs.live2d.com/cubism-editor-tutorials/deformer/)、[公式：物理演算](https://docs.live2d.com/cubism-editor-manual/physics-operation/) | 静止状態の開閉で前後関係を確認してから揺れを加える。髪を瞬き変形の子にせず、頭部変形は共有する |

上表右列は本プロジェクトへの提案であり、全モデル共通の分割数や数値規格ではない。作業順序と受け入れ条件は [制作仕様書の第13節](ciel-live2d-production-spec-ja.md#13-前髪の分離と閉眼境界の修正) に定める。

## 11. 共通の顔下地と目パーツの変形へ移行

最新の採用方針は [制作仕様書の第16節](ciel-live2d-production-spec-ja.md#16-目のない顔の下地と独立した目パーツ最新方針再開位置)。目のない顔を先に仕上げ、目の部品をその上に重ねる。閉眼時だけ肌パッチを被せる処理の調整を繰り返さない。肌の補完自体は必要だが、素材制作の段階で行う。

公式の [目の開閉の具体例（4.2版）](https://docs.live2d.com/4.2/cubism-editor-tutorials/expression/) は、まつ毛を閉眼形へ変形し、白目をまつ毛の下に収め、白目にクリッピングした目玉も隠す手順を示す。[現行のメッシュ編集マニュアル](https://docs.live2d.com/cubism-editor-manual/mesh-edit-manual/) では、まつ毛等に変形に適した手動メッシュ編集を勧めている。閉眼イラストは到達形の見本として保持する。

実モデルの参考は公式の [桃瀬ひより](https://www.live2d.com/learn/sample/momose-hiyori/)。編集モデルと物理演算設定が提供され、デフォーマ・パラメータ・髪揺れを学ぶ資料になる。ただし今回確認したのは配布ページまでで、モデル内部の階層を実見したという意味ではない。
