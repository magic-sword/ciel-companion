# シエルに歌を聴いてもらう（A 段階の試作）

2026-10-27。仕組みの説明（図つき）は [シエルが歌を聴く仕組み](../singing-scoring-ja.md)。調べたことと方針は [歌を聴く機能の調査](../singing-evaluation-research-ja.md)（とくに 7 章）。音程を原曲に合わせる採点ではなく、「シエルという一人の聴き手の心に響いたか」で感想を言う。A 段階は、お手本なし（アカペラ・鼻歌、またはヘッドホンで伴奏を聴く）。

## 決めたこと

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 歌声の行き先 | **自宅の GPU サーバーの中だけ**。聴いているあいだは会話モデル（OpenAI Realtime）への声を止める（`session.input.set_audio_enabled(False)`）。会話モデルへ渡すのは、分析の手がかりの文字だけ | 利用者の指定（2026-10-27）。LiveKit 1.8 は外した入力のフレームを捨てる（`room_io/_input.py`）ので、歌声は OpenAI に届かない |
| 歌声の保存 | しない。会話サーバーのメモリーにためて分析に渡し、渡したら捨てる。分析のサービスもメモリーの中だけで扱い、ファイル・ログ・DB に残さない | 仕様書 8 章（ユーザーの音声を保存しない） |
| 始め方 | 声（道具 `start_listening_to_song`、「歌を聴いて」）。アプリの `ciel.song` の `start` も受ける（ボタンはまだ無い） | 会話の流れで頼むのが自然 |
| 終わり方 | アプリの札「歌い終わったらタップ」、歌ったあと 8 秒の静けさ、10 分の上限。「どうぞ」から 30 秒歌が始まらなければやめる | 聴いているあいだは会話モデルに声が届かないので、声では終われない |
| 聴いている間 | シエルから話しかけない（内なる考えを止める）。返事も作らない。「どうぞ」を言い終えるまでの声は使わない（シエルの声が混ざる） | 歌の途中で話し出さないように |
| 分析 | 新しいサービス `server/singing`（127.0.0.1:8767、GPU）。Audiobox Aesthetics の CE を 10 秒ごと、MERT の特徴の変わり目、CREPE の音の高さ、音量・帯域の手がかり（[analysis.py](../../server/singing/analysis.py)） | 調査の 7.2・7.3 |
| 感想 | 手がかりを文字にして（`singing.facts`）、[singing_feedback.md](../../server/agent/config/prompts/singing_feedback.md) と一緒に会話モデルへ渡し、シエルの言葉で言わせる。点数・数値は言わない。順番は「ぐっときた所 → 個性 → 提案 1 つ → 応援か質問」 | 調査の 7.3 |
| 音程の扱い | その人の音の基準（いつも少し低い・高いはそのまま）から外れた音と、ビブラートでない揺れだけを提案の候補にする。くせ（しゃくり・フォール・ビブラートが音の 30% 以上）は個性としてほめる側に回す。調の外の音（わざとの半音かもしれない）は外れにしない | 「外れて聞こえる」ことは好みに効くが、測ったずれと聞こえは人によって合わない（Bruder ら 2024） |

## ときめき度と、歌っている途中の表示（2026-10-27 追加）

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| ときめき度 | 0〜100 の「シエルの主観の点数」。聴かせてくれた点 40 に、響き（いちばん響いた区間の CE、25）・ぐっときた瞬間（理由の数、15）・表現（強弱の幅・盛り上がりや展開の変化・くせ、12）・伸び（揺れなかった伸ばす音の割合、8）を足す（`analysis.tokimeki`）。正しさの減点はしない | 利用者の希望。研究では専門家どうしでも点数がばらつくので、主観の点数だと分かる名前・見せ方にする |
| 目盛り | **仮**。CE は 3〜7 を 0〜1 にする（スマホのアカペラは 4〜5 くらい）。合成の歌声で 77〜81 点。本物の歌を何曲か聴いてから合わせ直す | 素の CE をそのまま使うと、どの歌も 40 点前後になる |
| シエルの言い方 | 感想の最初に一度だけ「ワタシのときめき度は 82 点！」と言う。内わけの点数は言わない | 画面にも出ているので |
| 結果のカード | 歌い終わったら `song.result` で、ときめき度・内わけ・ぐっときた所・あなたらしさ（くせ）・もう一歩（揺れた伸ばす音か、外れて聞こえたかもしれない音の時刻 1 つ）を出す | |
| 歌っている途中 | 5 秒ごとに直近 10 秒を `/live` に渡す。アプリへ `song.live`（ときめきメーター・♡・吹き出しのひとこと）と、シエルの表情を送る（`singing.LiveCues`） | 利用者の希望 |
| 途中のシエル | **声は出さない**。表情・♡・吹き出しの文字だけ。ひとことは決まった文から選び（会話モデルを使わない）、12 秒より間をあける | シエルの声がマイクに入って分析が乱れ、歌う人の邪魔にもなる。会話モデルに作らせると数秒遅れ、料金もかかる |
| ♡ の出る時 | その歌でいちばん響いた（CE がそれまでの最大で、中央値より 0.3 以上高い）、盛り上がり（帯域の音量が前の 2 回より 3 dB 以上）、展開の変化（MERT の特徴の変わり方が平均＋標準偏差以上） | 調査の 7.1 |
| GPU | 「どうぞ」を言い終えたら読み上げに作業用のメモリーを手放してもらい、歌のあいだ分析のモデルを載せておく。`/analyze` を終えたとき、または 30 秒使われなかったときに外す | 1 回ごとに載せると 4 秒かかる |

`/live` は手元の RTX 2060 で 1 回 0.45 秒（最初の 1 回はモデルを載せるので 8 秒）。声がほとんど無い 10 秒（息つぎ・間奏）はモデルを使わない。

## 歌のあとに「これから歌う」と取り違えた（2026-10-27）

- 起きたこと：歌い終わって感想をまとめているはずのときに、シエルが「これから歌い始める」と受け取った返事をすることがよくあった（利用者）。
- ログ：2 回目の歌では、分析が終わったその秒に、内なる考えが話しかけていた（`内なる考え：話しかける（recall…）`）。感想の返事と重なっていた。
- 原因：(1) 歌っているあいだは会話モデルへ声を送らないので、内なる考えの係から見ると「ずっと静か」で、歌い終わると静けさの分だけ話したい気持ちが上がっていた。(2) 分析が終わると、感想を話し終える前に「聴いている」状態を解いていた。(3) 貯めていた考えは歌う前のもの（「これから歌ってくれる」など）だった。(4) 分析中に話しかけると、会話モデルは「どうぞ」までしか知らないまま返事をしていた。
- 直したこと：感想（やめた・聞こえなかった・失敗のひとことも）を話し終えるまで、内なる考えを止めたままにする。話し終えたら、歌の前の考えを捨てて、静けさを今から数え直す（`Initiative.interlude`。知りたいことは残す）。会話モデルへの声は、感想を話し始めるときに戻す（分析中の声は送らない）。
- 1 回目の歌では、道具を呼んでから「どうぞ」を言い終えるまで 22 秒かかっていた（道具を呼んだ返事が話していた）。次の節で直した。秒数はログ `「どうぞ」を言い終えた` で見られる。

## 「どうぞ」までが長い（2026-10-27）

道具を呼んだ返事の前置きを止める（2026-10-27）：歌を聴く・議事録を始める／終える／過去の分をまとめる道具は、すぐ戻って、あとから短い一言を言わせる。会話モデルが同じ返事で前置きを何文も話すと、その一言が前置きを読み終えるまで待たされた（歌で「どうぞ」まで 22 秒。利用者は議事録でも同じと感じていた）。LiveKit は道具を読み上げと並べて動かすので、道具の中から `tools.cut_preamble` で頼み、読み上げている 1 文のあとは読まない（`emotion.PreambleCut`。止めるのは頼んだ返事だけ）。止めたらログに `道具を呼んだ返事の前置きを止めた` が出る。プロンプトで前置きを禁じることはしない（「やるな」を書くと会話の指示がよごれるため。利用者）。会話モデルは全部言ったつもりのままになる。

## 分析の中身

| 手がかり | 出し方 | 感想での使い方 |
| --- | --- | --- |
| 心に響いた度 | Audiobox Aesthetics の CE（1〜10）を 10 秒の区間・5 秒ずらしで | 歌の中で高い・低い所を見る。全体の高さは評価に使わない |
| ぐっときた瞬間の候補 | CE が高い区間に、盛り上がり・展開の変化が重なった所（最大 3 つ） | 最初に話す所 |
| 盛り上がり | 920〜4400 Hz の声の音量が、前の 2 区間より 3 dB 以上上がった区間 | 鳥肌の研究（Nagel ら 2008） |
| 展開の変化 | MERT-v1-95M の第 7 層を区間ごとに平均し、前の区間との違いが平均より 1 標準偏差以上大きい所 | 曲の展開の変化が感動のきっかけになる |
| 声の入り・明るさ・息・強弱の幅 | 声の出だしから -3 dB までの時間、スペクトルの重心、5 kHz より上の割合、音量の 95%−10% | 個性としてほめる材料（目安として） |
| くせ | しゃくり（入りが 80 セント以上下から）、フォール（終わりが 100 セント以上下がる）、ビブラート（伸ばす音の揺れが 4〜8 Hz に集まり、深さ 15 セント以上） | 個性 |
| 揺れ・外れたかもしれない音 | ビブラートでない伸ばす音の揺れ（30 セント超）、その人の基準から 40 セント以上ずれた 0.4 秒以上の音 | 提案の候補（1 つだけ） |

## 速さ・資源（手元の RTX 2060 6GB で測定、2026-10-27）

- 4 分 17 秒の合成の歌声で：Audiobox 2.4 秒、MERT 4.7 秒、CREPE full 24.2 秒。CREPE を tiny にすると 7.8 秒（声のある所の 99.8% が full と 50 セント以内で一致）。既定は tiny（`SING_CREPE`）。合わせて約 15 秒の見込み。
- GPU のメモリーは、CREPE full のとき最大 3.4 GB、tiny のとき最大 2.35 GB（MERT・Audiobox を含む）。

## GPU の分け合い方（2026-10-27）

- 自宅の RTX A2000 12GB は、読み上げ（Irodori-TTS）が 10.8 GB を取っていて、空きは約 1.1 GB だった。モデルの重み（約 3 GB のファイル）より大きく、大半は合成のたびに PyTorch が取っておく作業用のメモリーと見られる。
- 読み上げを外して載せ直す案は、起動のログで約 10 秒かかり（モデル・音声の符号化の読み込み、最初の合成まで）、載せ直しに失敗するとシエルが話せなくなる。そこで、**モデルは外さず、作業用のメモリーだけを手放してもらう**口（tts-irodori の `POST /release`、合成と同じスレッドで `torch.cuda.empty_cache()`）を足した。会話サーバーが分析の前に呼ぶ。次の合成で必要な分だけ取り直す。
- 歌を聴くサービスは、モデルを分析のたびに GPU に載せて、終わったら外す（`SING_KEEP=1` で載せたまま）。載せる時間を含めて、4 分の歌で 18〜24 秒（RTX 2060）。外したあとも約 0.5 GB が確保されたまま残る（使っているのは 8 MB。細切れのため返せない）。

## 検証

- 回帰テスト `server/agent/tests/test_singing.py`：手がかりの取り出し（しゃくり・ビブラート・揺れ・外れ・いつも低めの人を外れにしないこと・瞬間の選び方・展開の変化）、手がかりの文、聴く係の流れ（会話モデルへの声を止めて戻す、送る音の長さ、短い歌は送らない、静けさで終わる、やめる、サービスに届かないとき、道具）。オフラインの回帰テスト 303 件が通った。
- 分析のサービスは、手元の GPU で合成の歌声を通して動くことを確かめた。
- 自宅サーバー（2026-10-27 に反映）：4 分 17 秒の合成の歌声で、読み上げのメモリーを手放してから分析して 20.9 秒。読み上げは確保 3254 MB → 2244 MB（使っているのは 1906 MB）、分析中の GPU 全体の最大は 4890 MB（12 GB 中）、分析後は分析のサービスに約 0.6 GB が残る。
- **本物の歌声・実際の会話では、まだ確かめていない**。
- Unity はバッチでコンパイルが通ることだけ確かめた。札の見た目と、タップで終わることは未確認。

## まだのこと

- 本物の歌で、指摘が納得できるか・言い方がシエルらしいかを利用者に見てもらう（合否は「納得できる・うれしい・また歌いたくなる」）。
- 歌詞は聞き取っていない（OpenAI の文字起こしに歌声を送らないため）。必要なら自宅 GPU の文字起こしを足す。
- 「歌を聴いて」のボタン、ときめき度の目盛りの合わせ直し、同じ人の前回との比較、好みを育てる仕組み（調査 7.3 の 5・6）、声の高さの線（アプリの中でマイクの音を取れるか要確認）。
