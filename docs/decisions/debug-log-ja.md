# デバッグ用の会話ログ

決定日：2026-10-22。対象：`server/agent/debug_log.py`、`scripts/server/debug-log.sh`。

## 背景

返事の遅さ・トークン数・キャッシュの効き方を調べようとしたが、実際の会話で何が起きたかを後から追う手段が無く、試験用の声（`bench_latency.py`）で測るしかなかった。[仕様書](../specification-ja.md) 8 章では、利用者の音声と会話全文を自前の永続ログへ保存しない。

## 決めたこと（利用者の判断）

| 項目 | 決めたこと |
|---|---|
| ふだん | 残さない。開発・試験のときだけ入れる（仕様書 8 章の例外） |
| 入れ方 | 本番：サーバーの `server/agent/data/debug/ON` があれば、次に始まる会話から残す（`scripts/server/debug-log.sh on`・`off`。会話サーバーの再起動は要らない）。試験用の会話サーバー：環境変数 `CIEL_DEBUG_LOG=1` |
| 残す中身 | 文字も残す。発言の文字起こし、シエルの返事の文字、返事ごとに足した 1 行（話者の行・議事録の状態など）、道具の呼び出しと結果、Unity からの知らせ（タッチ・会話のしかたなど）、話し始め・話し終わりなどの状態、返事の速さ、トークン数（キャッシュ分を含む）。**音声は残さない** |
| 会議 | 入れているときは、会議につないでいるときも残す（会議の試験を解析するため）。ほかの参加者の発言の文字も残るので、会議の試験のときだけ入れ、終わったら切る |
| 残す日数 | 7 日（`CIEL_DEBUG_LOG_DAYS`）。会話が始まるたびに古いファイルを消す（入れていないときも消す） |
| 置き場所 | 自宅サーバーの `server/agent/data/debug/` だけ（Compose で `/app/data/debug` にマウント）。Git・デプロイ・LiveKit Cloud には出さない。持ち帰るときは手元の `.local/debug-logs/`（Git の外） |

## 形式

会話ごとに 1 ファイル（`<UTC の日時>-<部屋名>.jsonl`）、1 行に 1 つの出来事（JSON）。`t` は UNIX 時刻、`kind` は種類：`start`・`settings`（指示の文字数・道具）・`turn_end`（会話モデルの側が発言を区切った）・`transcript`・`item`（会話に入った発言・返事。LiveKit の `metrics` つき）・`reply_request`（返事を頼んだときに足した指示）・`tool`・`data`・`user_state`・`agent_state`・`latency`・`usage`・`instructions_changed`・`error`・`end`。1 つの値は 8,000 字まで。

返事を頼む場所（`turns.py`・`touch.py`・`initiative.py`・`agent.py`）と会話の指示を入れ替える場所（`mode.py`）はいくつもあるので、入れているときだけ `session.generate_reply` と `agent.update_instructions` を、記録してから元の処理を呼ぶものに差し替える。切っているときは何も差し替えない。

## 確かめたこと（2026-10-22）

- 自動テスト 7 件（切っているときは書かない・ON のファイルと環境変数で入る・長い値を切る・古いファイルを消す・差し替えの有無）。
- 試験用の会話サーバーで 7 文を話し、150 行が残ることを確かめた。このログから、返事ごとに足す 1 行が前の返事と変わると、キャッシュされる入力が 98% から 78% に下がる（指示の後ろの約 2,500 トークンを計算し直す）ことが分かった。
- 本番での入れ方・切り方・持ち帰りは、反映のあとに確かめる。
