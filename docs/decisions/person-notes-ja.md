# その人について覚えておくメモの決定記録

日付：2026-10-16（日本時間）。状態：試作。話者の識別（[決定記録](speaker-identification-ja.md)）と道具（[決定記録](tools-ja.md)）の上に作る。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 何を覚えるか | 声を覚えている人について、本人が自分で話したことの短いメモ（1 件 60 字くらい、1 人 50 件まで）。役割・シエルとの関係、好み、続いている予定、接し方の好み、「覚えておいて」と頼まれたこと | 次に会ったときの会話に活かすため |
| 覚えないもの | 健康・宗教・思想・性的指向・犯罪歴・民族・詳しいお金のこと（本人がはっきり頼んだときを除く）、ほかの人の個人情報、シエルの発言、推測、その場かぎりの雑談 | 配慮が必要な情報と、本人以外の情報を残さないため |
| 誰が書くか | 書くきっかけは 2 つ（2026-10-16 更新）：(1) 会話モデル（Realtime API）が道具 `remember_about_speaker` で 1 文を預ける。道具はすぐ戻り、返事を作り直さない（`ToolResult(reply_required=False)`）。(2) 会話の流れから拾い漏れを補う。どちらも、今のメモと突き合わせて保存するのは、会話の裏の別の文字のモデル（既定 `gpt-5.4-mini`、`CIEL_NOTES_MODEL`、`notes.py`） | 利用者の判断（2026-10-16）：リアルタイム性を優先。会話モデルに道具で書かせると、そのたびに返事が遅れ、二重に話すこともある。裏で書けば会話を止めない。1 回 約 2 秒（自宅サーバーで測定） |
| いつ書くか | 同意した人が 4 回話したとき、話が 40 秒途切れたとき、会話が終わるとき。最近の会話 30 行（ほかの人の発言も文脈として）と、その人の今のメモを渡し、足す・書き直す・消すを決めてもらう | 似たメモは足すより書き直させ、増えすぎないように |
| 日付 | 「来週」「明日」は、今日の日付をもとに日付に直して書く | あとで読んだときに意味が変わらないように |
| 誰が読むか | 会話モデルが道具 `recall_about_speaker` で読む。読めるのは、**いま話している本人が「声を覚えている人」だと自信を持って分かったときだけ**（「たぶん」のときは読めない） | 利用者の判断（2026-10-16、案 A）。会議で、ほかの人にその人のメモを話さないため |
| 一覧を渡さない | メモは指示に入れない。本人だと分かった最初の発言に「この人について覚えていることがある」と添え、必要なら会話モデルが読みに来る | 道具の決定記録と同じ方針（指示を長くしない、関係ない話を出さない） |
| 同意 | 声を覚えるときの質問を「お名前と声、それからお話ししたことも少し、覚えておいてもいいですか？」にして、一緒に同意をもらう（`people.notes_consented_at`）。すでに声だけ覚えている人（博士さん）には、会話の自然なところで一度だけ聞き、同意したら `agree_to_notes` | 利用者の判断（2026-10-16）。声よりも踏み込んだ情報なので、同意の範囲をはっきりさせる |
| 忘れること | 「それは忘れて」で 1 件ずつ（`forget_about_speaker`、読んだときの番号）。声の記録を消すと、メモも一緒に消える。管理用に `speaker_admin.py notes <番号>` | 本人が中身を確かめ、消せるように |
| ログ | メモの中身も会話も出さない（件数だけ） | 個人情報を診断ログへ出さない（仕様書 8 章） |

## 2026-10-16 の試験で分かったこと

- 博士さんが「ミルクティーが好き」と話してから同意したが、メモに残らなかった。原因：
  1. 記録係は、同意している人の発言だけを本人の発言として印を付けていた。同意の前の発言は、同意のあとも本人の発言にならなかった。
  2. 同意したときにすぐ書く仕組みが無く、そのあと本人が話さないまま接続が切れた。
- 対策：発言には、同意の前でも「この会話の話者」を付けておく（メモリーの中だけ。書くのは同意してから）。この会話の途中で名乗って覚えた人も、名乗る前の発言が本人の発言になる。同意したら、すぐ書く。人違いを直したときは、その発言を分けた人の発言にする。
- あわせて：シエルが「内部で処理を進めます、お待ちください」と言っていたので、道具や内部の処理のことを話さないよう `speakers.md` に書いた。崩れた感情の印（「[happ博士…]」「]」）を読み上げていたので、`emotion.strip_tags` で外すようにした。

## 道具と記録係の組み合わせ（2026-10-16）

- 利用者の提案：会話モデルが道具でメモでき、道具は呼んだらすぐ戻って、保存は裏で走る形。
- 決定：両方を組み合わせる。
  - 会話モデルは「覚えておいて」と頼まれたときや大事なことを聞いたときに `remember_about_speaker` で 1 文を預ける。声を直接聞いている会話モデルが決めるので、文字起こしの聞き間違いの影響を受けず、頼まれたことを確実に拾える。
  - 道具は預けるだけですぐ戻る（手元で 0 ms）。`reply_required=False` なので、道具のあとに返事を作り直さず、「お待ちください」や二重の返事が起きない。
  - 記録係は、預かったメモ（`requested_notes`）を今のメモと突き合わせて保存し、会話の流れから拾い漏れも補う。配慮が必要な情報・ほかの人の情報は、どちらの経路でも残さない。
  - 預けられるのは、いま話している本人で、声を覚えていて、お話を覚えることに同意している人のことだけ（道具の中で確かめる）。
- 確かめた（自宅サーバー、実際のモデルと DB、試験用の人は削除）：すでに「ミルクティーが好き」があるところに「ミルクティーが好き」「猫を 2 匹飼っている」を預けると、重ねずに猫の 1 件だけ足した（裏で 2.0 秒）。

## 「シエル」の聞き間違い（2026-10-16）

- 会話ログの解析：シエルが道具で「ミルクティーが好き」を預けて保存できた（17:37、1.2 秒後）。一方、裏の記録係が文字起こしから「博士はCLを開発している」を残し、接続し直したあとシエルが「CL」と話した。
- 原因：シエル（会話モデル）は声を直接聞いて分かっているが、メモの元の文字起こしは別のモデル（gpt-4o-mini-transcribe）で、「シエル」を「CL」などと書いていた。
- 測定（自宅サーバー、シエルの名前を含む合成音声 3 文）：ヒントなしは「チエル」「スチール」など 3 文中 2 文が誤り。日本語の指定だけでも 2 文が誤り。日本語＋ヒント（「AI キャラクター『シエル』との会話。出てくる名前：シエル、博士」）は 3 文とも正しい。
- 対策：文字起こしに日本語とヒントを渡す（`agent.py` の `transcription`。ヒントはシエルと、覚えている人の名前 30 人まで）。記録係にも「シエルが CL などに聞き間違えられることがある。直して書く。意味の分からない言葉は残さない」と教える。
- DB の「博士はCLを開発している」は「博士はシエルを開発している」に直した。
