# 返事ごとに変わる情報の渡し方（キャッシュを効かせる）

決定日：2026-10-22。対象：`server/agent/turns.py`（`TURN_CONTEXT`・`_add_context`）、`speakers.py`（`identify_parts`）。

## 背景

会話モデル（Realtime API）は、指示・道具の説明・会話の履歴の**頭から完全に同じ部分**だけをキャッシュする（[OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)）。返事ごとに足す情報（話者の行・議事録の状態など）は `generate_reply(instructions=…)` で渡していたが、LiveKit はこれを、その返事のあいだだけ「会話の指示＋足した分」に**置き換えて**送る。足した分が前の返事と変わると、指示から後ろ（道具の説明・会話の履歴）を計算し直していた。[デバッグ用の会話ログ](debug-log-ja.md)で、話者の行のある・なしが変わるたびに、キャッシュされる入力が 98% から 77% に下がることを確かめた。

## 決めたこと

| 返事ごとに足す情報 | 渡し方 |
|---|---|
| 話者の行（`[発言者：…]`。初めて分かったときの前に話した日・同意のことを含む） | **会話の後ろ**（相手の発言のすぐ後ろ）に system の項目として置く。過去の発言にも誰が話したかが残る |
| 議事録の状態（`[議事録状態]`） | **変わったときだけ**会話の後ろに置く |
| 覚えている人のメモ・関係 | 今までどおり返事ごとの指示に足す（利用者の判断）。会話に置くと、人前に切り替えても履歴に残り、ほかの人に伝わるおそれがある。指示なら、人前になったらすぐ外れる |
| ひかえめの念押し、議事録を始めた・終えたときの一言、おしゃべりの話しかけ、あいさつ | 今までどおり（念押しは同じ設定の間は変わらないのでキャッシュが効く。ほかはたまにだけ） |

プロンプトの本文は変えていない。`CIEL_TURN_CONTEXT`（既定 `items`。`instructions` で以前のやり方）。開発用の会話サーバー（[決定記録](dev-server-ja.md)）で確かめてから、2026-10-22 に本番に入れた。

### 置き方の注意

- LiveKit の `update_chat_ctx` は、項目を作る知らせを送ってから、置けたかの確認（1 往復、約 0.12 秒）を待つ。待ってから返事を頼むと、返事が 0.12〜0.14 秒遅れた。知らせを送るところまで進めて、確認を待たずに返事を頼む（同じ接続の上なので、「項目を作る → 返事を作る」の順に届く）。あとから断られたらログに残す。
- `update_chat_ctx` は手元の会話と会話モデルの側の会話の差を送るので、会話モデルの側にだけある項目（まだ手元に届いていない相手の発言など）があると、それを消してしまう。そのときは置かずに、今までどおり返事ごとの指示に足す。
- すぐに失敗したときも、今までどおり返事ごとの指示に足す。

## 確かめたこと（2026-10-22、試験用の会話サーバー、7 文）

| | 今まで（instructions） | 新しい渡し方（items） |
|---|---|---|
| 返事を頼むまで（会話モデルの側が区切ってから） | 0.28 秒 | 0.28 秒 |
| 最初の声 | 1.52 秒 | 1.50 秒（ばらつきの範囲） |
| 3 回目以降の返事のキャッシュ | 足した分が変わると 72〜77% に下がる | いつも 97〜98% |

- シエルは話者の行を口にしなかった。返事はどれも、その発言の中身に答えた。
- 置かずに指示へ足した回（会話モデルの側の会話が手元に届いていない）は 0 回、断られた回も 0 回。
- 自動テスト 6 件（話者の行が会話に置かれ指示に入らない・議事録の状態は変わったときだけ・メモは指示に残る・会話モデルの側にだけ項目があるときは置かない・失敗したら指示に足す）。

開発用の会話サーバーでのアプリからの会話（約 6 分、2026-10-22）：話者の行は 7 回とも発言のすぐ後ろに置けた。会話全体のキャッシュは 86%（OpenAI の側で 1 回だけ 0% になった返事を除くと 93%）。

まだのこと：2 人以上が交互に話す会話（試験の声も、アプリの試用も 1 人）。
