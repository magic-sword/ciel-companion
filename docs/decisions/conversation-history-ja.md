# 接続中の共通会話履歴

2026-10-18。人物メモ・議事録に加え、シエルが長い会話の具体的な発言を調べ直す用途を追加した。

## 構成

- 入力音声は従来どおり Realtime に渡し、入力書き起こしは別モデルで非同期に行う。通常の返答開始の待ち方は変更しない。
- `conversation.py` の `Conversation` が発言 ID・開始時刻・話者・話者の確かさ・確定状態・本文を持つ。部屋ごとに独立し、話者識別や DB が無い場合も利用できる。
- `turns.py` が話し終わりにユーザー発言の場所を予約し、書き起こし・話者判定が遅れてもシエルの返答より後ろへ並ばないようにする。LiveKit の書き起こし item_id と続くユーザー会話項目を結び付け、会話項目の `started_speaking_at` で声の区間を選ぶ。開始時刻を取得できない場合だけ従来の順序対応を使う。開始時刻があるのに対応する区間が無い場合は話者不明として記録する。
- シエルの本文は従来と同じ LiveKit の `conversation_item_added` から取り、感情の印と `[silent]` を外す。音声を再度書き起こす処理は追加しない。
- 人違いの訂正は共通履歴の直近の対象発言へ一度反映する。以後、各機能は同じ話者を参照する。処理済みの議事録の要約・保存済み人物メモを自動で遡及修正する機能ではない。

## 各機能

| 機能 | 入力・処理 |
|---|---|
| 会話検索 | `tools/conversation.py` の `search_conversation(query, first_id, last_id)`。短いキーワードの部分一致と文字 bigram で検索し、前後2発言を含めて発言順に返す。空の query は直近12発言、ID指定は最大20発言。本文の合計は最大7000字。時刻は日本時間。追加の外部API呼び出しなし |
| 人物メモ | 共通履歴の処理済み ID を人物ごとに持ち、未処理の発言を最大30行ずつ読み進める。多人数・同意が遅れた場合も、直近30行だけを読んでそれ以前を飛ばさない。本人の確かな発言・保存同意の制約を維持する |
| 関係の更新 | 人物メモの私有リストへの依存を外し、共通履歴を参照する。忘れる依頼は引き続き人物メモ係から受け取る |
| 議事録 | 開始時の発言IDより後から終了時点のIDまでを対象とする。10分ごとに最大100発言を処理してカーソルを進め、共通履歴を削除しない。終了時は対象範囲の未確定発言を最大5秒待ち、残りも最大100発言ずつ処理する。次の会議の発言を混ぜない。API失敗時は従来どおり原文を付けた下書きを作る |

要約後も元発言へ戻れることを優先した初期実装とする。会話検索専用の区間要約・意味検索モデル・Realtime側の履歴圧縮は追加していない。必要性を検索精度と待ち時間で判断して導入する。現在の検索は言い換えを十分に拾えないため、プロンプトで短いキーワードによる再検索と発言範囲の確認を指示する。

## 保持・欠落・同意

- 本文は接続中のメモリーだけに保持する。自前の会話全文ログ・DB保存は追加しない。議事録の明示的な開始・終了、Discordへの下書き送信と送信失敗時のローカル保存は既存仕様を維持する。
- 共通履歴は最大3000発言かつ本文合計200万字、1発言は最大16000字。上限を超えた古い発言は捨てる。区間要約による代替保存はしない。
- 検索結果に保持上限で失われた末尾ID、未確定件数、本文・結果の省略を明示する。未検出は「その話をしていない」証拠にしない。
- 人物メモと議事録は未確定の発言を飛び越さずに処理する。ただし20秒を超えた未確定区間では処理を進める。議事録は欠落・長さ上限を下書きへ明記する。人物メモは遅れて到着した本人の発言を次の更新で拾い直す。
- 人物メモの永続化同意・本人確認は従来どおり必要。会話検索は同じ接続内で共有されている会話の参照であり、過去の別接続や人物DBを検索しない。

## 検証

`server/agent` から、既存依存を入れた Python 3.11 以降で実行する。

```sh
python -m unittest discover -s tests -v
python -c "from persona import load_persona; print(load_persona().fingerprint)"
```

API・DB・Discordはモックに置き換え、遅延書き起こし、発言順、待機上限、保持上限、話者訂正、変更された決定の検索、人物メモの同意と未処理バッチ、議事録の開始終了・途中要約・失敗時の下書きを検証する。実際のモデルによる検索ツールの選択、書き起こしと声の区間の対応、割り込み時の発言、変更したプロンプトの会話品質・速度は実会話での比較が必要。ローカルテストはこれを保証しない。本番への配布は行っていない。
