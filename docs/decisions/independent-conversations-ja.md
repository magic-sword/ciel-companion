# 複数端末の独立した会話

2026-10-18。実装済み、本番未反映。端末ごとに別の会話を行い、同意して保存した人物の長期記憶を共有する。同じ部屋への複数アプリの参加は対象外。会議の音声はWindowsアプリとMeet・Zoom等の連携で扱う。

## 接続と状態の範囲

- Unityは新しい接続のトークンを取得するたびに `ciel-<UUID>` を部屋名として指定する。個人名や端末名を含めない。通信切断後のLiveKit自身の再接続は同じ部屋だが、アプリが新しく接続し直す場合は別の会話になる。
- 取得したJWTの `video.room` が要求した部屋と一致することを接続前に確認する。署名検証はLiveKitが行う。Endpointを利用する場合も `room_name` を守る必要がある。固定トークン（Literal）は部屋を毎回分けられないため、このアプリでは受け付けない。設定アセットの固定 `RoomName` は使用しない。
- 会話履歴・Web調査の記録・話者の仮名簿・議事録・音量・会話モードは部屋ごと。接続先を切り替えて前の会話全文を読む機能は追加しない。
- 人物の名前・声・同意・メモ・関係は従来の共通DBを使う。端末やアカウント別の記憶領域は追加しない。議事録の送信先も従来の共通Webhookのまま。

## 共有記憶の同期と競合

- `memory_versions` が人物ごとの版番号を持つ。名前・同意・声の見本・メモ・関係・忘却依頼の変更をDBトリガーで検知する。人物削除後も版番号を残し、稼働中の会話が削除を検知できるようにする。最終接触日時の更新では版番号を変えない。
- 話者の判定前・返答の補足情報の作成前と参照ツールで更新を確認する。変更された人物のキャッシュを無効化し、新規登録・改名・削除を反映する。削除された人物は保存済みの本人との対応を外す。DB障害時に以前のメモを再注入しない。通知の常時配信ではなく、次の発言・対応する参照ツールでの反映となる。
- メモと関係の更新は、版番号と対象情報を単一SQLのスナップショットで取得する。AIの処理中にDBロックを保持しない。保存時に人物と版番号をロックし、読み取り時の版番号と一致するときだけ、トランザクション内で反映する。
- 競合した場合は最新情報を読み直して再生成する。即時再試行は最大3回。メモの依頼は保持して次の更新機会へ回し、関係の更新は今回は見送る。人物が削除済み・同意がない場合は更新しない。同じ接続を使う別タスクが、他のタスクのトランザクションに混ざらないようStore操作も直列化する。
- `memory_forgets` は忘れる依頼の短い指定と処理状態を共有する。受付時に版番号を進め、関係の古い気持ち・気分を空にする。未処理中は以前のメモや気持ちの注入・読み上げと関係の更新を止める。メモ処理後も忘却指定を保持して、別の会話の過去発言を再処理するAIにも除外を指示する。人物削除時に忘却指定も削除する。意味に基づく削除の判断自体は従来どおりAIが行うため、版番号の検証だけで意味上の削除精度を保証するものではない。
- すでに会話モデルへ渡した情報や過去の会話項目を遡及削除する機能は含まない。声が未登録の同じ人物を複数の会話から同時に新規登録した場合の重複統合も対象外。同名だけでの自動統合は行わない。

## 共有GPUの音声合成

- GPUでの合成は1件ずつ維持する。待機中の要求を会話ごとに管理し、会話の順番を回して処理する。1会話の長い返答の全件を先に処理しない。
- 実行中を含め1会話4件・全体64件まで。超過はHTTP 429。待機から合成開始までの期限は25秒、サービス側の結果待ちは30秒。期限切れの待機要求は合成しない。
- クライアントは会話と要求の匿名IDを付ける。返答の割り込みやHTTP失敗時には、短い独立した接続で取消要求を送る。待機中なら除去し、実行中ならGPU処理を中断せず結果を破棄する。取消通信が失敗しても、開始前の期限判定は残る。
- 待ち時間を `X-Queue-Ms` とログ、合成時間・音声長をログに記録する。本文は音声合成ログへ出さない。GPUを増やすかは2端末同時利用の測定結果で判断する。

## 検証

- ローカルの自動テスト122件に合格。別途、隔離したPostgreSQL＋pgvectorで5件の結合テストに合格（通常のテスト実行では `CIEL_TEST_DB_URL` 未指定時にこの5件をスキップ）。
- DBでは古いメモの上書き防止、関係の会話回数の保持、忘却依頼による古い処理の拒否、削除済み人物の再作成防止、同一接続上の別タスクを巻き込まないロールバックを確認した。DB起動時のスキーマ作成も複数接続から検証した。一時DBは本番と分離し、検証後にコンテナを削除した。
- 音声合成は実GPUを使わず、会話間の順番、上限、期限、待機中の取消、実行中の結果破棄、クライアントからの取消送信を確認した。
- 設定済みのLiveKitトークン取得先に2件の異なる部屋名を要求し、JWTがそれぞれ指定どおりの部屋を許可することを確認した。部屋への参加・音声送信は行っていない。
- Windowsビルド成功（Unity 6000.6.4f1、`CIEL_BUILD_OK`）。出力は `unity/Builds/Windows/CIEL Companion.exe`。最初の制限環境での直接起動はライセンスIPC接続待ちとなったため終了し、既存のUnity Hub経由でビルドを確認した。
- 実際のWindows・スマホの2台同時会話、応答時間の比較、Android再ビルド・実機確認は未実施。本番へのデプロイも未実施。

結合テストは、通常のアプリDBではなく、明示的に作成した使い捨てDB `ciel_concurrency_test` を `CIEL_TEST_DB_URL` に指定する。テストは接続先のDB名を確認してからスキーマ作成・書き込みを行う。
