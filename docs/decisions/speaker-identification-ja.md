# 多人数の会話での話者の識別の決定記録

日付：2026-10-15（日本時間）、2026-10-16 更新（2 人のときも判定する、覚えている人は道具で調べる、返事を作らせるのを文字起こしの確定まで待つ、多人数では呼ばれたときだけ作らせる）。状態：試作。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 方式 | 会話モデル（Realtime API）には今までどおり声を渡し、発言が終わるたびに（2 人でも多人数でも）会話サーバーで話者を判定して、「[発言者：…]」の 1 行を足してから返事を作らせる | Realtime API に話者の機能は無い（開発者フォーラムに要望が出ている段階）。声を文字にしてから渡す方式（話者分離つきの文字起こし）より、抑揚が伝わり、遅れと料金が増えない |
| 声の特徴 | ECAPA-TDNN（SpeechBrain の `speechbrain/spkrec-ecapa-voxceleb`、Apache-2.0）。192 次元。CPU で計算する | 話者照合の定番で小さい（約 15 MB）。手元の PC の CPU で 3 秒の声が約 0.23 秒。GPU は読み上げに使う |
| 照合 | 覚えている人（DB）は会話の始めにメモリーへ読み込み、発言ごとにコサイン類似度で比べる。人ごとに見本を最大 30 持ち、似ている上位 3 つの平均を使う | 数十人規模なら DB へ毎回問い合わせなくてよい。マイクや部屋の違いに強くするため、見本を複数持つ |
| 記録の場所 | PostgreSQL＋pgvector（`pgvector/pgvector:0.8.0-pg17`）のコンテナ。自宅サーバーの 127.0.0.1:5433 だけで待ち受ける | 利用者の判断（2026-10-15）。将来の「会話の記憶」も同じ場所に置ける |
| 同意 | **本人がはっきり同意した人だけ** DB に保存する。シエルが名乗った人に「声を覚えてもいいですか？」と聞く | 利用者の判断（2026-10-15）。声の特徴は個人を識別できる情報（個人情報保護法の「個人識別符号」）で、会議の参加者は利用者本人ではない |
| まだ覚えていない人 | 「知らない人A・B…」として、その会話の間だけメモリーで区別する。DB に残さない | 同意の無い人の声の特徴を保存しない |
| 消すこと | 本人が「私の声を忘れて」と頼んだら消す（直前の発言者がその人のときだけ）。管理用に `speaker_admin.py`（一覧・削除・全削除） | 他人が勝手に消せないように。判定に失敗して本人が消せないときの手段も用意する |
| 返事の作らせ方 | 会話モデルの自動の返事を止め（`create_response=False`）、LiveKit も自動で返事をしない（`turn_detection='manual'`）。話し終わりの判定と割り込みは今までどおり会話モデルの側（semantic_vad） | 話者の 1 行を、返事より先に足すため。LiveKit が別に返事を作って二重にならないように manual にする |
| 返事を作らせる時 | 会話モデルの側が発言を区切り、その**文字起こしが確定したとき**（`user_input_transcribed` の final）。そのとき次を話し始めていたら（読点の間で区切られたとき）待って、続きと合わせて 1 回にする。1.2 秒未満の短い発言は 0.6 秒待ってから。文字起こしが空なら作らせない。文字起こしが 5 秒たっても確定しなければ、そのまま作らせる（2026-10-16） | 話し終わり（`user_state`）で作らせていたときは、LiveKit の手元の VAD（silero）が会話モデルの側より先に、読点の間でも区切るので、発言の声が会話に入る前に返事を作らせ、1 つ前の発言に答えていた（下の「返事がずれた件」）。文字起こしの確定を待つと、声が会話に入ったあとなので、「[発言者：…]」がその声の後ろに入る。会話モデルの側の区切りから返事を作らせるまで約 0.6 秒（文字起こし 約 0.4 秒＋判定 約 0.15 秒） |
| 多人数で返事を作らせる条件 | 文字起こしに「シエル」（「しえる」「AI」「エーアイ」）があるとき、またはシエルが質問で終わる返事をしてから 20 秒以内のときだけ作らせる。それ以外は作らせない（声は会話に残るので、話の流れは覚えている）。作らせるときも答えるか `[silent]` かは会話モデルが決め、返事ごとに `config/prompts/group_turn.md` の念押しを添える（2026-10-16） | 指示（`group.md`）だけでは、会話モデル（gpt-realtime-2.1-mini）が呼ばれていない発言にも答えることが多く、一度答えると、続く人どうしの話も自分への返事と受け取って答え続けた。名前を呼ばずに「みんなはどう？」と聞かれたときは答えない（呼んでもらう） |
| 2 人のとき | 2 人でも話者を判定する。知らない声なら、会話が一段落したところで一度だけ名前を聞く（2026-10-16） | Android などで 1 対 1 で話すときも名前を覚えられるように（最初の版は多人数のときだけで、Android の試験では名前を聞かれなかった）。同じ端末を家族で使うときの区別にもなる。返事の前に約 0.15 秒の判定が入る |
| 覚えている人を会話モデルが知る方法 | 一覧を指示に入れない。発言ごとの「[発言者：…]」と、道具 `lookup_person`（覚えているか）・`people_here`（この会話にいる人）で、必要なときだけ調べる（2026-10-16） | 人数が増えても指示が長くならず、会話に関係ない名前を出さない。道具の決まりは [道具の決定記録](tools-ja.md) |
| GPT-Live | 対象外（返事の作らせ方を変えない） | 聞きながら話す全二重なので、発言ごとに区切る方式と合わない |

## 判定の結果と、会話モデルへの伝え方

| 結果 | 会話モデルへの 1 行 | 条件（既定値、環境変数で変えられる） |
|---|---|---|
| 覚えている人 | `[発言者：田中（声を覚えている人）]`。この会話で初めて分かったときは `…。前に話したのは10月15日）]` | 類似度 0.45 以上（`CIEL_SPK_MATCH`） |
| たぶん覚えている人 | `[発言者：たぶん田中（声を覚えている人）]` | 0.35 以上（`CIEL_SPK_MAYBE`） |
| この会話で聞いた人 | `[発言者：知らない人A（まだ名前を知らない人）]`、名乗ったあとは `[発言者：田中（名前はこの会話の間だけ。声は覚えていない）]` | 0.45 以上 |
| 初めての声 | `[発言者：知らない人B（まだ名前を知らない人）]` | どれにも届かない |
| 不明 | 多人数：`[発言者：不明]`。2 人：何も足さない（直前の人のままとみなす。2026-10-16） | 声のある部分が 1 秒未満（`CIEL_SPK_MIN_SECONDS`） |

- よく当たった（0.60 以上、`CIEL_SPK_ADAPT`）2 秒以上の発言は、覚えている人の見本に足す（1 回の会話で 3 つまで）。会うたびに精度が上がるように。
- 判定する声は、会話サーバーが Unity のマイクのトラックを別に受けて 30 秒ためておき（メモリーの中だけ。古いものから捨て、ファイルや DB には書かない）、「話し始め」の知らせの 0.8 秒前から「話し終わり」までを取り出す。そのうち声のある 20 ms だけを残し、最後の 8 秒を使う。
- 基準の値は仮。Zoom を通した実際の声で測って決め直す。

## 仕様書 8 章との関係

仕様書 8 章は「初期版ではユーザー音声と会話全文を自前の永続ログへ保存しない」。この方式は録音も会話も保存しない。保存するのは、**同意した人の名前と声の特徴（192 個の数）と日時だけ**。声の特徴も個人を識別できる情報なので、次のように扱う：

- 同意した人だけ保存し、本人の依頼で消す。
- DB は自宅サーバーの中だけ（外から入る口を開けない）。パスワードは `server/.env`（Git に入れない）。
- ログには名前も声の特徴も出さない（DB の番号と類似度だけ）。
- ほかの人へ公開する前に、利用規約・説明の文面と、保存の期間（例：長く会っていない人は消す）を決める。

## 2026-10-16 の試験で分かったこと

- Android（2 人）で「博士」と名乗り、同意して保存できた。接続し直しても、発言のたびに「覚えている人 #2」と判定された（類似度 0.56〜0.66、判定は約 80 ms）。
- ところが会話モデルは、覚えていないかのように「この会話の間だけ」と言い、接続のたびに同意を聞き直した。原因は 2 つ：
  1. 「覚えている人」も「この会話の間だけ名前を聞いた人」も、同じ `[発言者：博士]` で届いていて、区別できなかった。
  2. シエルが声で人を覚えて、次の会話でも分かるしくみを、会話モデルに説明していなかった。
- 対策：呼び名に状態を添える（上の表）。`speakers.md` の最初に覚えるしくみを書き、覚えている人には名前も同意も聞き直さないと教える。覚えている人に `name_speaker` が呼ばれたら「もう覚えています」と返す。

## 2026-10-16 の確認（Android、スピーカー）

- DB に保存しているのは、名前・日時・声の特徴（192 次元のベクトル）だけ。音声の列は無い（`people`・`voiceprints` の列を確認。博士さんの見本 14 個で計 11 kB）。
- シエル自身の声が「初めての声」になったり、DB に入ったりはしていなかった（エコー除去が効いている）。
- 1 秒未満の短い発言が「[発言者：不明]」になり、シエルが「声がまだ判別できない」と話してしまった。2 人のときは何も足さないようにした。
- 返事の最後に残った書きかけの感情の印（「[happy」）を読み上げようとしていた。`emotion.strip_tags` で外すようにした。

## 人違いを直す（2026-10-16）

- 声が似ていて別の人と判定されたら、本人が「私はハカセじゃない」と言い、会話モデルが `not_this_speaker` を呼ぶ。
  - 直前の発言の声の特徴を、判定された人から外す。その発言で DB に足した見本があれば消す（`add_voiceprints` が足した行の番号を返す）。
  - その人を別の人（名前を言われればその名前、言われなければ知らない人）として、この会話で区別する。その会話の間は、判定された人（ハカセ）の見本を自動で足さない。
  - 以後、その人の発言は、分けた人の見本に入っていく。照合では、分けた人を元の人より少し（0.05）優先する。
- 照合を、覚えている人とこの会話の人をまとめて比べ、一番近い人にするように変えた（以前は、覚えている人が基準を超えればそちらを優先していた）。
- 一番近い人と次に近い人の差が 0.05 未満（`CIEL_SPK_MARGIN`）なら、断定せず「たぶん」にする。
- 作った声の特徴での試験：
  - 似た声（ハカセと田中の声の類似度 0.8 程度）：人違いを直したあとは、田中さんの発言はすべて田中さん、ハカセさんの発言はハカセさんと判定された。次の会話でも 2 人を区別できた。
  - ほとんど同じ声（類似度 0.92）：次の会話で、ハカセさんが「たぶん田中」になった。ここまで似た声は、声だけでは区別しきれない（名前で確かめてもらう）。

## 返事がずれた件（2026-10-16）

議事録の段階 B の試験（[議事録の決定記録](meeting-minutes-ja.md)）で、多人数のモードなのにシエルが呼ばれていない発言に答え、返事が 1 つ前の発言に答える形にずれた。

- 調べ方：本番の会話サーバーとは別のコンテナで、`agent_name` を付けた会話サーバーを動かし、明示して呼んだ部屋にだけ入れた（部屋を `agents` 付きで作ると、本番の会話サーバーは入らなかった）。試験用の参加者が Irodori-TTS の 2 つの声（caption で男声・女声）で 8 文（呼ぶのは 2 文）を流し、Realtime API との送受信（`LK_OPENAI_DEBUG=1`）を時刻つきで見た。
- 議事録の追加（コミット 98dfea9）の前（98c3d93）でも同じようにずれた。議事録の追加が原因ではない。
- 原因：`turns.py` は `user_state` が話している→聞いているになったときに返事を作らせていた。この状態は LiveKit の手元の VAD（既定の silero。Realtime の側で返事を作らせない設定のときに使われる）でも変わり、会話モデルの側（semantic_vad）より 0.5〜3 秒早く、読点の 0.4 秒ほどの間でも区切る。そのため：
  1. 発言の声が会話に入る（`input_audio_buffer.committed`）前に「[発言者：…]」と `response.create` が送られ、返事が 1 つ前の発言に答えた。
  2. 「シエル、」のような読点の前の 0.5 秒が別の発言になり、「[発言者：不明]」で返事を作らせた（発言ごとに 2 回）。
- 直したあとの試験（同じ 8 文、別のコンテナ）：
  - 文字起こしの確定を待つだけ：返事は正しい発言に答え、読点で区切られた発言は 1 回にまとまった。ただ、呼ばれていない発言にもよく答えた。
  - 返事ごとに念押し（`group_turn.md`）を添える：2 回のうち 1 回は呼ばれていない 6 文で黙ったが、もう 1 回は最初の発言に答えたあと、続く発言にも答え続けた。
  - 呼ばれたときだけ作らせる（今の形）：呼ばれていない 6 文では返事を作らせず、「シエル、展示のテーマで何かいい案ある？」にはテーマの案、「シエル、準備には何日くらいかかると思う？」には「2〜4日くらい」と、その発言に答えた。2 人のモードでも 3 文すべてに答えた（短い「うん。」にも 0.6 秒待って答えた）。
- まだ：実際の会議（Zoom などの声）で、呼ばれたのに文字起こしで「シエル」にならず黙ってしまうことがどれくらいあるか。
