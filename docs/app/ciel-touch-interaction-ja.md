# タッチの入力と端末内反応

> 責務：タッチの当たり判定、部位・変形・入力の送信と端末内反応。

この資料は触れた部位の判定、モデルの動き、サーバーへ送る入力を説明する。入力の重複・期限・発話と表情の優先は[共通反応契約](../conversation/service-events-and-reactions-ja.md)、パラメーターは[リグ](live2d/ciel-live2d-rig-design-ja.md)が正本。

## 端末側

`CielTouch`は、触れた点の不透明な描画部品と手前からの重なりを見て部位を決める。tap、stroke、hold、頬のpullを区別し、撫で始め/終わり等のphaseを付ける。当たり判定の範囲・しぐさの閾値はUnityの実装を正本とする。

| 部位 | 反応の範囲 |
|---|---|
| 頭・耳 | 顔の向き・耳・表情、撫でる/つつく反応 |
| ほっぺ | 押す・つまむ変形、強さに応じた困り/半泣き等 |
| 髪 | 物理演算へ指の動きに応じた力を加える |
| 肩・手 | 部位のばね・向き・表情 |
| 胸・おなか・首等 | 対応する触覚反応として扱わない |

触れている点は実際に表示されるモデル座標で扱う。画面の一律の矩形だけで顔・衣服・奥の髪へ誤って当てない。描画上の左右とモデルのL/Rを区別する。即時の身体・表情は端末で反応し、LLMやGPU推論を待たない。

## 送信と受信

`CielConversation.SendTouch`がtopic `ciel.touch`へ`user.touch v2`を送る。event_id、source_epoch、seq、occurred_atと部位・しぐさ・phase等を付ける。旧版を受け入れる互換分岐は置かない。正式な型は[入力契約](../conversation/service-events-and-reactions-ja.md)を参照する。

ホストの`touch.py`と共通反応基盤が妥当性、重複、期限、会話の世代を確認する。文脈の補足とMouthによる発話へつなぎ、直接generate_replyを乱立させない。通常のタッチで進行中の会話を無条件に中断しない。

## 誰が触ったか

端末への接触だけで本人を特定しない。話している区間または直近の話者から推定できる場合も、その確かさを維持する。会議の向こうの人物を画面へ触れた人とみなさず、手がかりがなければ名前を付けない。推定を保存同意・記憶アクセスの権限へ昇格させない。

## 検証

入力の版・不正値・二重送信、部位と変形、表情の優先と期限、発話中/考え中の調停を確認する。実際の端末とマイクでの快適さ・反応時間は別に測り、[確認状況](../testing/verification-status-ja.md)を更新する。
