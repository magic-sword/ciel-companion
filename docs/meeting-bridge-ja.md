# シエルを Zoom・Google Meet の会議に参加させる（多人数の会話）

全体の構成は [システムの構成](architecture-ja.md) を参照。

更新：2026-10-15（日本時間）。試作の段階。会議にはシエルが「別の参加者」として入り、何人かの人と同時に話す。

## しくみ

LiveKit の部屋に入るのは、今までどおり Unity のアプリ（CIEL Companion）と会話サーバー（server/agent）だけ。会議の人たちは LiveKit の部屋には入らない。
シエル用の会議のクライアント（ブラウザ）のマイク・スピーカー・カメラを、仮想オーディオケーブルと OBS の仮想カメラでアプリにつなぐ。

```
会議（Zoom / Meet）
 ├─ 利用者 … 普段のアプリかブラウザ（実際のマイク・ヘッドホン）
 ├─ ほかの参加者
 └─ シエル … 別のブラウザ（例：Edge）で「シエル」として参加
       スピーカー：Hi-Fi Cable Input ─→ Hi-Fi Cable Output ─→ アプリの「マイク」 ─→ 会話サーバー（シエルが聞く）
       マイク    ：CABLE Output     ←─ CABLE Input       ←─ アプリの「声の出力」 ←─ 会話サーバー（シエルの声）
       カメラ    ：OBS Virtual Camera ←─ OBS のウィンドウキャプチャ ←─ アプリの配信用のウィンドウ（シエルと背景だけ）
```

向きの違う 2 本の音の線が要るので、仮想ケーブルを 2 本使う。会議システムは自分の声を自分に返さないので、シエルの声が入力へ戻ってくることはない。

## 用意するもの（初回だけ）

| もの | 入手先 | 用途 |
|---|---|---|
| VB-Audio Virtual Cable（無料） | https://vb-audio.com/Cable/ | シエルの声 → 会議（「CABLE Input／CABLE Output」） |
| VB-Audio Hi-Fi Cable（寄付制・無料で使える） | 同じページ | 会議の音 → シエル（「Hi-Fi Cable Input／Output」） |
| OBS Studio（映像も流すとき） | https://obsproject.com/ja | アプリの画面を仮想カメラにする |
| シエル用の会議の参加口 | — | Zoom はブラウザからゲスト名で入れる（主催者の設定による）。Meet はゲスト参加を主催者が承認する。安定させるならシエル専用のアカウントを作る |

仮想ケーブルを入れたら PC を再起動する。

## アプリのビルド（Windows）

会議で使うときは、Unity のエディタではなくビルドしたアプリを使う。

- Unity のメニュー **CIEL ＞ Build ＞ Windows**、または Unity を閉じて、リポジトリの `unity` で次を実行（Git Bash。PowerShell では `--` が渡らない）：
  ```sh
  "/c/Program Files/Unity Hub/resources/unity.exe" --no-banner run . --timeout 1800 --log-file ./Logs/build-windows.log -- -executeMethod Ciel.Companion.Editor.CielBuild.Windows
  ```
- 出力：`unity/Builds/Windows/CIEL Companion.exe`（Git 管理外）。処理は `Assets/Editor/CielBuild.cs`。詳しくは [アプリのビルド](build-ja.md)。
- ビルドの設定：前面でなくても動き続ける（Run In Background）、ウィンドウで開く、大きさを変えられる。会議中に OBS やブラウザを操作しても会話が止まらないようにするため。
- ビルドには LiveKit の接続の設定（`Assets/Settings/LiveKitTokenSource.asset`）が入る。**ほかの人に配らない。** `..._BackUpThisFolder_ButDontShipItWithYourGame` も配らない。
- アプリのログ：`%USERPROFILE%\AppData\LocalLow\CIEL\CIEL Companion\Player.log`

## 会議のたびの手順

### 1. アプリ（CIEL Companion）

1. `CIEL Companion.exe` を起動する。
2. 設定 → そのほか → 「声のつなぎ方」で **会議** を選ぶ（選んだものは次回も使われる）。左上の名前が「C I E L ・ 会議」になる。
   - マイクと声の出力が、会議の組にまとめて切り替わる。仮想ケーブルは名前から自動で見つける（会議の音を聞く：**Hi-Fi Cable Output**、会議へ話す：**CABLE Input**）。見つからなければ黄色の注意が出るので、欄で選ぶ。
   - 会議にすると、マイクが自動で入る。**会議のあいだ入れたままにする。** 切るとシエルには何も聞こえない。
   - 終わったら **ふだん** に戻す。自分のマイクとスピーカー（それぞれ別に覚えている組）に戻る。
3. 同じ画面で、つながっているかを確かめる（会議のクライアントを開いたあと。3 の手順）：
   - 会議のだれかが話すと「● 会議の音が届いています」と光る。光らなければ、シエル用の会議のクライアントのスピーカーが **Hi-Fi Cable Input** になっているか。
   - 「シエルの声を試しに流す」を押すと、シエルが「シエルです。わたしの声、聞こえていますか？」と話す。会議で聞こえなければ、会議のクライアントのマイクが **CABLE Output** になっているか。この一言は会話モデルを使わないので、OpenAI が使えないときも確かめられる。
4. 右上の会話のしかたが「ひかえめ・人前」になっていることを確かめる（その場にいる人が自動のとき）。
5. 左上の接続の表示が「止まっています・OpenAI の残高切れ」などになったら、会話サーバーが聞き取り・返事をできていない。原因を直してから、表示をタップしてつなぎ直す（[困ったとき](#困ったとき)）。

### 2. OBS（映像も流すとき）

1. ソースの「＋」→「ウィンドウキャプチャ」→ `[CIEL Companion.exe]: CIEL Companion 配信`。キャプチャ方式は「Windows 10 (1903 以降)」。
   - アプリを起動すると、操作用のウィンドウ（`CIEL Companion`）のほかに、シエルと背景だけを映す配信用のウィンドウ（`CIEL Companion 配信`）が開く。設定・参加者の名前・ボタンは操作用のほうにだけ出るので、配信用のほうを取り込む。
   - 配信用のウィンドウは大きさを自由に変えられ、その大きさで描く（最初は 540×960。次に開くときも同じ大きさ）。横長にすると、シエルの左右に背景が広がる。閉じたときは、設定 → そのほか → 「配信用のウィンドウを開く」で開き直す。
   - 配信用のウィンドウは最小化しないで、ほかのウィンドウの後ろに置いておく（最小化すると描くのを止める）。
2. 配信用のウィンドウは縦長（540×960）なので、横長のキャンバス（1280×720 など）の中央に置く。
3. 「仮想カメラ開始」を押す。

### 3. シエル用の会議のクライアント

利用者とは別のブラウザ（例：利用者が Chrome なら Edge）か別のプロファイルで、名前を「シエル」にして入る。

**Zoom（ブラウザ版）**
1. 招待リンクを開き、「ブラウザから参加」を選ぶ。
2. 「コンピューターオーディオで参加」を押す。
3. 画面下のマイクのボタンの横の「^」で選ぶ：
   - マイク：**CABLE Output**
   - スピーカー：**Hi-Fi Cable Input**
4. 映像を流すなら、カメラの「^」で **OBS Virtual Camera**。
5. 音声の設定で「背景雑音を抑制」を「低」にするか、「オリジナルサウンド」をオンにする（合成の声が雑音として削られないように）。

**Google Meet**
1. 会議のリンクを開き、参加する前の画面か、参加後の「︙」→「設定」→「音声」で選ぶ：
   - マイク：**CABLE Output**
   - スピーカー：**Hi-Fi Cable Input**
2. 「動画」でカメラを **OBS Virtual Camera**。

### 4. 利用者

いつものアプリかブラウザで、実際のマイクと**ヘッドホン**で同じ会議に入る（スピーカーだと、会議の音を実際のマイクが拾い直す）。

### 5. 参加者への説明

会議に AI（シエル）が参加し、会議の声を会話サーバー（OpenAI の Realtime API）で処理することを、参加者に先に伝えて了承を得る。

## 会話のしかた（おしゃべり度・その場にいる人）

アプリの設定の「声と会話」で選ぶ（右上の表示をタップすると、おしゃべり度を順に切り替える。選んだものは次回も使われる）。

| おしゃべり度 | 答え方 |
|---|---|
| ひかえめ | 次のときだけ答える：「シエル」と呼ばれた／シエルへの質問やお願い／シエルの直前の発言への返し／その場の全員への質問。答えるときは 1〜2 文 |
| ふつう | 話しかけられるたびに答える |
| おしゃべり | 答えるうえに、45 秒ほど静かだとシエルから話しかける。返事がなければ、次までの間を倍にしていく（10 分まで） |

| その場にいる人 | 覚えている人のこと（メモ）の出し方 |
|---|---|
| ひとり | 本人のメモを渡し、シエルから話題にする |
| 身近な人 | 本人のメモを渡すが、心に留めておくだけ（話の流れで自然に生かす） |
| 人前 | メモを渡さない。本人に聞かれたら道具で読む |
| 自動 | 会議につないでいれば人前（おしゃべり度もひかえめにする）、この会話で 2 人以上の声を聞いたら身近な人、それ以外はひとり |

会議につないでいるかは、設定の「声のつなぎ方」（ふだん・会議）で決める（`CielConversation.Route.cs`）。会議の組の「自動」は、機器の名前の頭が `CielConversation` の Meeting Listen Names（Hi-Fi Cable Output・CABLE-B Output・VoiceMeeter Out）・Meeting Speak Names（CABLE Input・CABLE-A Input・VoiceMeeter Input）に合うものを、前から順に探して使う。ほかの仮想ケーブルを使うときは、欄で選ぶか、この名前を足す。2026-11-02 より前の版で仮想ケーブルを選んでいた設定は、初回の起動で会議の組へ移り、ふだんは OS の既定から始まる。

しくみ：

- Unity は `ciel.style` のデータのメッセージ（`{"v":1,"type":"conversation.style","talk":"quiet","presence":"auto","meeting":true}`）を、つないだとき・会話サーバーが部屋に入ったとき・設定やつなぎ方が変わったときに送る。
- 「シエルの声を試しに流す」は `ciel.soundcheck`（`{"v":1,"type":"voice.test"}`）。会話サーバー（`server/agent/soundcheck.py`）が決まった一言を読み上げ（Irodori-TTS だけ）、相づちのトラックで流し、`voice.test`（topic `ciel.event`。`state` は playing・failed）で返す。
- 会話サーバーの聞き取り・返事・読み上げが失敗したら、`agent.problem`（topic `ciel.event`。`kind` は quota・auth・rate_limit・error、`service` は stt・llm・tts、`stopped` は会話が止まったか）で知らせる（`server/agent/health.py`）。エラーの本文は送らない。
- 会話サーバー（`server/agent/mode.py`）は、いまの答え方・出し方を決め、その決まり（`config/prompts/talk_*.md`・`presence_*.md`）を指示の最後に足す（`update_instructions`。会話の途中で切り替わる）。決めた結果は `conversation.style`（topic `ciel.event`）で Unity へ返す。
- 答えないとき、会話モデルは `[silent]` とだけ出す。`mode.drop_silent` が読み上げ・文字起こしから捨てる。会話の履歴には残るので、黙っていたあいだの流れもシエルは覚えている。
- ひかえめは `CIEL_VOICE=irodori`（文字から声を作る方式）のときだけ使える。ほかの方式では、会話サーバーはふつうで続ける。

## 話者の識別（多人数のとき）

会議では、発言ごとに声の特徴（ECAPA）で話者を判定し、会話モデルに「[発言者：田中（声を覚えている人）]」「[発言者：知らない人A（まだ名前を知らない人）]」のように伝える。2 人のときも含めた使い方は [人を覚える機能の使い方](people-memory-ja.md)、しくみと決まりは [決定記録](decisions/speaker-identification-ja.md)。

- **名前を覚えてもらう**：シエルに「シエル、私は田中です」と名乗る。シエルが「声を覚えてもいいですか？」と聞くので、覚えてよければ「いいよ」と答える。覚えた人は、次の会議でも名前で分かる。
- **覚えてもらわない**：断れば、その会議の間だけ名前で呼ばれ、声は保存されない。名乗らない人は「知らない人」として区別されるだけで、保存されない。
- **呼び名を直してもらう**：本人が「ハカセじゃなくて、ハカセイです」「これからは○○って呼んで」と言う（声を覚えている人なら、次の会議からもその呼び名）。直せるのは本人の呼び名だけ。管理用には `docker compose exec agent python speaker_admin.py rename <番号> <新しい呼び名>`。
- **人違いを直してもらう**：声が似た人と間違えられたら、「私はハカセじゃないよ、田中です」と言う。シエルはその人を別の人として区別し直し、その会議の間は田中さんとして見本を集める。覚えてよいか聞かれたら答える。
- **忘れてもらう**：本人が「シエル、私の声を忘れて」と言う。うまくいかないときは、自宅サーバーの `~/work/ciel-companion/server` で `docker compose exec agent python speaker_admin.py list` で番号を確かめ、`docker compose exec agent python speaker_admin.py delete <番号>` で消す。
- 名乗る前の数回の発言や、1 秒未満の短い発言は、うまく判定できないことがある。

## 議事録をとる

会議の発言を議事録にまとめ、下書きを利用者だけが見る Discord のチャンネルへ送れる。参加者に先に伝えてから使う。準備（アプリの設定画面の「議事録」タブで、送り先の Discord の Webhook を足して選ぶ）としくみは [議事録の決定記録](decisions/meeting-minutes-ja.md)。

- 始めるとき：アプリの「議事録」のボタン（マイクボタンの左）を押すか、「シエル、議事録とって」と頼む。シエルが「議事録、とり始めますね」のように一言告げ、ボタンが「議事録をとっています」になる。
- 終わるとき：もう一度ボタンを押すか、「シエル、議事録まとめて」と頼む。シエルが一言告げ、少しあとに下書きが届く。
- 開始を忘れたとき：「ここまでを議事録にして送って」「直近30分を議事録にして送って」と頼む。今の接続で保持中の会話から下書きを作って送る（今後の記録は始めない）。記録中の場合は、進行中の議事録を終了して送るか確認する。
- 遅れて開始するとき：「10分前から議事録をとって」と頼む。保持中の過去分も対象にして記録を続け、終わりは通常どおり頼む。接続前や保持上限で失われた会話は対象にできない。すでに記録中の開始範囲は変更しない。
- アプリを使えないときは、自宅サーバーの `~/work/ciel-companion/server` で `docker compose exec agent python minutes_admin.py start`／`finish`。
- 送り先を切り替えるとき：設定画面の「議事録」タブで押して選ぶか、「シエル、議事録は仕事用に送って」と頼む（登録済みの名前から選ぶ）。
- Discord の下書きを確かめて直してから、共有先へ貼る。

## 困ったとき

| 症状 | 確かめること |
|---|---|
| シエルが何も反応しない | まず左上の接続の表示。「止まっています・OpenAI の残高切れ」なら OpenAI の請求設定でクレジットを足し、表示をタップしてつなぎ直す（2026-11-02 に実際に起きた。配線は合っていたのに、聞き取りと返事が残高切れで止まっていた）。表示が「つながっています」なら、設定 → そのほか の「会議の音」が会議の発言で光るか（光らなければ、マイクが切れている・シエル用の会議のスピーカーが Hi-Fi Cable Input になっていない） |
| 会議にシエルの声が聞こえない | 設定 → そのほか の「シエルの声を試しに流す」で一言が会議に聞こえるか。聞こえなければ、「会議へ話す：」が CABLE Input か、シエル用の会議のマイクが CABLE Output か、会議の側でミュートになっていないか |
| ふだん使うときに、話しかけても届かない・シエルの声が聞こえない | 声のつなぎ方が **会議** のままになっていないか（左上が「C I E L ・ 会議」）。**ふだん** に戻す |
| シエルの声が小さい・途切れる／PC のスピーカーからシエルの声が鳴る | Windows の「設定 → システム → サウンド → 音量ミキサー」で、CIEL Companion の出力が CABLE Input になっているか。PC のスピーカーから鳴っていると、利用者のマイクがそれを拾って会議へ小さく流れる。2026-10-15 より前のビルドは、接続のときに WebRTC が声の出力を OS の既定（通話用の機器）へ戻していた（接続の後に選び直すよう修正済み）。2026-10-17 より前のビルドは、会話の途中で「声の出力」を変えても反映されなかった（シエルの声の受信をいったん止めて切り替えるよう修正済み） |
| シエルの声が途切れる・小さい | シエル用の Zoom の雑音の抑制を「低」にするか、オリジナルサウンドをオンにする |
| 呼んでも答えない・呼んでいないのに答える | 会話サーバーのログで「多人数の会話：シエルは黙った」「会話のしかた：quiet・public」が出ているか。判断の決まりは `config/prompts/talk_quiet.md` |
| アプリを前面から外すと止まる | 古いビルドを使っていないか（Run In Background はビルドの設定で入れてある） |

会話サーバーのログは、自宅サーバーの `~/work/ciel-companion/server` で `docker compose logs --tail 50 agent` で見る。

## 今の制限（試作）

- 話者は声の特徴で判定する（下の「話者の識別」）。1 つの発言に 2 人の声が混ざると、主な話者しか付けられない。
- 多人数でも、誰かが話し終わるたびに会話モデルは動く（黙るかどうかを決めるため）。出力は `[silent]` だけなので料金は小さい。
- シエルが話している途中で誰かが話し始めると、シエルの話は止まる（2 人のときと同じ割り込み）。
- 映像には操作の部品（ボタン・選択欄）も映る。会議用に隠す表示は未実装。
- 確かめていないこと：実際の会議での聞き取り・判断の精度、Zoom・Meet の雑音の抑制との相性、OBS での取り込み。

## 今後の候補

- 会議用の表示（操作の部品を隠す、横長の画面、単色の背景）。
- 話者の区別：OpenAI の `gpt-4o-transcribe-diarize`（Realtime で使えるかはアカウント次第）か、自宅 GPU の pyannote など。
- 迷う発言だけ、別の小さなモデルで「答えるべきか」を判断する。
