# シエルに歌を聴いてもらう機能：調べたことと方針案

日付：2026-10-27（日本時間）。きっかけ：カラオケの採点機能のように、シエルに歌を聴いてもらい、点数・感想・直すところを言ってほしい。まだ作っていない。論文・製品の事例を調べ、今の構成（[システムの構成](architecture-ja.md)）で使えそうな方法をまとめた。

## 1. カラオケの採点は「音の高さが合っているか」が中心

- DAM の精密採点は、音程・安定性・表現力（抑揚・しゃくり・こぶし・フォール）・リズム・ビブラート＆ロングトーンを項目ごとに測り、合計する加点方式と解説されている。いちばん重いのは音程（お手本のメロディーに合っている割合）。計算式は公表されておらず、出典は攻略サイト・個人ブログ（[UTATEN](https://utaten.com/karaoke/point/)、[ねとらぼ](https://nlab.itmedia.co.jp/cont/articles/3272332/)）。
- つまり、カラオケの採点は**曲ごとのお手本のメロディー（音符と時刻）**を持っていて、歌声の高さと比べている。お手本がないと、音程正確率は出せない。

## 2. 研究：お手本ありとお手本なしの 2 通り

| 方式 | 分かったこと |
|---|---|
| お手本と比べる | NUS の Gupta らは、音の高さ・音程の幅・リズム・ビブラート・声の明るさ・強弱の幅などを、お手本と DTW（時間のずれを吸収して並べる方法）でそろえて比べ、専門家の評価と合う点数を作った。単純な距離より大きく改善したと報告（[PESnQ, APSIPA 2018](https://nowpublishers.com/article/Details/SIP-094)、[2017](https://smcnus.comp.nus.edu.sg/archive/pdf/2017-2018/2017_Perceptual_Evaluation_of_Singing_Quality.pdf)）。人の総合評価は、項目ごとの評価の足し算でほぼ説明できる（[TASLP 2019](https://smcnus.comp.nus.edu.sg/archive/pdf/2019-2021/2019_Chitra_TASLP_08871113.pdf)）。リズムを音の高さでそろえると、音程とリズムが混ざる弱点も指摘されている |
| お手本なし | 音の高さの分布（音階の音にどれだけ集まっているか）などで、人の評価と順位相関 0.716（同じ NUS の流れ）。伴奏の調（キー）を手がかりにする方法（[Hsieh ら, Interspeech 2025](https://www.isca-archive.org/interspeech_2025/hsieh25c_interspeech.pdf)、本文は未確認）。声の特徴を入れて学習する TG-Critic（[2023](https://astro.paperswithcode.com/paper/tg-critic-a-timbre-guided-model-for-reference)） |
| 言葉で評価する | Sing-MD は、一般の人の歌に専門家が息の使い方・声色・感情・技術を付けたデータ。**専門家どうしでも評価がかなりばらつく**ので、正確さだけの点数には限界があると述べ、言葉による評価へ移ることを提案（[ACM MM 2025](https://arxiv.org/html/2512.06999v1)） |
| 合成音声の評価 | SingMOS-Pro は歌声合成の品質評価用。人の歌の採点にはそのまま使えない（[arXiv 2510.01812](https://arxiv.org/abs/2510.01812v2)） |

## 3. 音声の AI に直接聴かせるだけでは、音程は判断できない

- **PitchBench**：音声の AI に音の高さを当てさせると、平均の正答率は GPT-4o audio 8.4%、Gemini 3.1 Pro 17.8%、最もよい Qwen-3.5 Omni Plus でも 47.7%。音程の幅（インターバル）は全モデル 11% 以下。基準の音を一緒に聞かせると大きく上がる（[arXiv 2605.26176](https://arxiv.org/html/2605.26176v1)）。
- **VocalCoachBench**：ボイストレーナー 18 人の指導を正解にした試験。2 つの歌のどちらが上手いかは 74.5%（Qwen3.5-Omni Plus）まで当たるが、具体的な問題点の指摘は「いつも多い答えを返す」よりも当たらず、厳密な診断の的中は全モデル 7% 未満。**直し方の助言はもっともらしく聞こえるのに、診断が外れている**ことが多い。点数は同点だらけで当てにならない（[arXiv 2609.04241](https://arxiv.org/html/2609.04241)）。
- 結論：点数と指摘は**数値で測ってから**、それを言葉にする役を文字のモデルに任せる。音声の AI は、声色・雰囲気の感想など、外れても困らない部分の補助に限る。

## 4. 使えそうな部品

| 役割 | 候補 | メモ |
|---|---|---|
| 歌声の高さ（F0） | **RMVPE** | 伴奏が混ざった音から直接、歌声の高さを取るために作られた。雑音に強い（[arXiv 2306.15412](https://arxiv.org/abs/2306.15412v2)） |
| | **FCPE** | MIR-1K で RPA 96.79%、RMVPE と同程度で約 5 倍速く軽い（[arXiv 2509.15140](https://arxiv.org/html/2509.15140v1)）。歌いながら音程バーを出すならこちら |
| | CREPE | 1 つの音だけの前提。伴奏が混ざると落ちる。今回は選ばない |
| 伴奏と歌の分離 | **BS-RoFormer**（公開の学習済みあり）、HTDemucs v4 | 歌声の SDR は BS-RoFormer が約 10.5〜10.7、Hybrid Demucs 8.1（[arXiv 2508.14556](https://arxiv.org/pdf/2508.14556)）。原曲からお手本の歌を取り出す・スピーカーの伴奏を消すのに使う。歌い終わってからの一括処理なら GPU 12GB で足りる見込み（未測定） |
| 歌声を音符にする | **ROSVOT**（MIT、ACL 2024）、SOME（openvpi）、basic-pitch（Spotify） | 原曲の歌から「お手本のメロディー」を作る。ROSVOT は雑音下で他より良いと報告（[arXiv 2405.09940](https://arxiv.org/html/2405.09940v2)）。SOME・basic-pitch は今回未調査 |
| 並べる | DTW、歌詞の文字起こし（既存の `gpt-4o-mini-transcribe`） | テンポのずれを吸収して、「サビの 2 回目」など場所を特定する |

## 5. シエルの今の構成で気をつけること

- **歌の最中に返事をしてしまう**：今は話し終わりを Realtime API が見つけて返事を作る。歌っている間は、会話の入力を止めて（または返事を作らせず）、サーバーで歌声を録り続ける「歌を聴くモード」が要る。
- **マイクの音の加工**：通話向けの雑音除去・自動音量・エコー消しは、伸ばした声やビブラートを削ったり、強弱を平らにしたりするおそれがある（未確認。LiveKit Unity SDK で切れるか要調査）。
- **伴奏の聞こえ方**：スマホのスピーカーで伴奏を流すとマイクに入る。ヘッドホンをすすめるか、分離で消す。アプリ自身が伴奏を流せば、お手本と時刻がそろい、いちばん正確になる。
- **料金**：数値の計算は自宅 GPU で無料。言葉にするのは文字のモデル 1 回（数値の要約だけを渡す）。歌の音声を丸ごと音声の AI に送るのは高くつくので、使うなら回す前に見積もる（[料金のかかる試験](paid-checks-ja.md)）。
- **著作権・保存**：原曲・伴奏のファイルは利用者の手元かサーバーの一時領域だけに置き、Git にも OpenAI にも送らない。歌声の録音は採点が終わったら消すのを既定にする。歌の記録を人物メモに残すなら、今の同意の仕組みに合わせる。

## 6. 方針案（段階的に）

**A. まずお手本なし（鼻歌・アカペラ・伴奏はヘッドホン）**
1. 「歌を聴いて」で歌を聴くモードに入り、歌い終わり（「おしまい」かボタン）で抜ける。
2. RMVPE で歌声の高さを取り、次を数値で出す：音階に乗っている割合（キーを推定して）、音の安定（伸ばした音のぶれ）、ビブラート（速さ・深さ・回数）、ロングトーン、音域、強弱の幅、しゃくり・フォール（音の入りと終わりの形）。
3. 数値と「どこで」を JSON にして文字のモデルへ渡し、シエルの人物像のまま、点数（参考点と明示）・よかったところ・直すところ 1〜2 個を返す。読み上げは今の Irodori-TTS。
4. 確かめ方：利用者が自分の歌を数本録り、「この指摘は合っている・的外れ」を付けてもらう。可能ならカラオケの採点（DAM など）の点数と並べて傾向が合うかを見る。点数が近いことより、**指摘が納得できて、言い方がシエルらしいか**を合否にする。

**B. お手本あり（利用者が原曲のファイルを用意）**
- 原曲 → BS-RoFormer で歌を取り出す → RMVPE ＋ ROSVOT でお手本のメロディー → DTW で歌声と並べ、音程正確率・リズムのずれを出す。「サビの 2 回目で低め」のように場所を言える。

**C. 歌いながら（アプリが伴奏を流す）**
- 端末か サーバーで FCPE を回して音程バーを出す。歌っている最中のシエルの反応（手拍子・表情）はこの段階で考える。

## 7. 追加調査：音程の正しさより「上手に聞こえる・心に響く」で聴く（2026-10-27）

きっかけ：サカナクションの山口一郎さんが、カラオケの採点に合わせると歌の個性が消える、という趣旨を話していた（利用者の記憶。切り抜き動画の題「カラオケ採点機能は使っちゃダメ」は見つけたが、発言の中身は未確認：[yutura](https://yutura.net/channel/150219/video/JiuDP2Q-se4/)）。音の高さを合わせる採点ではなく、聴いた人の感じ方で評価できるかを調べた。

### 7.1 研究で分かったこと

| 調べたこと | 分かったこと |
|---|---|
| 好きな歌声は何で決まるか | 訓練を受けた歌手 16 人のアカペラ 96 本を 326 人が評価した。**測った音の特徴（約 300 種）では好みがほとんど説明できず**、聴いた人が感じた印象（10 項目）なら好みの 43% を説明できた。効いていたのは、**聞こえの上での音程の正しさ・響き（薄い〜豊か）・声の入り（柔らかい〜硬い）**。聴く人どうしの一致は非常に低い（[Bruder, Poeppel, Larrouy-Maestri, Scientific Reports 2024](https://communities.springernature.com/posts/perceptual-but-not-acoustic-features-predict-singing-voice-preferences)、[MPI の紹介](https://www.aesthetics.mpg.de/en/newsroom/news/news-article/article/the-magic-of-voices-why-we-like-some-singers-voices-and-not-others-1.html)） |
| 音程の扱い | 上の研究でも「音程が合って**聞こえる**こと」は好みに効く。ただし測った音程のずれと、聞こえの音程の正しさの関係は、人によって無い〜中くらい。**機械で測ったずれをそのまま減点するのは、聴く人の感じ方と合わない** |
| 専門家の評価 | 一般の人の歌に専門家が息・声色・感情・技術を付けても、専門家どうしでばらつく。点数より言葉で伝える評価を提案（[Sing-MD, ACM MM 2025](https://arxiv.org/html/2512.06999v1)） |
| 鳥肌・感動の瞬間 | 鳥肌が立った部分では、920〜4400 Hz の音量が上がっていた（[Nagel ら 2008](https://jyx.jyu.fi/handle/123456789/19439)）。きっかけは音の変化・曲の展開の変化・感情の表現の 3 種（[Beier ら 2020](https://memlab.bard.edu/files/2020/12/Beier20_Chills_AestheticsCreativityArts_preprint.pdf)）。新しいフレーズや強弱の変化と重なる（[Frontiers 2017](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2017.02044/pdf)）。日本の研究では、**鳥肌は音の特徴、涙は歌詞の内容と結びついていた**（2011。検索結果の要約で見ただけで、論文の原本は未確認）。感動の瞬間は人によって違い、当てるのは難しい |
| 曲の感情 | 音楽の感情（明るさ＝valence、高ぶり＝arousal）の推定は、高ぶり r=0.81、明るさ r=0.67 程度まで（[Eerola のメタ分析 2025](https://c4dm.eecs.qmul.ac.uk/news/2025-06-06.C4DM-Seminar_Tuomas_Eerola/)）。MERT など音楽向けの学習済みモデルで推定できる（[MERT](https://arxiv.org/pdf/2306.00107)） |
| 音声の AI | 2 つの歌のどちらが良いかの比較は 74.5% まで当たる。具体的な問題点の診断は外れる（3 章の VocalCoachBench）。言葉の感想を学習させる研究もある（[VocalCritic, NeurIPS 2025](https://arxiv.org/abs/2512.02523)） |

まとめ：「上手に聞こえる」は、測った正しさではなく**聴く人の感じ方**で決まり、しかも人によって違う。だから、**シエルという一人の聴き手の感想**として返すのが、研究にも山口さんの考えにも合う。ただし「外れて聞こえる」ことは好みに効くので、音程は無視せず「伝わりを邪魔したときだけ」触れる。

### 7.2 足せそうな AI モデル

| モデル | できること | 動かす場所・条件 |
|---|---|---|
| **Meta Audiobox Aesthetics** | 音を 4 つの軸で採点：作りの質（PQ）、**聴いて楽しい・心に響く（CE）**、複雑さ、使いやすさ。短い区間ごとに出せば「どこで響いたか」の曲線になる | 小さいモデル。自宅 GPU で動く見込み（未測定）。CC-BY 4.0（一部 MIT）。GitHub の LICENSE は未確認（[論文](https://ai.meta.com/research/publications/meta-audiobox-aesthetics-unified-automatic-quality-assessment-for-speech-music-and-sound/)、[GitHub](https://github.com/facebookresearch/audiobox-aesthetics)） |
| **SongEval** | 曲全体のまとまり・覚えやすさ・**息づかいとフレーズの自然さ**・構成の分かりやすさ・音楽性の 5 項目。音楽の訓練を受けた 16 人が評価した約 2,400 曲で学習 | 道具は公開（[arXiv 2505.10793](https://arxiv.org/abs/2505.10793)、[GitHub](https://github.com/ASLP-lab/SongEval)）。英語・中国語の、伴奏つきの完成した曲が対象で、素人の歌・日本語に効くかは要確認。データは CC BY-NC-SA とする二次情報あり（非商用） |

| **Music Flamingo（NVIDIA）** | 音楽を聴いて言葉で説明する（声色・構成・歌詞・感じ）。最長約 15 分 | 公開モデルだが**非商用の研究用**（[モデルカード](https://huggingface.co/nvidia/music-flamingo-hf)）。大きく、12GB の GPU に載るかは未確認 |
| **Qwen3.5-Omni（API）** | 試験で最も成績がよかった音声の AI。2 本の歌の比較、声の印象の言葉 | 外部の API。歌声を外へ送ることになるので、同意と料金の見積もりが要る |

### 7.3 方針案の見直し：「シエルの心に響いたか」で聴く

1. **感想を軸にする**：返す順番は「どこでぐっときたか → よかったところ（個性として） → もっと伝わるための提案 1 つ」。点数を出すなら「正確さ」ではなく「シエルのときめき度」のような、シエルの主観だと分かる名前にする。
2. **聞こえの印象を測る**：響き（倍音の豊かさ）、声の入り、息づかい、強弱の流れ（盛り上がり）、声の明るさの変化を、数値ではなく「印象の言葉」に直すための手がかりとして使う。Audiobox Aesthetics の CE を区間ごとに出し、盛り上がり（920〜4400 Hz の音量の増加、強弱の変化）と重なったところを「ぐっときた瞬間」の候補にする。
3. **歌詞と表現を結びつける**：涙は歌詞と結びつくので、文字起こしの歌詞と、その部分の声の変化（強くした・息を混ぜた・溜めた）を並べて、「『〜』のところ、気持ちが伝わってきた」と言えるようにする。
4. **音程は個性と崩れを分ける**：同じくせが曲を通して繰り返される（しゃくり・崩し・低めに入る）なら個性としてほめる側に回す。ばらばらに揺れて「外れて聞こえる」ところだけ、提案の候補にする。原曲に合わせることは目標にしない。
5. **比べる相手は本人の前回**：原曲の歌手ではなく、同じ人の前の歌と比べる（「前より響きが増えた」）。2 本の比較は AI でも当てやすい。記録を残すなら人物メモと同じ同意の仕組みに乗せる。
6. **好みを育てる**：聴く人で好みが違うので、シエル自身の好み（人物像の設定）を決め、利用者の反応（「うれしい」「そこじゃない」）で少しずつ合わせる。集まれば MERT の上に小さな判定器を学習させる。

A 段階の試作（自宅 GPU の Audiobox Aesthetics・MERT と文字のモデルだけ。歌声は外へ送らない）は [歌を聴く決定記録](decisions/singing-ja.md) にまとめた。

確かめ方：利用者が同じ曲を何回か歌い、「どれが一番よかったか」「シエルの言った『ぐっときた所』は自分でも手応えがあったか」を付ける。合否は「納得できる・うれしい・また歌いたくなる」か。

ライセンスの注意：SongEval と Music Flamingo は非商用。個人の開発・試作では使えるが、アプリを公開する前に外すか、条件を確かめる。

## 8. 決めてほしいこと

- 最初に想定する歌い方：アカペラ・鼻歌／ヘッドホンで伴奏／スピーカーで伴奏。
- 原曲のファイルを用意して使う想定があるか（B へ進むか）。
- 点数を出すか、感想と指摘だけにするか（研究では、専門家どうしでも点数はばらつく）。出すなら「シエルのときめき度」のような主観の点数にするか。
- 歌声を外部の音声の AI（Qwen3.5-Omni など）へ送ってよいか。送らないなら、自宅 GPU のモデル（Audiobox Aesthetics・MERT）と文字のモデルだけで組む。
