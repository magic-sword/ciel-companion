# サービス処理の整理・検証記録

実施日：2026-11-10。[設計方針の正本](design-policy-ja.md)と[サービス境界の仕様](service-boundaries-ja.md)に基づく実装。[能力カタログ導入時の記録](capability-runtime-2026-11-10-ja.md)に続く変更です。

## 実装した変更

- `service_mcp.py`へMCP通信・スキーマ検証・期限・取消・結果サイズ制限・計測を集約し、モデルの道具呼び出しと基盤専用の処理で再利用した。
- `ResearchService`へ検索・引用検証を抽出。利用者の依頼とCuriosityの自発的検索が、同じMCP検索処理へ到達する。履歴、画面通知、発話との対応はWebResearcherが保持する。
- メモ整理、関係性更新、好みの成長、出来事の保存・読み込みを`memory_jobs`の基盤専用操作へ接続。信頼できる対象を処理へ束縛し、人物IDをLLMやMCPの公開引数へ追加しない。既存Storeの同意・スコープ・競合検知を維持した。
- 記憶の生成・保存が取消になった場合、処理中の保存・削除要求をキューへ戻すよう修正した。
- AppEnvが受け取った端末のraw schemaを共通MCPアダプターで検証してから端末へ転送する。Unityの`ciel.app`通信形式は維持した。
- 画像の説明生成を`ImageAnalysis`へ抽出。MCP入力は保持済み画像の参照だけとし、画像受信・保持・会話への添付はEyesが担当する。
- YouTubeの動画情報・コメントページ取得を`youtube_source`のMCP処理へ抽出。キー・接続先・HTTPセッションは基盤側に束縛し、コメントの選択・到着イベント・返答判断はホストに残した。

## 検証結果

| 確認 | 結果 |
|---|---|
| 単体回帰テスト | 600件合格、失敗・エラー・skipなし |
| 隔離PostgreSQL結合テスト | 9件合格、失敗・エラー・skipなし |
| 追加したサービス境界のテスト | 上記単体に含む10件。最後に同じ10件を再確認して合格 |
| 会話入口からのオフライン結合確認 | ロード→道具・指示の公開→実MCP→検索ホストまで合格 |
| `git diff --check` | 空白エラーなし |

追加テストでは、自発的検索が実際のMCP検索を使うこと、端末に送る前のアプリ引数検証、画像参照の失効、ローカル構成での画像解析不可、記憶生成取消時の保存・削除要求の保持、基盤操作がモデルの道具にならないこと、サービス期限による取消、MCP結果への内部例外本文の非公開、任意のYouTube取得操作の拒否を確認した。

既存のYouTubeテストも、ローカルHTTPサーバーによる動画情報・コメント取得を今回のMCP経路で確認している。実際のYouTubeサービスへの接続ではない。

出来事保存の旧テストはイベントループ1回分の待機で保存が進むことを前提にしていた。MCP往復に合わせ、既存の`Diary.drain()`で保存完了を待ったうえで、保存回数・本文・保持数を引き続き検証するよう更新した。

回帰テストは使い捨てPostgreSQLを使用した。本番DB・Minecraftワールドは使用していない。ローカルのGit管理外レポートは`server/benchmark/data/service-boundaries-verified-20261110/`。

## 未実施・制約

実モデルでの選択精度・初動時間・共有GPU負荷の比較、実際の画像・歌・YouTubeによる運用確認、Minecraftの再測定、本番反映は未実施。既存ベンチマークの成績を今回のソースの成績とは扱わない。

今回の境界はSDKのメモリtransportを使う会話単位のサービス。資格情報・話者・保持中画像などの依存をネットワーク越しへ移す契約は追加していない。独立プロセス・共有MCPサーバーとして配備したという意味ではない。
