# シエル Live2D：お手本との差の原因分析と、作り直しの計画（2026-10-11）

対象：頭の向き（角度X×Y）の出来が、お手本 `assets/ciel/generated/pose-ref/`（25 向き）より大きく劣る件。
前提：一から作り直してよい（ユーザー指定）。最も品質が高くなる進め方を選ぶ。
関連：経緯は `ciel-live2d-production-spec-ja.md` 12.1〜12.46、過去の調査は `ciel-face-3d-research-ja.md`・`ciel-live2d-material-guidelines-research-ja.md`・`ciel-angle-y-research-ja.md`。

---

## 1. 結論

1. 出来が悪い主な原因は、**作り方の土台**にある。細かい調整の不足は主因ではない。頭のパーツ 20 枚以上を **1 つのワープデフォーマ（Head_Warp）にまとめ**、Cubism の外の Python で計算した楕円体の回転を格子に当てている。このため、前髪・横髪・顔・耳が**同じ曲面に貼り付いて**動き、視差（手前は大きく、奥は小さく動く）が出ない。Live2D 公式の手順（パーツごとにデフォーマを分ける）と逆の構造。
2. 素材は、**動かすための分け方**になっていない。前髪 1 枚、横髪は左右 1 枚ずつ。輪郭の線と塗りも分かれていない。お手本は向きごとに AI が描き直した絵なので、パーツに無い絵（顎の裏、首、奥の頬）が写っている。これに合わせようとして、症状ごとの継ぎ足し（Chin_Under・JawLine・Neck_Line など）が増えた。
3. Cubism の画面操作が不安定なため、**エディターを避けて XML を直接書き換える**方法に移った。その結果、リギングに欠かせない「目で見ながら制御点を直す」作業ができなくなった。Cubism に元からある「3D 回転表現の適用」「4 隅の自動生成」「グルー」「ブレンドシェイプ」も使っていない。
4. Web リサーチは、症状が出るたびに検索結果の要約を集める方式だった。「パーツごとにデフォーマを分ける」は 10/09 の調査で見つけていたが、実装に反映しなかった。**プロのモデルの実物（公式サンプルの .cmo3）を開いて構造を数える**調査はしていない。
5. 作り直しの方針：見本モデルを解析して設計を決める → 動かす前提でパーツを作り直す（Codex が、パーツごとに最大の画像サイズで生成）→ Cubism の標準構成（部位ごとのデフォーマ＋3D 回転表現）で組む → **画像で見ながら調整する仕組みを先に作り**、Claude が調整する（届かなければユーザーが Cubism で仕上げる）。評価は、目の位置の誤差ではなく、輪郭・髪の重なり・動画で見た印象で行う。

## 3. 見えている症状と、その直接の原因

ユーザーが示した上向き 30°（左30〜右30）の 5 枚と、25 向きの比較図（Unity の描画とお手本）から。

| 症状 | 直接の原因 |
| --- | --- |
| 横髪の大きな毛束が、頬・顎の上を斜めに横切る（左右 30°） | 横髪が顔と同じ Head_Warp の曲面にあり、顔の表面として回る。本来、横髪は顔の外側の、半径の大きい円柱の上にあって、奥側の毛束は顔の後ろへ回り込む |
| 顔の輪郭（特に奥側）が無く、顔と髪が白い一つの塊に見える | 輪郭線が独立したパーツでなく、向きごとの輪郭の形も作っていない。白い肌と白い髪の境は、線と描画順でしか見分けられない |
| 首が長い灰色の柱になり、顎の下が平らな台形に見える | 顔は上へ動くが、首・首輪は体側にあって動かない。空いた所を、顎の裏と首の継ぎ足しで埋めている。お手本は首と顎の明暗・形を描き直している |
| 奥の目が顔の外へ出る、または前髪に埋もれる | 目・前髪・顔が同じ曲面で動く。前髪が顔より手前で大きく動く、という視差が無い |
| 斜めの隅（例：右30×上30）が特に崩れる | X と Y の変形を 1 つの数式で作り、隅を目で直していない |
| 耳がカードのように平行移動するだけ | 耳を「深さ 290 の平面」として動かしている。付け根の回り込み、描画順の切り替えが無い |

お手本との比較図（作業用、Git 管理外）：Python で 5×5 の比較を作り、上向き・正面・下向きの 3 段と 2 段で見比べた。

## 4. 根本の原因

### R1. デフォーマの構造（最大の原因）
- 公式チュートリアル「XY の顔の動き」は、輪郭・左右の目・鼻・口・左右の眉・左右の耳・髪（前・左右・後ろ）を**それぞれ別のデフォーマ**にし、視差を出して立体的に変形させる、としている。作業の順は、角度X → 角度Y → 4 隅の自動生成 → 調整。
- 今のモデルは、デフォーマが Head_Warp 1 つだけ。外部の 3D 計算で「1 枚の曲面」を回しているため、パーツごとに奥行き（手前・奥）を変えられない。
- 10/09 の調査（`ciel-face-3d-research-ja.md` の表の 1）で、このことは見つけていた。しかし「形は 3D モデルで計算する」方針を優先し、構造を変えなかった。**調査と実装の対応を確かめる手順が無かった。**

### R2. 素材が「動かす前提」で設計されていない
- 髪の毛束の分け方が粗い（前髪 1 枚、横髪 1 枚ずつ）。束ごとに違う量・違う向きに動かせない。
- 顔の輪郭は、線と塗りを分けていない（後から `split-jaw-line.py` で顎の線だけを分けた）。
- 首は「口の高さまで大きめに描く」（公式の素材分けの指示）になっていなかった。後から継ぎ足した。
- 基準画像は低解像度の生成画像を 2 倍にしたもの。パーツは v2 → v4 → v5 と、AI で 3 回作り直した。毎回、線・色・形が少しずつ違う。
- **お手本の性質を取り違えた**：お手本は向きごとに AI が絵全体を描き直したもの（仕様書 12.21・12.29 に記載）。顎の裏・首の陰影・奥の頬の形など、パーツに無い絵が含まれる。変形だけでは届かない目標に、継ぎ足しで近づけようとした。お手本どうしでも、髪や耳の形が一致しない。

### R3. 作業環境：エディターを使わない作り方になった
- Cubism の画面操作（フォーカスが奪われる、入力が反映されない、画面が止まる）が不安定で、`.cmo3` の XML を直接書き換える方式に移った（12.23〜）。
- リギングは「制御点を動かし、パラメーターを動かして見る」を何百回も繰り返す作業。XML の書き換えと、数分かかる Unity での描画確認では、この反復が回らない。
- Cubism 5.1 以降の標準機能で代わりになるものを使っていない：
  - **3D 回転表現の適用**（アートメッシュ・ワープ・回転デフォーマに、3D で回した形を推定して、X・Y・4 隅のキーフォームを作る）。`head3d-keys.py` は、これを外で作り直したものに近い。
  - **4 隅の自動生成**、**グルー**（首と頭をつなぐ）、**ブレンドシェイプ**（特定の角度だけの補正）、**AI によるデフォーマの自動生成**。
- 10/10 の調査で「Cubism 5.1 に 3D 的な変形の補助機能がある。詳細は未確認」と書いたまま、確認しなかった。

### R4. 評価の物差しがずれていた
- 主な指標は「両目の中心の位置の誤差（px）」と「顎の下端の波（px）」。この数値は良くなった（13〜35 px 以内）が、見た目は良くならなかった。
- 測っていなかったこと：顔の輪郭（シルエット）の一致、髪と顔の重なり方、パーツ間の視差、中間の値での動き、動かしたときの印象。
- 静止画 25 枚だけで判定し、動画で見ていない。

### R5. 進め方：症状への対処の繰り返し
- 12.31〜12.46 の 16 節は、顎・首・頬・後ろ髪などの症状を一つずつ直した記録。直すたびに、別の所に新しい症状が出た（例：顎の裏を足す → 灰色の四角 → 首の柱 → 平らな面 → 凹の顎 → 斜めの帯）。
- 「どの向きで、何が、どう見えれば合格か」の設計が先に無かった。
- ±30° の目標が、1 枚の正面絵の変形で作れる範囲を超えていた。お手本の 30° はほぼ斜め 45° の顔で、顎の裏や奥の頬まで描き直している。

## 5. Web リサーチの手法の評価

### これまでの調べ方
- 症状が出るたびに、日本語の検索語で Web 検索し、ブログ・note・公式マニュアルの**検索結果の要約**から要点を拾った。
- 資料に「動画は全編を視聴していない」「【推奨】は一次資料で未確認」と書いてある。正直な記録だが、未確認のまま実装した。
- 調べた内容は、顎の線の消し方、首の影、頬の赤みなど、**部分的な技法**が中心。モデル全体の構造（デフォーマの木、パーツ数、動きの量）は調べていない。

### 問題点
| # | 問題 | 結果 |
| --- | --- | --- |
| 1 | 症状が出てから調べる（後追い） | 全体の設計を決めないまま、部分を直し続けた |
| 2 | 要約・ブログが中心で、一次資料（実物のモデル、公式マニュアル全文、動画）を見ていない | 「詳細は未確認」が残り、標準機能を見逃した |
| 3 | 見つけた原則を、実装と照らし合わせていない | 「デフォーマを分ける」を見つけても、構造を変えなかった |
| 4 | 数値（パーツ数・動きの量）を、プロのモデルから取っていない | パーツ数・分け方の目安が無いまま素材を作った |

### これからの調べ方
1. **実物のモデルを開いて数える（最優先）**：Live2D 公式サンプル（桃瀬ひより、マークくん など。`.cmo3` 付き。無料素材ライセンスと利用条件を確認する）を Cubism で開き、さらに既存の `caff.py`・`cmo3_tool.py` で XML を読み、次を表にする。アートメッシュの数と名前、デフォーマの木、各デフォーマの格子の分割数、角度X ±30 での各パーツの動きの量（頭の幅で割った比率）、描画順の切り替え、ブレンドシェイプの使い方。これが設計の一次資料になる。サンプルの絵やデータは、シエルの素材に流用しない（構造を調べるだけ）。
2. **公式マニュアルを、該当ページ全文で読む**：XY の顔の動き、3D 回転表現の適用（設定項目のページも）、4 隅の自動生成、グルー、ブレンドシェイプ、デフォーマの自動生成、素材分け。
3. **動画は人が見る**：公式の XY チュートリアル動画など、手の動きが要る資料は、ユーザーが見て要点を伝える。または文字起こしを読む。
4. **有料の手本も候補にする**：頭の角度の作り方を示す `.cmo3` と動画（cillia の頭角度ワークフロー例など）。
5. **AI のパーツ分けの最新研究を、下書き用として試す**：See-through（SIGGRAPH 2026、1 枚の絵を最大 23 層に分け、隠れた部分を補う。オープンソース）、Bunraku（2026 年 7 月、パーツ分けとキーの変位まで予測。コード公開は未確認）。どちらも作者が「そのままの Live2D 変換ではない」と書いている。下書きと比較の材料にとどめる。
6. **資料ごとに確度を書く**：「実物で確認」「公式」「ブログ」「推測」を分け、未確認のものは実装の前に確かめる。

## 6. 作り直しの方針

| 項目 | これまで | これから |
| --- | --- | --- |
| 設計の根拠 | 症状ごとの検索 | 公式サンプルの解析と、公式マニュアル |
| 素材 | 約 30 パーツ。髪の毛束が粗い。輪郭の線と塗りが一体 | 公式サンプルの解析で決めた分け方（目安 80〜150 メッシュ）。髪は毛束ごと。輪郭の線を独立。首は口の高さまで |
| 素材の作り方 | 部位ごとに AI で別々に生成。基準画像は 2 倍に拡大したもの | **設計原画**（配置と見た目の基準）を決め、Codex がパーツごとに**最大の画像サイズ**で生成し、組み立てる。全パーツを**同じ縮尺（1 px あたりの大きさ）**で生成し、線の太さをそろえる。拡大した画素は最終の絵に使わない。分解図と重ね直しで検査 |
| 構造 | Head_Warp 1 つ＋外部の 3D 計算 | 体 → 首（頭とグルー）→ 頭の回転（角度Z）→ 頭の XY のワープ → 部位ごとのワープ（輪郭・目 L/R・眉 L/R・鼻・口・耳 L/R・前髪・横髪 L/R・後ろ髪・頭頂・アホ毛） |
| 角度X・Y の形 | Python の楕円体で全キーを計算 | Cubism の「3D 回転表現の適用」で下地を作り、部位ごとに奥行き（前髪は手前、耳・後ろ髪は奥）を変える。4 隅の自動生成のあと、目で見て直す |
| 細部の調整 | XML の書き換え。確認は Unity で数分 | Claude が調整する。そのために、**部位ごとのデフォーマを正確に再現する高速プレビュー**（数秒で 25 向きの一覧と、動かした動画）を先に作り、Unity の描画と一致することを確かめる。Cubism の画面は、取り込み・3D 回転表現の適用・4 隅の自動生成・アトラス・書き出しなど、少数の操作にだけ使う。採点表で合格に届かない項目は、ユーザーが Cubism で仕上げる |
| 目標の範囲 | お手本の ±30°（顎の裏まで描き直した絵） | 段階を分ける。第 1 段階は、お手本の ±15° 相当の見え方を、パラメーターの最大（±30）に当てる。第 2 段階で、追加の描き分け素材を使って大きな角度へ広げる |
| 評価 | 目の中心の誤差 | 輪郭のシルエット、髪の重なり、視差、中間値、**動画**。人の目での採点表を合否の基準にし、数値は補助 |

## 8. 作業計画

各段階の「次へ進む条件」を満たしてから進む。各段階の終わりにユーザーが確認する。

### 段階 1：手本の解析と、リグの設計書（1〜2 日）
1. **公式サンプルの入手（ユーザー）**：桃瀬ひより（Cubism 3.0 の標準モデル、`.cmo3` と物理演算つき）を、Live2D 公式のサンプルページから、利用条件（無料素材ライセンス・サンプルデータ利用規約）に同意してダウンロードし、`.local/reference-rigs/` に置く。**利用規約により再配布できないので、Git には入れない**（公開リポジトリのため）。
2. **解析（Claude）**：`caff.py`・`cmo3_tool.py` で XML を読み、Cubism でも開いて、次を表にする。アートメッシュの数と名前、デフォーマの木と格子の分割数、角度X・Y ±30 での各パーツの動きの量（頭の幅との比）、描画順の切り替え、物理演算の入出力、パーツごとのメッシュの細かさ。サンプルの絵・データはシエルに流用しない。
3. **公式マニュアルの通読（Claude）**：XY の顔の動き、3D 回転表現の適用と設定項目、4 隅の自動生成、グルー、ブレンドシェイプ、デフォーマの自動生成、素材分け。
4. **リグの設計書**：`docs/ciel-live2d-rig-design-ja.md`。パーツの一覧（生成の単位・重なり順・隠れる側の描き足し）、デフォーマの木、角度ごとの動きの量の目安、描画順の切り替え、第 2 段階で足す描き分け素材の候補。
- **次へ進む条件**：ユーザーが設計書を確認した。

### 段階 2：生成の条件を確かめる（1 日）
Codex の生成で、品質を左右する条件を、本番の前に小さく試して確かめる。
- 現在の最大の画像サイズと、選べる縦横比（過去の記録は 1254×1254。変わっている可能性がある）。
- 透明の背景で出せるか。出せない場合の背景色と、切り抜きの方法。
- 同じ縮尺の参照画像を渡したとき、線の太さ・色・肌の色がどこまでそろうか（同じパーツを 3 回生成して比べる）。
- **縮尺の決定**：頭（耳先〜顎）が 1 回の生成に収まる大きさを基準の縮尺にする。例：最大が 1254 px なら、頭の高さ約 1150 px。上半身全体の作業キャンバスは、この縮尺で決める（例：約 2400×3200）。長いパーツ（後ろ髪・横髪の毛先・服）は、同じ縮尺のまま、重なりを持たせた区画に分けて生成する。
- **次へ進む条件**：縮尺・キャンバス・生成の手順（`scripts/codex/` の依頼の型）を決め、設計書に書いた。

### 段階 3：設計原画とパーツ（4〜7 日）
1. **設計原画**：正面の上半身を Codex で生成し、ユーザーが確定する。リギングしやすい絵にする（毛束がはっきり分かれる、輪郭の線が明確、首が見える）。これは配置と見た目の基準で、最終の画素には使わない（作業キャンバスへは拡大して下敷きにするだけ）。
2. **パーツの生成**：設計書の一覧の順（下のパーツから）に、作業キャンバスの縮尺で、設計原画の該当範囲を下敷き・参照として渡し、パーツ単独の絵を生成する。完成済みの隣のパーツ（重なる部分）も参照に渡し、線と色をそろえる。
3. **組み立て**：スクリプトで、生成したパーツを作業キャンバスへ位置合わせして配置する（拡大縮小は小さな補正だけ）。
4. **隠れる部分の描き足し**：前髪・横髪の下の額と頬（輪郭の外まで）、首（口の高さまで）、耳の付け根、頭の裏の後ろ髪、口の中。第 2 段階の描き分け素材（奥の頬、顎の裏など）の候補も、この段階で同じ縮尺で作っておく。
5. **検査**：分解図、黒・白・灰の背景での縁、線の太さ（パーツ間で ±20% 以内）、肌・髪の色の差、各パーツを ±20px・±5° 動かしたときの隙間、重ね直しと設計原画の見た目。
6. 目（開・半・閉）・口（閉・小・大）・眉も、新しい原画に合わせて作り直す。
- **次へ進む条件**：重ね直した絵が、設計原画と同じキャラクターに見え、継ぎ目が見えない。ユーザーが分解図と重ね直しを確認した。

### 段階 4：調整の道具（2〜3 日、段階 3 と並行できる）
Claude が目で見て調整できるようにする道具。品質を決める段階 6 の前提。
1. **正確なプレビュー**：`.cmo3` を読み、デフォーマの木（ワープの入れ子、回転デフォーマ）、キーフォームの補間（X×Y の格子）、描画順、不透明度を、Cubism と同じ計算で描く。いまの `preview-pose.py`（Head_Warp だけの近似）を作り直す。
2. **Unity との一致の確認**：同じ向きで、プレビューと Unity（`CielRenderCheck`）の描画の差を測り、見た目で区別できない程度にそろえる。
3. **出力**：25 向きの一覧（お手本と並べる）、X・Y を連続で動かした動画（GIF）、輪郭だけ・髪だけなどの部分表示。
- **次へ進む条件**：既存のモデルの描画で、プレビューと Unity が一致する。

### 段階 5：構造と下地の動き（2〜3 日）
1. PSD を取り込み、メッシュを作る（自動生成のあと、目・口・輪郭は手で直す）。
2. デフォーマの木を作る（6 章）。名前・親子・格子の分割数は設計書どおり（スクリプトで作ってよい）。
3. 「3D 回転表現の適用」で、部位ごとに角度X・Y の下地を作る。前髪・横髪・耳・後ろ髪は、奥行き（回転の中心からの距離）を変える。Cubism の画面の操作が続かない場合は、同じ考え方の計算をスクリプトで、部位ごとのデフォーマに当てる。
4. 4 隅の自動生成。
- **次へ進む条件**：25 向きで破綻せず、髪と顔が別の量で動く（視差が見える）。

### 段階 6：仕上げ（5〜10 日。品質を決める段階）
Claude が、段階 4 のプレビューで見ながら、部位ごとに調整する。1 回の調整は「直す項目を 1 つ決める → 数値・制御点を変える → 25 向きと動画で確かめる」。
- 輪郭：向きごとの形（奥は細く、手前は広く。顎の形）。輪郭だけを表示して合わせる。
- 髪：奥側の横髪を顔の後ろへ回す。前髪は顔より大きく、後ろ髪は小さく動かす。耳・横髪の描画順を ±30 付近で切り替える。
- 上向きの顎・首：輪郭の線の不透明度、首と頭のグルー、必要ならブレンドシェイプ。
- 目・鼻・口：奥の目を細く。鼻は向きに合わせて位置と形を変える。
- 採点表（9 章）で、全 25 向きの点を記録する。**同じ項目で 3 回直しても点が上がらない場合は、その項目をユーザーへ渡す**（直す内容と、見るべき向きを書いた手順を付ける）。
- **次へ進む条件**：採点表で、全 25 向きが合格点。X・Y を連続で動かした動画に、跳ねや折れが無い。ユーザーが動画を確認した。

### 段階 7：表情・物理・組み込み（3〜5 日）
- まばたき・口・眉・4 表情、呼吸・体の傾き、髪と耳の物理演算。
- 書き出して Unity で確認（`CielRenderCheck`）。

### 第 2 段階（後で）
大きな角度（お手本の ±30° 相当）を、追加の描き分け素材（奥の頬、顎の裏、横向きの鼻など）と、角度ごとの差し替えで作る。

### PRO 版の期限
トライアルは 11/19 前後に切れる。段階 1〜4 は、トライアルの機能がなくても進められる。段階 5 以降（取り込み・アトラス・書き出し）は、期限までに終えるか、購入する。テクスチャが 4096px 1 枚に収まらない場合（パーツの解像度を上げるため、その可能性がある）も PRO 版が要る。段階 3 の終わりに、テクスチャの量を見積もって判断する。

## 8.1 再計画：1 枚の絵から上のパーツを順に剥がす（2026-10-11）

**経緯**：パーツを 1 枚ずつ別々に生成して組み立てる方式（v6、`generated/v6/parts/`）を試した。パーツ単体の絵の質は高かったが、組み立てると顔の土台が約 80px ずれ、ファーと上着が肩でつながらず、横髪の形も別物になり、一枚の絵に見えなかった。原因は、別々に生成したパーツは形を毎回描き直すので互いに合わないこと（位置合わせは位置・大きさ・回転しか直せない）。Claude がパーツごとの線のずれの数値だけで「ほぼ基準どおり」と報告したのは誤りで、4 章の R4（測りやすい数値だけを見る）の繰り返しだった。

**方針**（ユーザー了承）：
1. 元の絵は、承認済みの基準画像（`master/ciel-upper-body-2x.png`、2172×2896）。解像度を上げる工程は、パーツ分けと分けて別に行う。
2. 上のパーツから順に、Codex に「そのパーツを消して、下を描いた絵」を作らせる（前髪 → 横髪 → …）。消した絵は元の絵とほとんど同じなので、変わっていない部分全体で位置を合わせる。
3. 見えるパーツは、元の絵の画素（元の絵と消した絵の差の範囲）。生成した画素は、動いたときにだけ見える下の描き足しにだけ使う。正面の見た目は元の絵と一致する。
4. 分ける数は、動きが違う所だけ（前髪、横髪 L/R、後ろ髪、頭頂、犬耳 L/R、アホ毛、顔の土台、目、眉、口、首、首輪の前・後ろ、体、上着とファー L/R）。
5. 評価は、重ね直した全体と元の絵を並べた見た目（違いを書き出す）と、全体の画素の差。パーツごとの数値だけで合格にしない。
- v6 の個別パーツは、下の描き足しの参考として残す。
- AI の自動パーツ分け（See-through）は同じ考え方だが、このPCの GPU（RTX 2060）では動かない見込み。必要ならクラウドで試す。

## 9. 評価の採点表（案）

25 向きと、X・Y を連続で動かした動画について、各項目を 0〜2 点で付ける（2＝お手本と同等、1＝違いはあるが自然、0＝破綻）。

| # | 項目 |
| --- | --- |
| 1 | 顔の輪郭：奥側が細く、手前側が広い。顎の形が向きに合う |
| 2 | 視差：前髪・横髪が顔より大きく、後ろ髪・耳が小さく動く |
| 3 | 髪の重なり：奥側の横髪が顔の後ろへ回る。毛束が顔を横切らない |
| 4 | 目：奥の目が細く、顔からはみ出さない。前髪との重なりが自然 |
| 5 | 首・顎：上向きで、顎の裏と首が自然につながる。首が不自然に伸びない |
| 6 | 耳：付け根が頭から離れない。向きに応じて描画順が切り替わる |
| 7 | 継ぎ目：下のパーツの剥き出し、隙間、切れ端が無い |
| 8 | 動き：中間の値で、跳ね・折れ・波打ちが無い |

数値の検査（目の位置、シルエットの重なり率、UV の範囲）は、回帰の確認に使い、合否は採点表で決める。

## 10. 今の素材・道具で残すもの

| 残す | 理由 |
| --- | --- |
| 目・口の作り方（開・半・閉、閉・小・大の差し替えとキー） | 仕組みは新しいモデルでも使う。絵は新しい原画に合わせて作り直す（段階 3） |
| `caff.py`・`cmo3_tool.py` | 公式サンプルの解析、描画順・不透明度の一括設定、検査に使う |
| `CielRenderCheck.cs`・`compare-pose.py` | Unity での確認と比較 |
| お手本（`pose-ref/`） | 見た目の方向性の参考。形の正解としては使わない |

使わなくなるもの（削除は段階 5 で新しい構造が動いてから）：`head3d-keys.py` を中心とした 25 キーの計算、`chin-under-keys.py`・`rekey-head-followers.py`・`hair-back-follow.py`・`fit-jaw-curve.py`・`measure-jaw-wave.py` などの症状への対処、`Chin_Under`・`Face_JawLine`・`Neck_Line` の継ぎ足し。
