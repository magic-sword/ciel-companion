# シエル Live2D：お手本との差の原因分析と、作り直しの計画（2026-10-11）

対象：頭の向き（角度X×Y）の出来が、お手本 `assets/ciel/generated/pose-ref/`（25 向き）より大きく劣る件。
前提：一から作り直してよい（ユーザー指定）。最も品質が高くなる進め方を選ぶ。
関連：手本の解析 `ciel-live2d-reference-rig-analysis-ja.md`、リグの設計 `ciel-live2d-rig-design-ja.md`、Codex への相談の結果 `ciel-codex-consult-parts-ja.md`。古い方式の経緯は Git の履歴（2026-10-11 以前の `ciel-live2d-production-spec-ja.md` 12 章）。
**現在の方針・手順・進み具合は 6〜8 章。** 1〜5 章は、作り直しを決めたときの分析（そこで触れる古いファイル・節は、Git のタグ `archive/pre-v9-cleanup` で参照できる）。

---

## 1. 結論

1. 出来が悪い主な原因は、**作り方の土台**にある。細かい調整の不足は主因ではない。頭のパーツ 20 枚以上を **1 つのワープデフォーマ（Head_Warp）にまとめ**、Cubism の外の Python で計算した楕円体の回転を格子に当てている。このため、前髪・横髪・顔・耳が**同じ曲面に貼り付いて**動き、視差（手前は大きく、奥は小さく動く）が出ない。Live2D 公式の手順（パーツごとにデフォーマを分ける）と逆の構造。
2. 素材は、**動かすための分け方**になっていない。前髪 1 枚、横髪は左右 1 枚ずつ。輪郭の線と塗りも分かれていない。お手本は向きごとに AI が描き直した絵なので、パーツに無い絵（顎の裏、首、奥の頬）が写っている。これに合わせようとして、症状ごとの継ぎ足し（Chin_Under・JawLine・Neck_Line など）が増えた。
3. Cubism の画面操作が不安定なため、**エディターを避けて XML を直接書き換える**方法に移った。その結果、リギングに欠かせない「目で見ながら制御点を直す」作業ができなくなった。Cubism に元からある「3D 回転表現の適用」「4 隅の自動生成」「グルー」「ブレンドシェイプ」も使っていない。
4. Web リサーチは、症状が出るたびに検索結果の要約を集める方式だった。「パーツごとにデフォーマを分ける」は 10/09 の調査で見つけていたが、実装に反映しなかった。**プロのモデルの実物（公式サンプルの .cmo3）を開いて構造を数える**調査はしていない。
5. 作り直しの方針：見本モデルを解析して設計を決める → 動かす前提でパーツを作り直す → Cubism の標準構成（部位ごとのデフォーマ）で組む。評価は、目の位置の誤差ではなく、自然さ・かわいさ・動きで行う。素材の作り方と役割分担は、試行の結果で改めた（現在の方針は 6 章）。

## 3. 見えている症状と、その直接の原因

ユーザーが示した上向き 30°（左30〜右30）の 5 枚と、25 向きの比較図（Unity の描画とお手本）から。

| 症状 | 直接の原因 |
| --- | --- |
| 横髪の大きな毛束が、頬・顎の上を斜めに横切る（左右 30°） | 横髪が顔と同じ Head_Warp の曲面にあり、顔の表面として回る。本来、横髪は顔の外側の、半径の大きい円柱の上にあって、奥側の毛束は顔の後ろへ回り込む |
| 顔の輪郭（特に奥側）が無く、顔と髪が白い一つの塊に見える | 輪郭線が独立したパーツでなく、向きごとの輪郭の形も作っていない。白い肌と白い髪の境は、線と描画順でしか見分けられない |
| 首が長い灰色の柱になり、顎の下が平らな台形に見える | 顔は上へ動くが、首・首輪は体側にあって動かない。空いた所を、顎の裏と首の継ぎ足しで埋めている。お手本は首と顎の明暗・形を描き直している |
| 奥の目が顔の外へ出る、または前髪に埋もれる | 目・前髪・顔が同じ曲面で動く。前髪が顔より手前で大きく動く、という視差が無い |
| 斜めの隅（例：右30×上30）が特に崩れる | X と Y の変形を 1 つの数式で作り、隅を目で直していない |
| 耳がカードのように平行移動するだけ | 耳を「深さ 290 の平面」として動かしている。付け根の回り込み、描画順の切り替えが無い |

お手本との比較図（作業用、Git 管理外）：Python で 5×5 の比較を作り、上向き・正面・下向きの 3 段と 2 段で見比べた。

## 4. 根本の原因

### R1. デフォーマの構造（最大の原因）
- 公式チュートリアル「XY の顔の動き」は、輪郭・左右の目・鼻・口・左右の眉・左右の耳・髪（前・左右・後ろ）を**それぞれ別のデフォーマ**にし、視差を出して立体的に変形させる、としている。作業の順は、角度X → 角度Y → 4 隅の自動生成 → 調整。
- 今のモデルは、デフォーマが Head_Warp 1 つだけ。外部の 3D 計算で「1 枚の曲面」を回しているため、パーツごとに奥行き（手前・奥）を変えられない。
- 10/09 の調査（`ciel-face-3d-research-ja.md` の表の 1）で、このことは見つけていた。しかし「形は 3D モデルで計算する」方針を優先し、構造を変えなかった。**調査と実装の対応を確かめる手順が無かった。**

### R2. 素材が「動かす前提」で設計されていない
- 髪の毛束の分け方が粗い（前髪 1 枚、横髪 1 枚ずつ）。束ごとに違う量・違う向きに動かせない。
- 顔の輪郭は、線と塗りを分けていない（後から `split-jaw-line.py` で顎の線だけを分けた）。
- 首は「口の高さまで大きめに描く」（公式の素材分けの指示）になっていなかった。後から継ぎ足した。
- 基準画像は低解像度の生成画像を 2 倍にしたもの。パーツは v2 → v4 → v5 と、AI で 3 回作り直した。毎回、線・色・形が少しずつ違う。
- **お手本の性質を取り違えた**：お手本は向きごとに AI が絵全体を描き直したもの（仕様書 12.21・12.29 に記載）。顎の裏・首の陰影・奥の頬の形など、パーツに無い絵が含まれる。変形だけでは届かない目標に、継ぎ足しで近づけようとした。お手本どうしでも、髪や耳の形が一致しない。

### R3. 作業環境：エディターを使わない作り方になった
- Cubism の画面操作（フォーカスが奪われる、入力が反映されない、画面が止まる）が不安定で、`.cmo3` の XML を直接書き換える方式に移った（12.23〜）。
- リギングは「制御点を動かし、パラメーターを動かして見る」を何百回も繰り返す作業。XML の書き換えと、数分かかる Unity での描画確認では、この反復が回らない。
- Cubism 5.1 以降の標準機能で代わりになるものを使っていない：
  - **3D 回転表現の適用**（アートメッシュ・ワープ・回転デフォーマに、3D で回した形を推定して、X・Y・4 隅のキーフォームを作る）。`head3d-keys.py` は、これを外で作り直したものに近い。
  - **4 隅の自動生成**、**グルー**（首と頭をつなぐ）、**ブレンドシェイプ**（特定の角度だけの補正）、**AI によるデフォーマの自動生成**。
- 10/10 の調査で「Cubism 5.1 に 3D 的な変形の補助機能がある。詳細は未確認」と書いたまま、確認しなかった。

### R4. 評価の物差しがずれていた
- 主な指標は「両目の中心の位置の誤差（px）」と「顎の下端の波（px）」。この数値は良くなった（13〜35 px 以内）が、見た目は良くならなかった。
- 測っていなかったこと：顔の輪郭（シルエット）の一致、髪と顔の重なり方、パーツ間の視差、中間の値での動き、動かしたときの印象。
- 静止画 25 枚だけで判定し、動画で見ていない。

### R5. 進め方：症状への対処の繰り返し
- 12.31〜12.46 の 16 節は、顎・首・頬・後ろ髪などの症状を一つずつ直した記録。直すたびに、別の所に新しい症状が出た（例：顎の裏を足す → 灰色の四角 → 首の柱 → 平らな面 → 凹の顎 → 斜めの帯）。
- 「どの向きで、何が、どう見えれば合格か」の設計が先に無かった。
- ±30° の目標が、1 枚の正面絵の変形で作れる範囲を超えていた。お手本の 30° はほぼ斜め 45° の顔で、顎の裏や奥の頬まで描き直している。

## 5. Web リサーチの手法の評価

### これまでの調べ方
- 症状が出るたびに、日本語の検索語で Web 検索し、ブログ・note・公式マニュアルの**検索結果の要約**から要点を拾った。
- 資料に「動画は全編を視聴していない」「【推奨】は一次資料で未確認」と書いてある。正直な記録だが、未確認のまま実装した。
- 調べた内容は、顎の線の消し方、首の影、頬の赤みなど、**部分的な技法**が中心。モデル全体の構造（デフォーマの木、パーツ数、動きの量）は調べていない。

### 問題点
| # | 問題 | 結果 |
| --- | --- | --- |
| 1 | 症状が出てから調べる（後追い） | 全体の設計を決めないまま、部分を直し続けた |
| 2 | 要約・ブログが中心で、一次資料（実物のモデル、公式マニュアル全文、動画）を見ていない | 「詳細は未確認」が残り、標準機能を見逃した |
| 3 | 見つけた原則を、実装と照らし合わせていない | 「デフォーマを分ける」を見つけても、構造を変えなかった |
| 4 | 数値（パーツ数・動きの量）を、プロのモデルから取っていない | パーツ数・分け方の目安が無いまま素材を作った |

### これからの調べ方
1. **実物のモデルを開いて数える（最優先）**：Live2D 公式サンプル（桃瀬ひより、マークくん など。`.cmo3` 付き。無料素材ライセンスと利用条件を確認する）を Cubism で開き、さらに既存の `caff.py`・`cmo3_tool.py` で XML を読み、次を表にする。アートメッシュの数と名前、デフォーマの木、各デフォーマの格子の分割数、角度X ±30 での各パーツの動きの量（頭の幅で割った比率）、描画順の切り替え、ブレンドシェイプの使い方。これが設計の一次資料になる。サンプルの絵やデータは、シエルの素材に流用しない（構造を調べるだけ）。
2. **公式マニュアルを、該当ページ全文で読む**：XY の顔の動き、3D 回転表現の適用（設定項目のページも）、4 隅の自動生成、グルー、ブレンドシェイプ、デフォーマの自動生成、素材分け。
3. **動画は人が見る**：公式の XY チュートリアル動画など、手の動きが要る資料は、ユーザーが見て要点を伝える。または文字起こしを読む。
4. **有料の手本も候補にする**：頭の角度の作り方を示す `.cmo3` と動画（cillia の頭角度ワークフロー例など）。
5. **AI のパーツ分けの最新研究を、下書き用として試す**：See-through（SIGGRAPH 2026、1 枚の絵を最大 23 層に分け、隠れた部分を補う。オープンソース）、Bunraku（2026 年 7 月、パーツ分けとキーの変位まで予測。コード公開は未確認）。どちらも作者が「そのままの Live2D 変換ではない」と書いている。下書きと比較の材料にとどめる。
6. **資料ごとに確度を書く**：「実物で確認」「公式」「ブログ」「推測」を分け、未確認のものは実装の前に確かめる。

## 6. 現在の方針（2026-10-11 時点）

1 章〜5 章の分析のあと、素材の作り方を 3 回試して改めた（7 章）。現在の方針は次のとおり。

| 項目 | 方針 |
| --- | --- |
| 目標 | 組み合わせても、動かしても、**自然でかわいい** Live2D。元の絵と画素単位で一致させることは目標にしない（ユーザー決定） |
| 見た目の基準 | 承認済みの基準画像 `assets/ciel/master/ciel-upper-body-2x.png`（2172×2896） |
| 素材 | **Codex が、生成から組み立て・位置と大きさの調整・陰影・確認図まで一続きで担当する**。パーツは参照（基準画像、対象の枠、採用済みの隣のパーツを置いた合成）を渡して描かせ、組み合わせた見た目で採否を決める。補正は配置の記録（`placement.json`）に残す |
| リグ | Claude Code が担当。公式サンプルと同じ構成（顔の回転の下に部位ごとのワープを並べる）で組み、動きの量はサンプルの実測から始める（`ciel-live2d-reference-rig-analysis-ja.md`、`ciel-live2d-rig-design-ja.md`） |
| 判断 | ユーザーが区切りで判断する：A 顔の印象、B 動いた顔、C 会話画面 |
| 角度 | パラメーターの ±30 は、見た目で 15〜20° 程度。大きな角度は、必要になってから描き分けの素材を足す |
| Cubism | PRO 版トライアル（10/08 開始、11/19 前後まで）。必要なら購入を検討する（ユーザー） |

パーツの分け方・重なり順・影の所属・目と口の層、Codex への依頼で避ける指示は、`ciel-codex-consult-parts-ja.md` の 2 章・3 章と、`assets/ciel/generated/v9/layer-contract.md` に従う。

## 7. これまでの試行と教訓

| 版 | 方式 | 結果 | 教訓 |
| --- | --- | --- | --- |
| v5 以前 | 1 枚の絵を粗く切り分け、外部の 3D 計算で 1 つのワープを動かす | 1〜5 章のとおり | 部位ごとのデフォーマと、動かす前提の素材が要る |
| v6 | パーツを 1 枚ずつ枠いっぱいで別々に生成し、線の位置で合わせて組み立てる | 単体はきれいだが、パーツどうしの形が合わず一枚の絵に見えない | 別々に描いたパーツは互いに合わない。位置合わせは形の違いを直せない |
| v7 | 基準画像から上のパーツを順に「消した絵」と「塗りつぶした絵」を作り、塗った範囲を元の絵から切り抜く | 正面は元の絵とほぼ同じ。縁がぎざぎざ、隠れた部分が粗い | 画素の一致を目標にすると、縁と描き足しの質が落ちる |
| v8 | パーツの周りの枠を参照に、Codex がパーツ単体を同じ枠で描き、枠の座標で戻す | 縁はきれいだが、組み合わせると不自然（ユーザー評価） | Claude の指示（横髪を顔の外へ、前髪を目の上で止める）が髪型を変えた。枠で戻すだけで、見た目の調整をしなかった。首の影が消えた |
| v9 | 生成から組み立て・調整までを Codex が一続きで担当 | **ユーザー確認 A で承認**（「見違えるほど改善」） | 生成して組み上げて見る担い手が、直接直すのがよい |

Claude Code は、この経過で見た目の評価を 3 回甘く報告した（v6、v7 の途中、v8）。見た目の判断は、組み上げた図を元の絵と並べ、違いを具体的に書き出してから行う。数値（線のずれ、画素の差）だけで良いと判断しない。

## 9. 評価の見方

合否は、元の絵との画素の差ではなく、自然さ・かわいさ・動きで判断する。数値（目の位置、重なり、UV の範囲）は、回帰の確認にだけ使う。

| 観点 | 合格の見方 |
| --- | --- |
| 顔の印象 | 目が印象の中心で、額・頬の露出と髪の流れが承認した顔を保つ |
| 髪と顔 | 頬への意図した被りを保つ。向きを変えても、鼻・反対の目へ束が滑り込まない。毛束の間に穴が出ない |
| 視差 | 前髪・目・鼻・口が顔より手前の量で、後ろ髪・外側の横髪は小さく（または逆に）動く |
| 首と飾り | 顎から首輪まで立体感がある。上向きで白や灰の柱にならない。首輪の飾りと胸の宝石が接触しない |
| 目・口 | 閉じた状態で中身が漏れない。途中で二重線や色の帯が出ない。会話中も同じ顔に見える |
| 耳・頭頂 | 根元が離れない。頭頂の丸みが二重に盛り上がらない |
| 連続性 | パラメーターの途中で輪郭・描画順・陰影が跳ねない。表情の後に基準へ戻る |
| 実表示 | 実機の背景とサイズで、縁・細い線・クリッピングに問題がなく、目と口が読める |
