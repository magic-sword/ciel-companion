# 関連性で思い出す記憶の設計（採用前）

> 責務：長期記憶・短期記憶を関連性で検索し、会話とゲームの出来事を結び付けて思い出す仕組みの設計案と、評価・移行段階・採用条件。

この資料は採用前の設計案と、`feature/associative-memory`ブランチでの実装状況です。2026-11-20に開発用の会話サーバーへ配布しました（共有DBに表を作り、索引づくりが動くことを確認）。mainと本番には入っていません。今の記憶の契約は[共有記憶](shared-memory-ja.md)と[人を覚える機能](people-memory-ja.md)、ゲームの拠点は[Minecraftのシステム設計](../games/minecraft/minecraft-design-ja.md)が正本です。この案の各段階を採用したら、それぞれの正本を同じ変更で改めます。

## なぜ組み直すか

シエルが自分から話すには、今の会話に関係する記憶を思い出す必要があります。たとえば、休む話になったときに以前作った拠点を思い出し、「あの拠点で休みましょうか」と言えることを目指します。

今の記憶は、関連性で探す作りになっていません。

| 記憶 | 置き場所 | 会話への渡し方 | 足りないこと |
|---|---|---|---|
| 人のメモ | `person_notes`（1人50件・120字まで） | ひとり・身近な人のとき、本人と分かったら新しい15件を発言に添える。人前では添えない。全件は道具`recall_about_speaker`で読む | 検索がない。16件目より古いメモは、モデルが道具を呼ばないと届かない。上限を超えると古いものから消える |
| シエルの日記 | `ciel_events`（200件まで） | 会話には渡さない。好みを育てる処理だけが新しい40件を読む | 会話で出来事を思い出せない |
| 好み | `ciel_likes` | 全件を指示に入れる | 検索がない |
| 拠点 | ゲーム側。ワールドごとのファイルに1つ（`base.js`） | 会話側からは見えない | いつ・誰と・何のために作ったかがない |
| 名前を付けた場所 | ゲーム側の`MemoryBank`（名前と座標。死亡地点など） | 体のLLMだけが使う | 座標だけで、意味がない |
| ゲームの思い出 | 日記に、倒した・倒れたことだけ | 日記と同じ | 家を建てた・拠点を作ったことが残らない |

PostgreSQLには`vector`拡張がすでに入っています（声の特徴の`voiceprints`で使用）。新しいデータベースを足さずに、ベクトル検索を使えます。

## 採用する考え方

参考：[Proactive Conversational Agents with Inner Thoughts](https://arxiv.org/abs/2501.00383)（CHI 2025）、[Generative Agents](https://arxiv.org/abs/2304.03442)、[LongMemEval](https://arxiv.org/abs/2410.10813)、[A-Mem](https://arxiv.org/abs/2502.12110)、[Zep](https://arxiv.org/abs/2501.13956)、[Mr.Steve](https://arxiv.org/abs/2411.06736)。

1. **保存するときに、使い道の鍵を付ける。** 「休もう」と「拠点」は、文のままでは意味が近いとは限りません。拠点の記憶には「休める・寝られる・安全・帰る場所」のような使い道・言い換えを鍵として付け、本文と一緒に埋め込みます。検索の方式より、記憶の書き方のほうが効きます。
2. **検索するときに、今の関心を言い換える。** 発言そのものに加えて、決定ループが書く短い「今の関心」（例：休む場所、夜を安全に過ごす）でも探し、近いほうを関連度にします。
3. **関連度だけで選ばない。** 関連度・新しさ・重要度を掛け合わせて選びます。時間・人・ワールド・公開範囲は、普通の条件で絞ります。
4. **ゲームの事実の正本はゲーム側に置く。** 会話側の記憶は、何をした場所かという意味の文と参照IDだけを持ちます。座標・設備・今もあるかは、思い出した後にゲームへ問い合わせます。
5. **古くなった事実は消さずに無効にする。** 拠点が壊れた・引っ越したときは、無効になった時刻を付けます。「前はあそこに拠点があった」と話せるようにします。
6. **思い出したことはすぐ話さない。** 思い出したことは考えのたまり場へ入れ、話題とタイミングが合ったときに話します。話すかどうかは[状態機械の設計案](../conversation/agent-state-machine-ja.md)の一つの決定で選びます。

## 記憶の形

シエル自身の記憶（日記・ゲームの場所と出来事）は新しい表`memories`に、人のメモは今の`person_notes`のまま、索引だけを別の表`note_index`に置きます（実装は`server/agent/speaker_store.py`）。

| 列 | 内容 |
|---|---|
| `kind` | `diary`（日記）・`game_place`（拠点・家など行ける場所）・`game_event`（ゲームの大きな出来事） |
| `tag` | 日記の種類（`song`・`touch`・`minecraft`など。`ciel_events.kind`と同じ） |
| `text` | 思い出の1文（例：マイクラで拠点を決めた（作業台・チェストのそば）） |
| `keys` | 思い出すきっかけの言葉（使い道・言い換え・関係する話題）。保存のあとでLLMが書く。NULLはまだ書いていない |
| `embedding`・`embedding_model`・`embedded_text` | 本文と鍵の埋め込み、そのモデル名、埋め込んだ文。モデルや文が変われば埋め込み直す |
| `importance` | 重要度（1〜5）。日記は3、場所は4 |
| `occurred_at`・`last_recalled_at`・`recall_count` | 新しさと、思い出した回数 |
| `world`・`ref` | ゲームのワールドの識別と、ゲーム側の場所の参照（例：`minecraft:<ワールド>/base/<座標>`）。座標の正本は体が持つ |
| `invalidated_at` | 場所が無くなった時刻。消さずに「前は」として残す |
| `source`・`source_id` | 元の記録（`ciel_events`の行） |

- **日記：** `ciel_events`は好みを育てる材料として今のまま残し（200件）、同じ出来事を`memories`にも書きます（消さない）。起動時に、まだ写していない`ciel_events`を写します。
- **好み：** 件数が少なく全件を指示に入れているので、思い出す候補にはしません。
- **人のメモ：** 表を移すと、保存同意・版番号・忘却の仕組みを作り直すことになるため、`note_index`（鍵・埋め込み）を足すだけにしました。メモの表を書き換えると版番号が進み、書き込み中のメモの整理が捨てられるので、索引は別の表にしています。メモが消えれば索引も消え、メモが書き直されれば鍵と埋め込みを作り直します。
- **本人確認・同意：** 人のメモを候補にするのは、声で確かに本人と分かり、保存に同意していて、忘れる依頼の処理中でも保存情報の確認不能でもなく、ひとり・身近な人のときだけです（`SpeakerBook.recall_person`と`recall.eligible`）。LLMに任意の人物IDやSQLを渡しません。
- **鍵を書くときの送り先：** 鍵は、メモを書く係と同じ役目（`notes`）のモデルへ、記憶の本文を送って書かせます。人のメモの本文も、メモを書くときと同じ送り先へ送ります。
- **ほかの人の話：** ほかの人の個人情報や固有名詞を、本人の記憶として残さない今の規則を維持します。

## ゲームと記憶の結び付け

- **ワールドの識別：** 体が、体のデータ（`CIEL_BODY_DATA`、拠点の記録と同じ所）にサーバーごとの識別を作って残し、様子（`game://state`の`world`）に入れます。ワールドを作り直すと体のデータも退避されるので、新しいワールドには新しい識別が付きます。会話側は`<ゲーム>:<識別>`として記憶に付け、今のワールドの記憶だけを候補にします。
- **ゲームが出す出来事：** 拠点を決めた（`!setBase`）、家を建て終えた（`!buildHouse`が完成した）ときに、体の出来事として`memorable`（`{text, kind, ref, importance}`の並び）を送ります。話すきっかけにはせず、記憶に残すだけです。倒した・倒れたは今までどおり文だけの日記です。
- **無くなった場所：** 別の場所で拠点を決め直すと、前の拠点を`place_lost`として送り、前の拠点の記憶に`invalidated_at`を付けます。思い出したときは「…。でも、その場所は今はもう無い」として渡します（かっこ書きは返事に注釈を書き出させやすいため使わない）。
- **まだ作っていないこと：** 思い出したあとにゲームへ参照を問い合わせて、今もあるか・どれくらい遠いかを確かめる処理。壊れた拠点・家に気づく処理。村を見つけたなど、拠点と家以外の場所。「あの拠点へ行こう」で参照から行き先を決める処理。

## 検索

`recall.Recall.for_turn`が、返事を作るたびに候補を読み、上位3件までを選びます（`recall.rank`）。

```
関連度 × 新しさ（30日でおよそ半分、下限0.6） × 重要度
関連度 = 次の大きいほう：埋め込みの近さ・文字の重なり・日付の一致
```

- **文字の重なり：** 漢字1字と、カタカナ・英数字の2字組で比べます。ひらがなの2字組は、活用（「休もう」と「休む」）で重ならないので使いません。どの話にも出る漢字（今・日・前など）は外します。
- **日付の一致：** 「きのう」「おととい」「先週」「3日前」のように日を指す問いでは、その日の記憶を関係があるとみなします（LongMemEvalの時間を考えた問いの広げ方）。
- **埋め込み：** 既定は`cl-nagoya/ruri-v3-30m`（CPU、256次元）。sentence-transformersが入っていなければ、文字の重なりと日付だけで思い出します。関係のない文どうしでも近さが0.6前後になるため、0.65より上を0〜1に引き直します（`CIEL_RECALL_COSINE_FLOOR`）。
- **しきい値：** 関連度0.35未満の記憶は添えません。関係のない雑談に記憶を押し込まないためです。
- **繰り返し：** 5分以内に添えた記憶は点を半分にし、同じ記憶を続けて添えにくくします。
- **時間の上限：** 0.8秒（`CIEL_RECALL_TIMEOUT`）を超えたら、その返事には添えません。
- **つながり：** グラフのデータベースや記憶どうしのリンクの表は使っていません。

## システム1とシステム2の分担

Inner Thoughtsは、すぐ自動で返すシステム1と、文脈を深く考えるシステム2を分けます。シエルでは、返事を作る口（`mind.build`から会話モデル）がシステム1、会話の裏で「今のまとめ」を書く心（`mind_brief`）がシステム2に当たります。思い出しの仕事ごとに、かかる時間と質から置き場所を決めます。数字は[実行時間の実測](../testing/capability-results-ja.md#想起の実行時間)です。

| 仕事 | 置き場所 | かかる時間 | 理由 |
|---|---|---|---|
| 問いの埋め込み・候補の読み出し・順位付け | システム1 | 記憶100件で約8ms、1000件で約45ms、5000件で約200ms | LLMを使わない連想。返事の始まり（約0.1〜1.3秒）より十分短い |
| 日付で範囲を決める問い（「きのう何したっけ」） | システム1 | 上と同じ | 決まった計算で、取り違えがない |
| 強く当たった記憶を返事の補足に添える | システム1 | 1件約26トークン。3件で読み込み約0.2秒 | 休む話に拠点を8/10、夜ごはんに辛い物が苦手を9/10で使えた |
| 今の拠点があるか | どちらでもない（ゲームの様子） | ゲームの状態の読み取り | マイクラの様子に今の拠点の1行（座標・距離・残っている設備と無くなった設備）を出す。休む話では、これだけで拠点を10/10で提案できた |
| 候補が本当に今の話に合うかの見極め・「思ったこと」 | システム2 | 考えない設定で1回約1.1〜1.8秒（共有GPUが空いているとき）。全部ローカルの会話の中では中央値4.5秒・最大8.5秒。考える設定で約62秒 | 返事の始まりに間に合わない。検索の下限（0.35）より広い候補（0.2以上）から拾い、夜ごはんの話で検索だけでは届かなかった「辛い物が苦手」を届けた |
| 無くなった物 | システム1 | 検索と同じ | 心に見せると、壊れた拠点を今の拠点と取り違えた（5/5）。心には見せず、検索が「今はもう無い」と書いて添える |
| 話さなかった考えをためて、自分から話す番に使う | システム2 | 上と同じ | 次の発言や沈黙で使えば、待ち時間にならない |
| 鍵と埋め込みを書く | システム2（会話の裏） | 12件で鍵は数秒、埋め込みは約20ms | 返事と関係なく、会話の裏で進める |
| 振り返り・重要度の見直し・忘れ方 | システム2（会話の終わり） | 未測定 | 会話中に急ぐ理由がない |

- **長期記憶をシステム1にいつも足すか：** 足すのは、検索で強く当たった上位3件までにします。全部を足すと読み込みが記憶の数に比例して増え、関係の薄い記憶も持ち込みます。上位3件までなら、話し始めの遅れは約0.2秒で、使う割合が上がりました。
- **システム2の呼び方（`recall.MindRecall`）：** 2秒ごとに会話の記録を見て、まだ見極めていない相手の発言か出来事があれば、検索の広い候補（関連度0.2以上・8件まで、無くなった物を除く）と最近の8発言、今のゲームの様子を心（`brief`の役目のモデル、`prompts/recall_mind.md`）へ渡します。候補が無ければ心を呼びません。ローカルでは、シエルも相手も話していない状態が3秒続いてから送り、途中で話し始めたら取り消して次の静かな間にやり直します（`inference_activity`。同時に動くと返事の始まりが中央値で約0.1秒、まれに約1.6秒遅れたため）。
- **結果の渡し方：** 選んだ記憶（3件まで）と思ったこと1文を、次の返事の補足に1回だけ足します。検索の上位3件と同じ記憶は重ねません。思ったことは`[心に浮かんだこと]`（`prompts/thought_note.md`、使い方は`prompts/mind.md`の1行）として渡します。公開範囲・本人・ワールドが変わった、5分を超えた、相手の発言が3つ以上進んだ結果は捨てます。
- **考える設定：** 1回約62秒かかり、会話の中では使いません。
- **全部ローカルで間に合う条件：** 静かになって3秒待ってから送り、1回に約4.5秒かかるので、次の発言まで約8秒以上空いたときだけ次の返事に間に合います。間3秒の会話では一度も完了しませんでした（[再測定](../testing/capability-results-ja.md#全部ローカルでの再測定)）。返事の声までの時間は、心があってもなくても同じでした。
- **大きくなったとき：** 今は返事のたびに全候補をDBから読みます。5000件で読み出しが約156msになるので、1000件を超えたら、会話サーバーの中に候補を持つか、DBで近いものだけを読むようにします。
- **まだ作っていないこと：** 心の思ったことを、沈黙が続いたときに自分から話すきっかけにすること（今は次の返事で使うだけ）。`mind_brief`の`thoughts`への受け渡し。

## 短期記憶

| 部品 | 中身 |
|---|---|
| 会話履歴 | 今のまま |
| 問い | 今回の相手の発言。自分から話す番など相手の発言が無いときは、最後の発言か出来事 |
| 思い出したこと | 上位3件まで。今回の返事の補足（`[思い出したこと]`、見出しは`prompts/recall_note.md`。使い方は固定の指示`prompts/mind.md`の1行）に足し、送信済みの前半を変えない |

- **自分から話す番：** 出来事を受けて話す番も、同じ返事の組み立て（`agent.py`の`_pipeline_llm`）を通るので、最後の出来事や発言から思い出したことが届きます。続けて話すか待つかを決める指示（`prompts/continuation.md`）に、思い出したことが今の話や様子に合うときは、それをきっかけに話したり提案したりしてよいと書きました。
- **まだ作っていないこと：** 決定ループが書く「今の関心」で探すこと、話さなかった考えをためておく場所。どちらもシステム2に置きます（[分担](#システム1とシステム2の分担)）。

## 会話の終わりのまとめ

今は作っていません。鍵は会話の裏で書きます（`recall.Indexer`。鍵か埋め込みがまだの記憶・メモを、新しいものから12件ずつ）。振り返り（上位の考え）、重要度の見直し、思い出した回数による忘れ方は、思い出す量が増えてから検討します。

## 評価

検索の層の課題・指標・実行方法は[記憶の想起の評価](../testing/memory-recall-benchmark-ja.md)、結果は[実測](../testing/capability-results-ja.md#記憶の想起の基準値)にあります。採点の設計には[ciel-benchmark-progress](../../../agent-skills/skills/ciel-benchmark-progress/SKILL.md)を使います。

| 場面 | 正解 |
|---|---|
| 休む話になった。以前作った拠点がある | 拠点の記憶が上位に入る。今もあることを確かめてから話す |
| 拠点が壊れた後に、休む話になった | 「前はあそこにあった」と扱い、今あるとは言わない |
| 数日前の会話で聞いた予定の話 | その日付の記憶が上位に入る |
| 人前で、本人の個人的なメモに関係する話題 | 候補に入らない |
| 覚えていないこと | 作り話をせず、覚えていないと言える |

- **指標：** 正しい記憶が上位k件に入る割合、出してはいけない記憶が入った数、思い出したことを話した割合と、その自然さ、検索の遅延。
- **観点：** LongMemEvalの5つの能力（取り出し、複数回の会話にまたがる推論、時間、事実の更新、知らないと答えること）に合わせて課題を分けます。
- **出典：** 実際の会話ログから作るときも、生の発言・個人のメモはGitへ入れません。

## 移行の段階と採用条件

| 段階 | 内容 | 採用条件 | 状況 |
|---|---|---|---|
| 0 | 想起の課題と評価器を作り、今の方式の基準値を取る | 基準値が取れる | 2026-11-20に検索の層で取得（届いた割合0.167） |
| 1 | 記憶の表・埋め込み・組み合わせ検索を作り、日記を写す | 想起の課題で今の方式を上回る。会話の話し始めまでの時間が延びない | 実装済み。鍵と埋め込み（ruri-v3-30m）で1.000、漏れ0。使い捨てのPostgreSQLで結合試験が通り、開発用の会話サーバーで表の作成と索引づくりを確認。声の会話での話し始めまでの時間は未確認（LiveKitの上限） |
| 2 | 人のメモを索引に入れ、思い出す候補にする | 本人確認・同意・版番号・忘却・公開範囲の回帰がすべて通る | 実装済み。unitの回帰と、DBの結合試験（同意のない人のメモを索引にしない・書き直しで索引を作り直す）が通過 |
| 3 | ゲームの覚えるべき出来事と参照ID、存在の確認をつなぐ | 拠点の場面で正しく思い出し、無くなった拠点を今あると言わない | 拠点・家・ワールドの識別・決め直した拠点の無効化、マイクラの様子への今の拠点の1行を実装。実ワールドは未確認（体は本番の1つだけで、ブランチを入れていない） |
| 4 | 思い出したことを、自分から話すことにつなぐ | 自発会話の[比較仕様](../testing/continuation-benchmark-ja.md)で、関係のある自発発話が増え、繰り返しが増えない | 補足と自発判断の指示、心が見極めるシステム2（`MindRecall`）を実装。返事の層で、休む話に拠点を10/10、夜ごはんに辛い物が苦手を10/10（検索だけでは0/10）で使った。自発会話の比較は未実施 |

## 決まっていないこと

- 埋め込みモデル（ruri-v3-30mと、より大きい版の比較）と、声の会話でのCPUの遅延。しきい値は16課題で据え置いた（[結果](../testing/capability-results-ja.md#鍵と埋め込みを使う場合)）。
- 思い出したあとにゲームへ存在を問い合わせる方法と、その時間。
- 返事の層：自然さを人が聞いた評価。心の思ったことを、自分から話すきっかけにするか。
- 振り返りで作った考えを、本人の記憶と同じ同意の範囲で扱う方法。
