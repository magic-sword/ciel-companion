# 関連性で思い出す記憶の設計（採用前）

> 責務：長期記憶・短期記憶を関連性で検索し、会話とゲームの出来事を結び付けて思い出す仕組みの設計案と、評価・移行段階・採用条件。

この資料は採用前の設計案です。今の記憶の契約は[共有記憶](shared-memory-ja.md)と[人を覚える機能](people-memory-ja.md)、ゲームの拠点は[Minecraftのシステム設計](../games/minecraft/minecraft-design-ja.md)が正本です。この案の各段階を採用したら、それぞれの正本を同じ変更で改めます。

## なぜ組み直すか

シエルが自分から話すには、今の会話に関係する記憶を思い出す必要があります。たとえば、休む話になったときに以前作った拠点を思い出し、「あの拠点で休みましょうか」と言えることを目指します。

今の記憶は、関連性で探す作りになっていません。

| 記憶 | 置き場所 | 会話への渡し方 | 足りないこと |
|---|---|---|---|
| 人のメモ | `person_notes`（1人50件・120字まで） | ひとり・身近な人のとき、本人と分かったら新しい15件を発言に添える。人前では添えない。全件は道具`recall_about_speaker`で読む | 検索がない。16件目より古いメモは、モデルが道具を呼ばないと届かない。上限を超えると古いものから消える |
| シエルの日記 | `ciel_events`（200件まで） | 会話には渡さない。好みを育てる処理だけが新しい40件を読む | 会話で出来事を思い出せない |
| 好み | `ciel_likes` | 全件を指示に入れる | 検索がない |
| 拠点 | ゲーム側。ワールドごとのファイルに1つ（`base.js`） | 会話側からは見えない | いつ・誰と・何のために作ったかがない |
| 名前を付けた場所 | ゲーム側の`MemoryBank`（名前と座標。死亡地点など） | 体のLLMだけが使う | 座標だけで、意味がない |
| ゲームの思い出 | 日記に、倒した・倒れたことだけ | 日記と同じ | 家を建てた・拠点を作ったことが残らない |

PostgreSQLには`vector`拡張がすでに入っています（声の特徴の`voiceprints`で使用）。新しいデータベースを足さずに、ベクトル検索を使えます。

## 採用する考え方

参考：[Proactive Conversational Agents with Inner Thoughts](https://arxiv.org/abs/2501.00383)（CHI 2025）、[Generative Agents](https://arxiv.org/abs/2304.03442)、[LongMemEval](https://arxiv.org/abs/2410.10813)、[A-Mem](https://arxiv.org/abs/2502.12110)、[Zep](https://arxiv.org/abs/2501.13956)、[Mr.Steve](https://arxiv.org/abs/2411.06736)。

1. **保存するときに、使い道の鍵を付ける。** 「休もう」と「拠点」は、文のままでは意味が近いとは限りません。拠点の記憶には「休める・寝られる・安全・帰る場所」のような使い道・言い換えを鍵として付け、本文と一緒に埋め込みます。検索の方式より、記憶の書き方のほうが効きます。
2. **検索するときに、今の関心を言い換える。** 発言そのものに加えて、決定ループが書く短い「今の関心」（例：休む場所、夜を安全に過ごす）でも探し、近いほうを関連度にします。
3. **関連度だけで選ばない。** 関連度・新しさ・重要度を掛け合わせて選びます。時間・人・ワールド・公開範囲は、普通の条件で絞ります。
4. **ゲームの事実の正本はゲーム側に置く。** 会話側の記憶は、何をした場所かという意味の文と参照IDだけを持ちます。座標・設備・今もあるかは、思い出した後にゲームへ問い合わせます。
5. **古くなった事実は消さずに無効にする。** 拠点が壊れた・引っ越したときは、無効になった時刻を付けます。「前はあそこに拠点があった」と話せるようにします。
6. **思い出したことはすぐ話さない。** 思い出したことは考えのたまり場へ入れ、話題とタイミングが合ったときに話します。話すかどうかは[状態機械の設計案](../conversation/agent-state-machine-ja.md)の一つの決定で選びます。

## 記憶の形

日記・人のメモ・場所の思い出を、共通の記憶の表にまとめます。

| 列 | 内容 |
|---|---|
| `kind` | 出来事・人について・場所・好み・シエル自身 |
| `text` | 思い出の1文（例：ハカセと森の横に拠点を作った） |
| `keys` | 使い道・言い換え・タグ。保存するときにLLMが付ける |
| `embedding` | `text`と`keys`のベクトル |
| `importance` | 重要度。保存時に付け、会話の終わりのまとめで見直す |
| `occurred_at`・`last_recalled_at`・`recall_count` | 新しさと、思い出した回数 |
| `people` | 誰の話か。人のメモは今の人物IDに結ぶ |
| `scope`・`privacy` | 本番・開発の印と、人前で出してよいか |
| `invalidated_at` | 事実が古くなった時刻。消さずに残す |
| `ref` | 外部の正本への参照（例：Minecraftのワールドと拠点のID） |

- **本人確認・同意：** 人のメモは今と同じく、保存同意・確かな本人・版番号・忘却の規則に従います。表を変えても、LLMに任意の人物IDやSQLを渡しません。
- **公開範囲：** 人前の会話では、個人のメモを思い出す候補に入れません（[人を覚える機能](people-memory-ja.md)の「その場にいる人」と同じ扱い）。
- **ほかの人の話：** ほかの人の個人情報や固有名詞を、本人の記憶として残さない今の規則を維持します。

## ゲームと記憶の結び付け

- **ゲームが出す出来事：** 今の倒した・倒れたに加えて、拠点を作った、家が完成した、ベッドを置いた、村を見つけたなど、覚えるべき出来事を参照ID付きで知らせます。選ぶのはゲーム側の決まった処理で、LLMは使いません。
- **会話側で残すもの：** 出来事を思い出の1文と鍵にして、`ref`と一緒に保存します。座標の数字は記憶に書き写しません。
- **思い出した後：** ゲームのMCPで`ref`を引き、今もあるか・どれくらい遠いかを確かめてから話します。無くなっていたら`invalidated_at`を付けます。
- **向かうとき：** 「あの拠点へ行こう」は、決定が参照IDを選び、座標はゲームが結び付けます（[指示棒と目線](../games/minecraft/minecraft-design-ja.md#指示棒と目線による対象指定)と同じ考え方）。

## 検索

1回のSQLで、次の値を組み合わせて上位数件を選びます。

```
関連度（ベクトルの近さと語の一致の大きいほう） × 新しさの減衰 × 重要度
```

- **語の一致：** 地名・名前など、埋め込みでは拾いにくい固有の言葉のために使います。
- **条件：** 今のワールド、その場にいる人、公開範囲、無効になっていないこと（または「前は」の話として扱うこと）。
- **つながり：** 最初はグラフのデータベースを使いません。同じ出来事・人・場所でつながる記憶が必要になったら、記憶どうしのリンクの表を足します。
- **埋め込みモデル：** 共有GPU APIには埋め込みの口がありません。CPUで動く日本語対応の小さな埋め込みモデルを候補にして、想起の精度と遅延を比べてから決めます。

## 短期記憶

| 部品 | 中身 |
|---|---|
| 会話履歴 | 今のまま |
| 今の関心 | 決定ループが短く書く。検索の問いに使う |
| 思い出したこと | 検索の上位数件。会話の末尾へ補足として足し、送信済みの前半を変えない |
| 考えのたまり場 | まだ話していない考えと思い出したこと。今の継続メモを広げて使い、別のモデルは増やさない |

- **検索するとき：** 話題が変わったとき、ゲームの出来事で起きたとき、沈黙が続いたとき。時間がたっただけでは、同じ状況で探し直しません。
- **重さ：** 埋め込み1回とSQL1回です。会話の推論枠を取りません。

## 会話の終わりのまとめ

今のメモの統合（`notes.py`）を広げます。

- **鍵と重要度：** 出来事に鍵と重要度を付けます。
- **重複：** 同じ出来事・事実をまとめます。
- **振り返り：** 複数の出来事から、上位の考え（例：ハカセは夜になると拠点へ戻りたがる）を作ります。
- **忘れ方：** 日記の「200件を超えたら古い順に消す」をやめ、重要度と思い出した回数が低いものから忘れます。

## 評価

採用前に、想起の課題を作って今の方式の基準値を取ります。検索の層の課題・指標・実行方法は[記憶の想起の評価](../testing/memory-recall-benchmark-ja.md)、基準値は[実測](../testing/capability-results-ja.md#記憶の想起の基準値)にあります。採点の設計には[ciel-benchmark-progress](../../../agent-skills/skills/ciel-benchmark-progress/SKILL.md)を使います。

| 場面 | 正解 |
|---|---|
| 休む話になった。以前作った拠点がある | 拠点の記憶が上位に入る。今もあることを確かめてから話す |
| 拠点が壊れた後に、休む話になった | 「前はあそこにあった」と扱い、今あるとは言わない |
| 数日前の会話で聞いた予定の話 | その日付の記憶が上位に入る |
| 人前で、本人の個人的なメモに関係する話題 | 候補に入らない |
| 覚えていないこと | 作り話をせず、覚えていないと言える |

- **指標：** 正しい記憶が上位k件に入る割合、出してはいけない記憶が入った数、思い出したことを話した割合と、その自然さ、検索の遅延。
- **観点：** LongMemEvalの5つの能力（取り出し、複数回の会話にまたがる推論、時間、事実の更新、知らないと答えること）に合わせて課題を分けます。
- **出典：** 実際の会話ログから作るときも、生の発言・個人のメモはGitへ入れません。

## 移行の段階と採用条件

| 段階 | 内容 | 採用条件 |
|---|---|---|
| 0 | 想起の課題と評価器を作り、今の方式の基準値を取る | 基準値が取れる（2026-11-20に検索の層で取得。届くべき記憶が会話モデルの前に置かれた割合0.167。返答の層は未測定） |
| 1 | 記憶の表・埋め込み・組み合わせ検索を作り、日記・好みを移す | 想起の課題で今の方式を上回る。会話の話し始めまでの時間が延びない |
| 2 | 人のメモを移す | 本人確認・同意・版番号・忘却・公開範囲の回帰がすべて通る |
| 3 | ゲームの覚えるべき出来事と参照ID、存在の確認をつなぐ | 拠点の場面で正しく思い出し、無くなった拠点を今あると言わない |
| 4 | 思い出したことを考えのたまり場へ流し、自分から話すことにつなぐ | 自発会話の[比較仕様](../testing/continuation-benchmark-ja.md)で、関係のある自発発話が増え、繰り返しが増えない |

## 決まっていないこと

- 埋め込みモデルの種類と、CPUでの遅延。
- 鍵を付けるのを、出来事ごとに行うか、会話の終わりにまとめて行うか。
- 人のメモを共通の表へ移すか、今の表に埋め込みの列を足すだけにするか。
- 記憶どうしのリンクの表が要るかどうか。段階1の結果で決めます。
- 振り返りで作った考えを、本人の記憶と同じ同意の範囲で扱う方法。
