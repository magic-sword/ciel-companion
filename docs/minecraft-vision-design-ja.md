# シエルの目から見る（マイクラ・設計）

> **2026-11-07 から：** 会話サーバーとのつなぎ方を、MCP の「ゲームの環境」に変えた（[ゲームとアプリを環境としてつなぐ設計](game-environment-mcp-design-ja.md)）。この文書の `minecraft.py`・`tools/minecraft.py`・`config/prompts/minecraft.md`・WebSocket の決まりは、そのときまでの形。今は、体の MCP の入口（`server/minecraft/src/ciel/`）がシエル向けの言葉・道具・遊び方の指示を持ち、会話サーバーは `game_env.py` でつなぐ。

状態：作った（2026-11-06）。試作で A を確かめ、体に組み込んだ。前提は [マインクラフトで遊ぶ設計](minecraft-design-ja.md)（体）と [シエルに画像を見せる設計](vision-design-ja.md)（目の係）。

## 1. 何をするか

マイクラの中のシエルの体（Mineflayer のボット）が今いる場所から見た景色を絵にして、シエルが自分の目で見たものとして話せるようにする。今の「[マイクラの様子]」（体力・近くのブロックの数・近くの敵）は数と名前だけなので、「洞窟の入り口が見えます」「夕焼けがきれい」のような話はできない。

## 2. 絵の作り方（調べたこと）

ボットは画面を持たない。Mineflayer が知っている周りのブロックとエンティティから、3D の絵を描く部品が要る。

| 方法 | しくみ | 良いところ | 気になるところ |
|---|---|---|---|
| **A. prismarine-viewer の Web の視点 ＋ 画面の無いブラウザ（Chromium）** | 体の中で prismarine-viewer の一人称の Web の視点を開き、同じコンテナの画面の無い Chromium で開いて、頼まれたときに 1 枚撮る | ブラウザの WebGL（SwiftShader）で描くので、GPU も特別な部品も要らない。prismarine-viewer の本来の使い方 | Chromium の分、コンテナが大きくなる（数百 MB）。1 枚撮るのに 1〜数秒 |
| B. prismarine-viewer の headless（node-canvas-webgl） | Node の中で WebGL を使って描く（例は動画を書き出す） | ブラウザが要らない | node-canvas-webgl は 2023 年から更新が無く、Node 22 で入るか分からない。描くための部品（headless-gl）のビルドで詰まりやすい |
| C. 文字だけ（見えている方向のブロックを調べる） | 向いている方向へ視線を飛ばし、見えるブロック・敵を文にする | 軽い。料金もほぼ増えない | 景色としては見えない |

- prismarine-viewer は 1.21.4 までの絵（テクスチャ）を持ち、1.21.11 はいちばん近い 1.21.4 の絵で描く（README）。1.21.5 以降に足されたブロックは、正しく描けないことがある。
- **おすすめは A**。まず自宅サーバーで、1.21.11 の世界を描けるか・1 枚撮るのに何秒かかるかを試す（試作）。だめなら C で「見えている物の文」にする。

## 3. 形

```
体（server/minecraft/src/eye.js）：prismarine-viewer の一人称の視点のページを 127.0.0.1:3007 だけで開き、
                                  画面の無い Chromium（Playwright の headless shell）で開いたままにする
                                  「look」の命令 → そのときの 1 コマを JPEG（768×480）で返す（seen。向いている方角も）
会話サーバー：道具 look_at_view → minecraft.py の Body.look → 目の係（eyes.py）の see_minecraft
            → 道具の返事の続きで、心が「[わたしの目に見えている景色]」の絵を見て話す。説明文は「[わたしの目で見た景色（マイクラ）]」
```

- **待ち受け**：prismarine-viewer の mineflayer() は全部のアドレスで待ち受けるので使わず、同じ中身を eye.js で 127.0.0.1 に開く（体は host のネットワークで動くので、全部のアドレスで開くと外から見える）。
- **開いたまま**：見るたびに開き直さず、ページを開いたまま景色の変化を受け取り続ける。初めの 1 枚は描き終えるまで 8 秒待つ。向き・場所が変わったら 1.5 秒待つ。10 分見なければ閉じる。マイクラから出たら閉じる。
- **撮らないあいだは描かない**：描き続けると、画面の無い Chromium がソフトウェア（SwiftShader）で描くので、CPU を 17 コア分ほど使った。ページを凍らせても下がらなかった。ページの描画の合図（requestAnimationFrame）だけを止めると 0.1 コア分ほどになり、景色の変化の受け取りは続く。撮るときは合図を戻して 1 秒描いてから撮る（2 枚目からは 2 秒ほど）。
- **大きさ**：体のイメージは 0.8 GB から 1.7 GB になった（Chromium と、それが使うライブラリ）。目を開いているあいだのメモリーは 2 GB ほど。
- **いつ見るか**：頼まれたときだけ（「何が見える？」「周りを見て」で、心が look_at_view を呼ぶ）。ふだんの返事のたびには撮らない。数と名前だけの look_around（配信のコメントからも使える）は残し、絵を撮る look_at_view はコメントからは使わない（1 枚 0.3 円ほど）。
- 心が自分から見たくなったとき（「わあ、きれいな景色」のように）は、あとで考える（数分に 1 回まで、など）。
- **目の係**：絵に出どころ（source：見せてもらった画像 shown・マイクラの景色 minecraft）を持たせ、出どころごとに直近 3 枚を持つ。景色を何枚見ても、見せてもらった画像は押し出されない。新しい景色が来たら、前の景色はもう添えない。
- **見え方の限り**：prismarine-viewer は 1.21.4 までの絵で描くので、1.21.11 の草花などの小さなブロックは変な箱や紫色になることがある。空は単色。気にせず地形・木・水などを話すよう、config/prompts/minecraft.md に書いた。
- 人に見せる絵ではないので、保存しない。

## 4. 進め方

1. 試作（済み）：自宅サーバーで A を動かした。1.21.11 の世界の地形・水・木・山がきちんと描けた。初めの 1 枚は 9 秒ほど、向きを変えたあとは 2 秒ほど、その場でもう 1 枚は 0.6 秒。体の Node のメモリーは 340 MB ほど。
2. 体に「look」の命令（JPEG を返す）を足した（済み）。
3. 会話サーバー：look_at_view で絵を撮って、目の係に渡す（済み）。
4. 声で「何が見える？」と聞いて試す。

## 5. あとで：画面共有へ広げる

API への「画面共有」も、中身は映像から 1 コマずつ取った画像を送るしくみ（LiveKit Agents の映像入力は、話している間は 1 秒に 1 枚・ほかは 3 秒に 1 枚を 1024×1024 の JPEG にして送る。Realtime のモデル専用）。今の目の係は 1 枚ずつの絵を出どころつきで受けるので、同じ入口で広げられる。

| 広げ方 | しくみ |
|---|---|
| ① シエルの目を映像にする | 体の中で開いたままのページを、LiveKit の映像として部屋へ流す。アプリや配信で「シエル視点」を見せられる |
| ② 持ち主の画面を共有する | アプリが画面を LiveKit の映像として流し、会話サーバーが最新の 1 コマを持っておき、頼まれたとき・話の切れ目に目の係へ渡す |

- 今の組み立て（pipeline）は LiveKit の映像入力を使えないので、映像の受け取りと「いつ 1 コマ取るか」を自分たちで持つ。料金を抑えるため、ずっと送らず、頼まれたとき・数秒に 1 枚・画面が大きく変わったときに絞る（1 秒 1 枚だと 1 分で十数円ほど）。
- ① は描き続けるので CPU が重くなる。流すのは見ている人がいるときだけにする。② は Unity の LiveKit の部品で PC の画面を流せるかをまだ確かめていない。だめなら、アプリが数秒に 1 回撮って「画像を見せる」で送る。
