# 目的の係（長い目的をやり遂げる仕組み・設計）

状態：6 章の 1 を作った（2026-11-07）。見える化（goal.state を送る所まで。アプリと配信の画面の札はまだ）・心が分ける目的・会話をまたぐ置き場は、まだ。調べたことは [長い目的をやり遂げる仕組み（調べたこと）](long-horizon-planning-research-ja.md)。前提は [ゲームの知識の窓口](game-knowledge-design-ja.md)・[マインクラフトで遊ぶ設計](minecraft-design-ja.md)・[会話の組み立て（pipeline）の仕組み](conversation-pipeline-ja.md)。

## 1. 何をするか

「石のつるはしを作る」のような、いくつもの段がある目的を、シエルが最後までやり遂げられるようにする。目的・計画・今の段を 1 つの形で持ち、アプリと配信の画面に見せる。マイクラだけでなく、あとで足すゲームでも同じ仕組みで動くようにする。

### 決めたこと（ユーザーと）

- 長い目的は、心（LLM 1 回の返事）が毎回一から決めるのではなく、心の外の決まった流れ（ワークフロー）で回す：**分ける（計画）→ 1 つずつやる → 結果で確かめる → だめなら理由を見て計画し直す**。
- 心の自発は残す。目的を始めるのは、持ち主の頼みでも、シエル自身の思いつきでもよい。この係は「始めた目的を取りこぼさない」ためのもの。
- 今の目的・進行中の段・計画を、アプリと配信の画面に見える化する。視聴者にも見える。ゲームを問わない作りにする。
- Google ADK 2.0 はそのまま入れない。会話サーバーは LiveKit の pipeline なので、ADK のグラフの考え方（節・分岐・やり直し・人に聞いて止まる・再開）を借りて、小さな流れを自分で書く。

## 2. 形

```
持ち主「石のつるはしを作って」／シエル自身の思いつき
   │  心：道具 start_goal（目的の言葉と、ゲーム）
   ▼
目的の係（会話サーバー goals.py。ゲームを知らない）
   ├ 計画：ゲームの係（adapter）に「この目的の段」を聞く ─────┐
   ├ 実行：今の段を 1 つだけ、ゲームの係に頼む                 │ ゲームの係（ゲームごと。マイクラは minecraft.py）
   ├ 確かめる：ゲームの係に「この段はできたか」を聞く          │   体（技・様子）と知識の窓口（facts・search）を使う
   ├ 計画し直す：決まった直し方 → 無ければ心に相談 → 持ち主に聞く ┘
   ├ 知らせ：心へ（区切りだけ）、アプリと配信へ goal.state（いつも）
   └ 置き場：今の目的は付箋（board）の 1 枚。中身は DB（会話をまたいで続ける）
```

### 2.1 目的と段の形（goal.state。ゲームを問わない）

```jsonc
{
  "v": 1, "type": "goal.state",
  "goal": {
    "id": 12, "game": "minecraft", "game_label": "マイクラ",
    "title": "石のつるはしを作る",          // 見せる言葉（日本語）
    "by": "owner",                          // owner（持ち主の頼み）・ciel（シエルの思いつき）
    "status": "running",                    // planning・running・paused（持ち主に聞いている）・done・failed・stopped
    "why": "鉄を掘りに行くため"              // あれば（心が書く）
  },
  "steps": [
    {"id": 1, "label": "原木を集める", "target": {"item": "oak_log", "count": 3}, "progress": [3, 3], "status": "done"},
    {"id": 2, "label": "木のつるはしを作る", "status": "done"},
    {"id": 3, "label": "丸石を集める", "progress": [1, 3], "status": "running"},
    {"id": 4, "label": "石のつるはしを作る", "status": "todo"}
  ],
  "changes": [ {"at": "…", "text": "原木が足りなかったので、集める段を足した"} ],   // 直近 3 つ
  "next": ["鉄を掘りに行く"],                                                       // あとでやる目的
  "attention": null                         // 持ち主に聞いていること（paused のとき）
}
```

- `label` はゲームの係が日本語で作る（マイクラの名前は英語の ID しか無いので、よく使う物の日本語の呼び名を表で持ち、無ければ英語の表示名）。
- `status`（段）：todo・running・done・failed・skipped。進み具合 `progress` は、数で確かめられる段だけ。

### 2.2 ゲームの係（adapter）の決まり

ゲームごとに、会話サーバーの中に 1 つ置く（マイクラは `minecraft.py` の Body に足す）。目的の係はこれだけを使う。

| 呼ぶこと | 中身 |
|---|---|
| `plan(goal_text, hint)` | 目的を段の一覧にする。決まった計画で分かれば（作る目的）それを、分からなければ `None`（心が分ける。3.2） |
| `run(step)` | 段を 1 つ、体の技で始める。終わりは知らせで返す（今の体の done と同じ） |
| `check(step)` | できたか（持ち物の数・場所など、体の様子で）。`progress` も返す |
| `repair(step, failure)` | 決まった直し方で、前に足す段（無ければ `None`） |
| `label(...)` | 見せる言葉 |

**マイクラの係**（はじめに作る段の種類）：

| 段 | 頼む技 | できたか |
|---|---|---|
| `gather {item, count}` | collect（呼び名・落ちる物から決める） | 持ち物の item が、始めたときより count 増えた |
| `craft {item, count}` | craft | 持ち物に item が count ある |
| `find {item}` | 探す技（掘り下げる・探し歩く。体に足す） | 見えるブロックに入った |
| `go {to}` | go_to・come | 着いた |
| `mind {text}` | 心に任せる（係では決められない段） | 心が `finish_step` で知らせる |

- `plan` は体の側で決める（作り方の木 `planCraft` は体にある。持ち物と近くの作業台も体が知っている）。体の命令に `plan {id, goal: {kind: 'make', item, count}}` を足し、`planned {steps}` で返す。知識の窓口の facts とも同じ部品なので、答えが食い違わない。
- `repair`（決まった直し方）：
  - `missing_materials`（足りない物）→ その物の `gather`（作れる物なら `craft`）を前に足す。今回の「原木×1 が足りない」はこれで、心を通さずに直る。
  - `needs_tool`（掘る道具が無い）→ その道具の `craft` を前に足す。
  - `not_found`（見える所に無い）→ `find` を前に足す。
  - `no_path`・`error` → 1 回だけやり直す。だめなら心に相談（3.3）。

## 3. 流れ

### 3.1 始める・止める（心の道具）

| 道具 | 中身 |
|---|---|
| `start_goal(text, why?)` | 目的を始める。動いている目的があれば `next` に足す（「先にこっち」なら `first=true` で替える） |
| `stop_goal()` | 今の目的をやめる |
| `finish_step(result)` | `mind` の段（係では決められない段）を終える |
| `goal_status()` | 今の目的と段（会話の後ろの「[今の目的]」で足りないとき） |

- 持ち主の「止まって」「待って」は、今の体の止め方（stop_moving）と同じく、目的も `paused` にする。「続けて」で戻す。
- 配信のコメントからは始めない（体を動かすのは持ち主とシエルだけ。`FROM_COMMENTS` は False）。

### 3.2 計画

1. ゲームの係の `plan` で分かればそれを使う（作る目的。マイクラなら作り方の木）。
2. 分からない目的（「家を建てる」「村を探す」）は、心が分ける：心に「この目的を、ゲームの係の段の種類で分けて」と頼み、心は知識の窓口（search）で調べてから段の一覧を返す（GITM の Decomposer）。分けきれない所は `mind` の段にする。
3. 計画を立てたら、段の一覧を goal.state で見せる。

### 3.3 回す（決まった流れ）

```
次の段（todo の先頭）を選ぶ → run → 体の done を待つ → check
   できた   → done。次の段へ。全部済めば goal は done
   できない → repair があれば、その段を前に足して続ける（changes に書く）
             無ければ、心に相談：「[目的：…の段「…」ができない。理由：…。どうする？]」
               心は start_goal で別の手・段の書き換え（replan_goal）・持ち主に聞く、のどれかを選ぶ
             同じ段で 3 回だめ → paused。持ち主に聞く（attention に書く）
```

- 段は **1 つずつ**。体の技は一度に 1 つなので、そのまま合う。
- 「できた」は `check`（体の様子）で決める。心の言葉では決めない（Anthropic の「完了は結果の性質」）。
- 守る係が体を使っている間（敵が来た）は、段を待つ（今の体と同じ）。

### 3.4 心への知らせ（話しすぎない）

- 会話の後ろに、いつも短く「[今の目的] 石のつるはしを作る（3/4：丸石を集めている 1/3）」を渡す（付箋の「[今のタスク]」と同じ場所）。
- 口（mouth.py）の知らせは区切りだけ：目的を始めた・計画を直した・持ち主に聞きたい・目的ができた。段ごとには知らせない（Mindcraft で、細かく伝え合うと成功が下がった）。話すかどうかと言い方は心が決める。

### 3.5 置き場と再開

- 今の目的は付箋（board）の 1 枚（kind `goal`）。「[今のタスク]」と重ならないよう、目的の付箋は「[今の目的]」だけに出す。
- 中身（目的・段・changes・next）は DB に置き、会話をまたいでも続ける（会話を切ってつなぎ直したら、`paused` から始めて、心が「続きをしますね」と言う）。
- うまくいった段の列は、ゲームごとに覚える（同じ目的の次の計画に使う。JARVIS-1・GITM の記憶）。はじめは作らず、あとで足す。

## 4. 見える化

### 4.1 届け方

- 目的の係が、変わるたびに `goal.state`（2.1）を LiveKit のデータ（topic `ciel.goal`）で送る。付箋の `board.state` と同じ道。
- 見せる側はゲームを知らない。`label`・`progress`・`status` だけで描く。

### 4.2 配信用のウィンドウ（視聴者に見える）

- 配信用のウィンドウ（`CielStreamWindow.cs`）は、専用のカメラで描いた絵を別のウィンドウに写している。札は、そのカメラだけが映す UI（Screen Space - Camera の Canvas を、配信用のカメラの層に置く）として足す。操作用のウィンドウには出ない。
- 出す物（小さく、シエルの横か上。位置は設定で）：

```
┌ いまの目的 ──────────────── マイクラ ┐
│ 石のつるはしを作る（ハカセのお願い）      │
│ ✔ 原木を集める 3/3                        │
│ ✔ 木のつるはしを作る                      │
│ ▶ 丸石を集める 1/3                        │
│ ・ 石のつるはしを作る                     │
│ ↺ 原木が足りなかったので、集める段を足した │
│ つぎ：鉄を掘りに行く                       │
└───────────────────────────────────────────┘
```

- 段は 5 つまで見せ、多ければ「済み」をたたむ。目的が無いときは札を消す。できたときは少しのあいだ「できた！」を見せて消す。
- 設定 → 配信用のウィンドウ →「いまの目的を見せる」（入・切）。
- 人前（presence が public）では、だれの頼みかを「持ち主のお願い」と書く（名前を出さない。覚えている人の名前を配信で出さない決まりに合わせる）。

### 4.3 アプリ（操作用）

- 同じ札を、開くと詳しく見える形で出す（全部の段・直した履歴・あとでやる目的・持ち主に聞いていること）。
- 持ち主が「止める」「続ける」を押せる（`goal.control`。心の道具と同じ扱い）。

### 4.4 あとで足せる形

- OBS の「ブラウザソース」で取り込む表示用の Web ページ（置き場所・大きさを OBS で自由に）。中身は同じ `goal.state` なので、あとから足せる。家の中の Web の窓口が 1 つ増えるので、要るときに考える。

## 5. 料金・重さ

- 決まった流れは料金がかからない。心を呼ぶのは、目的を始める・決まった計画で分けられない目的を分ける・決まった直し方で直らない失敗のときだけ。今（心が毎回次の手を考える）より少なくなる見込み。
- goal.state は小さな JSON（段 10 個で 2 KB ほど）。変わったときだけ送る。

## 6. 進め方

1. **目的の係と、マイクラの係の作る目的**（作った。2026-11-07）：`goals.py`（GoalRunner）、`tools/goals.py`（start_goal・stop_goal・resume_goal・finish_step・goal_status）、`minecraft.py` の `Goals`（マイクラの係）と `Body.run_skill`・`Body.plan`、体の `src/goal-plan.js`（命令 plan）。使い方は `config/prompts/minecraft.md`。今は会話の中だけで持つ（DB はまだ）。goal.state は topic `ciel.goal` で送っている。本物の体で、原木 1 本と作業台を持った状態（止まったときと同じ）から石のつるはしを頼むと「原木を 1 本集める → 木のつるはしを作る → 丸石を 3 個集める → 石のつるはしを作る」になった。
   はじめに書いたこと：`goals.py`（決まった流れ・付箋・DB）、心の道具（start_goal・stop_goal・finish_step・goal_status）、体の命令 `plan`、マイクラの係の run・check・repair（gather・craft）。「石のつるはしを作って」で、原木の不足を心を通さずに直して最後まで作れるかを、Ciel_Debug と声で確かめる。
2. **見える化**：goal.state を送り、配信用のウィンドウとアプリに札を出す。
3. **探す技**（作った。2026-11-07）：体の技 `find`（walk・dig・auto）と心の道具 `find_blocks`。集める段が `not_found` なら、先に探す段を足す。[マインクラフトで遊ぶ設計](minecraft-design-ja.md) の 25 章。
4. **心が分ける目的**：作り方で決まらない目的（建てる・探す）を、心と知識の窓口で段に分ける。
5. **覚える**：うまくいった段の列をゲームごとに残して、次の計画に使う。

## 7. あとで考えること

- 目的を並べて持つ（「石のつるはし」のあと「鉄を掘る」）とき、心が自分から次の目的を始める間（持ち主が何もしていないとき・夜になる前など）。
- 視聴者の提案（コメント）を、目的の「候補」として札に出し、持ち主かシエルが選ぶ形。体はコメントから動かさない決まりは保つ。
- ブラウザソースの表示（4.4）。
