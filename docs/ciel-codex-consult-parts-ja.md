# シエルの Live2D パーツ分けと制作方法の相談報告

2026-10-11 / Codex

**提案は、顔に重なる前髪・横髪を戻し、生成と組み立ての見た目の調整を Codex が一続きで担当すること。** 枠は初期配置に使い、最終的な位置・大きさ・陰影は組み合わせた状態で決める。顔まわりの小さな試作を先に完成させ、その構造で軽く動かしてから全身の素材へ広げたい。

今回は画像生成・画像加工・新しい確認図の作成・リグの変更はしていない。既存画像の表示、資料とコードの読解、Python による読み取り専用の寸法・画素検査を行い、この報告だけを書いた。以下の成果物・調整・生成は、すべて**次回以降の提案**である。

確認した主な資料は、[承認済みの2倍原画](../assets/ciel/master/ciel-upper-body-2x.png)、[1倍原画](../assets/ciel/generated/upper-body-1x.png)、v8 の[全体比較](../assets/ciel/layers/v8/_check.png)・[頭部比較](../assets/ciel/layers/v8/_check-head.png)・[分解図](../assets/ciel/layers/v8/_exploded.png)。さらに、顔・髪・目・首・胴・首輪の主要原本と枠、[frames.json](../assets/ciel/generated/v8/frames.json)、[生成報告](../assets/ciel/generated/v8/parts/report.md)・[修正生成報告](../assets/ciel/generated/v8/parts/report-fix.md)の所見と関連指示文、[組み立てコード](../scripts/live2d/assemble-v8.py)を確認した。全代替候補の全画素を検査したわけではない。

設計上の根拠は、[公式サンプルの解析](ciel-live2d-reference-rig-analysis-ja.md)、[再計画（特に8.1・8.2）](ciel-live2d-rebuild-analysis-plan-ja.md)、[リグ設計](ciel-live2d-rig-design-ja.md)、[キャラクター設計の要点](ciel-design-constraints-for-parts-ja.md)。サンプルの実物の再解析、v8 の Cubism・Unity での動作確認は**未確認**。資料にある過去の実測は、今回自分で再測定した値と区別する。

## 1. v8 が不自然に見える理由

### 1.1 見た目の問題は、複数の部位の関係が同時に変わったこと

元のシエルの顔は、長い中央前髪、頬の上に入る左右の髪、大きなシアンの目がまとまっている。v8 ではそのまとまりがほどけ、広く露出した顔に目・鼻・口を配置した印象になっている。各パーツの線が滑らかでも、キャラクターとしての顔つきは保存されない。

| 部位 | 画像から確認できたこと | 見立てと修正方向 |
| --- | --- | --- |
| 前髪・額 | 元の中央束は目の間へ下りる。v8 は全体が短く、眉の下から目の上に広い肌の帯が見える | 最優先。額の見える面積と中央束の先端を戻す。前髪全体の平行移動だけでは分け目も下がるので、根元を保った束の形を直す |
| 頬まわりの横髪 | 元はこめかみから頬へ続く髪が顔を包み、長い束が胸元へ続く。v8 の独立横髪は短い小片になり、画面左と右で形・顔への入り方も違う | 顔の前に重なる髪をきちんと描く。頬を包む束と胸へ垂れる束の担当を明示し、誰も描かない区間をなくす |
| 目 | 顔全体では印象が弱い。一方、単体には濃い上まつげ・青からシアンの虹彩・明るいハイライトがある | 「全体の彩度が低い」だけでは説明できない。髪と顔の比率を直し、両目の大きさ・間隔・虹彩と白目の比を一緒に比較する |
| 首・顎 | 元は顎下の首が明確に暗い。v8 は顔と近い白さで、細い明るい柱のように見える。首輪の奥に白い服の立ち上がりも見える | 首の陰影不足に加え、顎・首・服の襟・首輪の位置関係の問題。首だけ暗くする前に、どこが肌でどこが服かを整理する |
| 首輪と胸飾り | v8 では丸い下がり飾りが胸の菱形の上に接し、ひとつの装飾に見える。元は間に白い服が見える | 胴側の宝石と首輪側の飾りを別々に位置調整する。描画順を逆にしても、元の間隔は戻らない |
| 頭頂 | v8 は耳の間に、前髪の分け目のさらに後ろの丸い髪の山が見える | 後ろ髪にも頭頂の丸み・分け目が描かれ、前髪側の丸みと競合していると考える。後ろ髪・頭頂・前髪の外形の担当を決める |
| 胴・ファー | v8 はファーの量感と胸の陰影が強まり、顔より服の存在感が増している | 首から下も別の比率・描き込みになっている。顔だけの調整後、上半身全体の主役が目に戻るかを確認する |
| 透明縁 | 特に選択済みの横髪 v2 原本に広い白灰色のにじみがある。前髪には小片も見える | 「v8 は縁がきれい」は相対評価として理解するが、素材として無条件合格にはできない。白い髪・白い肌上で隠れ、暗い背景や動作時に出る可能性がある |

ユーザーの「顔の土台の上に前髪・横髪を重ねれば、元のようにかわいくなる」という考えには賛成する。ただし、**別レイヤーにすることに加え、顔へ入る曲線と毛先が素材に存在していること**が必要。v8 の横髪はすでに目・顔より手前に描かれているため、描画順を変えるだけでは不足している。

### 1.2 指示文とコードで確認できた原因

修正生成報告には、横髪に対して `Stay OUTSIDE the face and eye silhouette`、前髪に対して目の上に隙間を設け、枠下部を透明にする指示がある。これは描画事故を避ける範囲を超え、**元の髪型を短く・外側へ変更する指示**になっていた。中央の毛先を目の間まで下ろす元絵と、「全毛先を目より上へ」の両立はできない。

再計画9章の「毛束が顔を横切らない」も、今後は次の意味に限定したい。

> 頬やこめかみを包む意図した重なりは保つ。向きを変えたときに、外側の大束が鼻や反対の目へ不自然に滑り込むことを防ぐ。

また、現在の `assemble-v8.py` は各原本を枠の幅・高さに `resize` し、枠左上へ置いている。**枠への拡大縮小は実行済みだが、見た目に基づくパーツごとの倍率・移動・回転の補正はない。** 同じ枠で生成することは、枠の中の物体の位置まで一致する保証ではない。縦横比が違う場合も警告後に枠寸法へ変形するため、今後は自動的な縦横別倍率を避けたい。

コードは `-v2.png` が存在すると自動採用する。生成報告で「完成品質には未達」とした候補も配置される仕組みであり、「新しいファイル」と「合成まで確認して採用したファイル」を区別できていない。

### 1.3 目の大きさ・首の明るさの補助検査

2172×2896 座標の同じ領域を読み取り、虹彩の青〜シアン領域を粗く調べた。下表は目全体の寸法ではなく、限定領域内で RGB の `B−R>80、G>65、B>150` を満たす画素の外接幅・高さ。輪郭の厳密な計測ではない。

| 対象（キャラクター視点の左右） | 元絵 | v8 合成 |
| --- | --- | --- |
| 右目：画面左、検査領域 (830,965)–(1010,1140) | 132×137 px | 132×127 px |
| 左目：画面右、検査領域 (1210,950)–(1390,1130) | 133×136 px | 139×137 px |

この範囲では、両目が一様に大幅縮小したとは言えない。右目は縦方向が少し短いが、左目の色領域は小さくなっていない。**小さく弱く見えるという評価を尊重しつつ、まず髪・露出した肌との相対関係を直す**のがよい。両目を一律に大きくする倍率の正解は**未確認**。

首中央の小領域 (1080,1390)–(1150,1410) の平均 RGB は、元絵が約 (219,206,219)、v8 合成が約 (249,246,249)。これは首全体の測色でも物理的な照明測定でもないが、この場所の陰が大きく弱まったことは確認できる。首単体の上部には薄い影があるものの、合成後の見える首に十分な暗さが残っていない。

### 1.4 調整と描き直しの境界

- **配置から試すもの**：両目の倍率・間隔・高さ、首輪の前後の幅と高さ、丸飾りと菱形の間隔、後ろ髪上端の出方。
- **素材の形から直す可能性が高いもの**：短くされた前髪、頬を包む横髪、胸までの手前の髪、顎の動きに対応する首の落ち影。
- **分離してから調整するもの**：Body に含まれる胸の菱形、首輪と一体の丸飾り、後ろ髪に含まれる頭頂、目・口の機能層。

大きな変形で無理に合わせると、線幅や毛束の曲率まで崩れる。元の曲線を持たない素材は再描画し、原画から残せる良い部分は残す。全パーツを必ず再生成する必要はない。

## 2. 自然に動かすためのパーツ構成

### 2.1 分ける基準

**位置・変形・揺れ・隠れ方・不透明度を別々に制御する必要があるものを分ける。** 生成1回、PNG1枚、Cubism のメッシュ1枚は同じ単位にしなくてよい。例えば片目の完成形をまず整合させ、それを白目・虹彩・まつげ等の層に仕上げる。

既存設計の約90〜110メッシュは目安として維持できる。ただし枚数を埋めることを合格条件にしない。前髪や耳の試作段階では粗い分割で重なりを確定し、必要な動きが分かってから細分化する。

以下の L/R はキャラクター視点（L は画面右）。同じ名前の部位が複数の素材へ重複して焼き込まれないよう、担当を固定する。

### 2.2 背面から前面への層一覧（正面の初期案）

表は奥から手前の基準。目・口の内部順は後述。重ならない領域どうしの細かな順序は任意だが、首輪の前後、顔と髪など、交差する箇所はこの関係を守る。

| 順 | パーツ案 | 描くもの・重なり・描き足し |
| --- | --- | --- |
| 1 | `Hair_Back_Upper`、`Hair_Back_L/R`、必要なら `Hair_Back_Center` | 頭と肩の後ろの髪。顔・首・体を外しても穴にならない面。正面の頬を包む髪はここへ焼き込まない |
| 2 | `Body_Skin`、`Body_Torso`、`Body_Skirt`、`Body_Belt` | 肌、服、画面下端の服。胸飾りと首輪は含めない。肩はファーの下まで。動きが同じ部分は制作中にまとめてよい |
| 3 | `Choker_Back` | 首の後ろの帯だけ。中央を首で隠す。首に沿う同じ楕円の奥側として前側と設計する |
| 4 | `Neck_Base` | 口の高さ程度まで上へ続く首。下端は服の内側へ。顎の輪郭線、首輪、服の襟は含めない |
| 5 | `Neck_Shadow_Chin`、必要なら `Neck_Shadow_Collar` | 首の範囲へ限定する影。顎による影と首輪の接触影を分離して二重に塗らない |
| 6 | `Jacket_L/R`、`Jacket_Lining_L/R`、必要なら `Sleeve_L/R` | 上着・裏地・袖。裏地は上着本体より奥。呼吸だけで同じ動きをする区間は過剰に分けない |
| 7 | `Fur_Collar_L/R` | 上着と肩の上のファー。元絵のふくらみを保つ。首を隠す部分は首より手前 |
| 8 | `Chest_Gem` | 服に付く菱形。下地の服にも同じ宝石を残さない。体側に追従 |
| 9 | `Choker_Front`、`Choker_Buckle`、`Choker_Pendant` | 首の手前の帯・金具・丸飾り。金具を別にするのは曲げずに保つため。丸飾りは独立した揺れが必要なら分離。首側に追従 |
| 10 | `Hair_Side_L/R_Outer` | 頭の横の外側の髪。顔より奥に置く部分。頬を覆う内側の束と区別する |
| 11 | `Hair_Crown` | 頭の上の一続きの丸み。後ろ髪から独立して形を調整できるようにする。前髪の根元と輪郭を二重に描かない |
| 12 | `Ear_L/R_Outer`、`Ear_L/R_Inner`、必要な `Ear_L/R_Back` | サモエドの厚みのある犬耳。表と内毛は耳の親で一緒に動く。裏面は倒すときに必要な範囲だけ。人間耳は作らない |
| 13 | `Face_Skin` | 目・眉・鼻・口・髪を除いた顔の土台。額・こめかみ・頬を髪の下まで連続して描く。肌の弱い立体陰影は保持 |
| 14 | `Face_Line_L/R/Chin`（必要箇所）、`Cheek_Indicator_L/R` | 角度で調整する輪郭線、表情で灯る頬。通常時の血色は加えない。塗りと線を分けるなら肌側に同じ線を残さない |
| 15 | `Face_Shadow_HairFront`、`Face_Shadow_HairSide_L/R` | 額・こめかみ・頬に落ちる髪影。顔へクリッピングし、目・口の通常の絵の下に置く初期案 |
| 16 | `Nose`、口の各層、目の各層 | 鼻は元絵の小ささを保つ。口・目は独立した部位デフォーマに置く |
| 17 | `Hair_Side_L/R_Inner`、`Hair_Side_L/R_LongFront` | **頬の肌・必要な目尻部分の上に重なる横髪**と、胸へ垂れる手前の長い髪。服・ファーの前に出る範囲もこの層で扱う |
| 18 | `Ear_Base_L/R`、`Hair_Front_1…5`程度 | 耳根元の接合毛と前髪。耳の差し込みと横髪の根元を隠す。中央束は元絵のように目の間へ下ろす |
| 19 | `Brow_L/R` | 既存のユーザー決定「まず前髪の上」を維持。濃さを合成で調整。浮く場合だけ、既存設計の透け表現案を比較する |
| 20 | `Hair_Ahoge` | アホ毛。根元が浮くなら下端を頭頂・前髪の下へ回す構造にする。見える先端だけ独立して揺らす |

横髪の「内側」「外側」は、見た目の左右でなく**顔の前後**を意味する。一本の長い髪が途中でファーの前後をまたぐなら、自然な重なり位置で分割し、共通の親と一致する根元でつなぐ。全体を前へ出して解決しようとしない。

耳も、全部を頭頂の上へ貼るだけでは付け根が浮く。外側・内毛・接合毛で「髪から耳が生えている」接続を作る。耳の強い倒れに必要な裏面量は**未確認**。

### 2.3 目の層とまばたき

片目につき以下を基準とする。左右の完成形を顔に置いて承認してから、この機能分割を仕上げる。

| 奥→手前 | 層 | 用途 |
| --- | --- | --- |
| 1 | `Eye_*_Sclera` | 白目。虹彩の下まで連続した白目を描く。目の開口形を作り、虹彩等のクリッピング元にする |
| 2 | `Eye_*_Iris` | 虹彩と瞳孔。まつげに隠れる上端も含む丸い全体。瞳孔の拡縮が不要なら虹彩と一体でよい |
| 3 | `Eye_*_Shade`（必要時） | 上まぶたが眼球に落とす影。まぶた側に追従させ、視線と一緒に滑らせない |
| 4 | `Eye_*_Highlight` | 虹彩上の光。まず虹彩と一緒に動かす。独立した揺れは必要性を見て追加 |
| 5 | `Eye_*_LidSkin_Upper/Lower`（必要範囲） | まぶたの肌。閉眼時の境界を隠す。周囲の顔色となじませ、明るい四角いパッチにしない |
| 6 | `Eye_*_LashUpper`、`Eye_*_LashLower`、必要なら `Eye_*_Corner` | まつげと目尻。目尻の尖りは大きく圧縮されるなら別にする |
| 7 | `Eye_*_Crease` | 二重線。開き具合に合わせて位置・濃さを調整 |

白目による虹彩のクリッピングは公式の基本手順である。[Live2D公式：クリッピングマスク](https://docs.live2d.com/en/cubism-editor-manual/clipping-mask/)

まばたきでは、白目の開口と上下まぶた・まつげを連動させる。虹彩全体を縦につぶして閉じた目を表すと瞳の絵が歪むため、開口で隠す。閉じ切る直前の虹彩・ハイライトの漏れ、白い一線、目尻の折れを確認する。

通常の開閉は連続変形を第一案とする。笑顔の閉じ目など異なる線形が必要なら差し替えを加えるが、「開・半・閉の完成絵をフェードするだけ」を通常まばたきの前提にしない。差し替えの境目では二重のまつげや瞳が見えないことを確かめる。

前髪は目の上に重ねてよい。ただし元絵のように瞳の中心・大きなハイライトが読める範囲を守る。目を常に髪より上へ出す、髪を全体的に半透明にする、といった処理を初期解決には使わない。

### 2.4 口の層と口パク

口は `Mouth_Inside`（暗い口腔）→ `Mouth_Tongue`・`Mouth_Teeth`（必要な小さな八重歯を含む）→ `Mouth_Skin_Upper/Lower` → `Mouth_Line_Upper/Lower` を基本とする。舌と歯は口の開口内に収める。口周りの肌は唇の移動に追従し、口腔の縁を隠す。

口腔・歯・舌は開いたときの見える範囲より少し大きく描く。閉口では口内が漏れず、元の小さな微笑みの線になるようにする。上下の唇、口内、覆い用の肌を分ける方法は公式にも示されている。[Live2D公式：イラスト加工](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)

`ParamMouthOpenY` で開閉、`ParamMouthForm` で笑み・困りを作る案。最初に「閉じた微笑み、小さな会話口、最大の会話口」を同じ顔で比較し、口を開くと別人になるのを防ぐ。大口や八重歯の正確な形は元の閉口絵だけでは決まらず、**未確認**。

### 2.5 影を持つ場所

「白磁の肌」は反射色の基準であり、「陰も白くする」という意味ではない。白い肌・白い髪・白い服の境界では、冷たい灰紫の陰が特に重要になる。

| 陰影 | 所属・作り方 |
| --- | --- |
| 肌自身の立体感 | 顔・首の土台に、部位に固定された弱い陰影を持たせる。顔・首・肩の色調をそろえる |
| 顎が首に落とす影 | `Neck_Shadow_Chin` を首へクリッピング。首の位置に追従しながら、顔のX・Yで影の位置・広がりを補正する。首の土台と二重計上しない |
| 前髪・横髪が顔に落とす影 | 顔上の別層。顔側の変形を基礎に、対応する髪の動きで補正。髪PNGの外にぼんやり付けた光・影で代用しない |
| 髪の束の内部の陰 | その毛束に持たせる。付け根の隠れる領域には、露出時に不自然な濃い輪郭を描き込まない |
| 首輪の接触影 | 首側に置く。金具自身の陰影は金具側。首輪が動く際の接触を保つ |
| ファー・服の折り目 | 原則その素材に焼き込む。他部位の移動で大きく位置が変わる落ち影だけ分離 |

まずは通常合成の半透明の影で組み上がりを確認し、必要なら乗算へ変える。合成方式は最終の Unity と合わせる。分離した影を追加するなら、その影が元の肌にも焼き込まれていないかを先に確認する。

### 2.6 レイヤー分けを動きにつなぐ

頭の回転の下に、顔、左右目、左右眉、鼻、口、前髪、内外横髪、耳、後ろ髪のXYデフォーマを兄弟として置く。まばたき・視線・口形・髪や耳の揺れは、それぞれの部位の子で制御する。首は顔とは別に保持する。部位ごとの視差を作る方針は公式のXYチュートリアルに沿う。[Live2D公式：XYの顔の動き](https://docs.live2d.com/en/cubism-editor-tutorials/xy/)

既存の解析資料では、ひよりの前髪は輪郭と近い移動量で、横の毛束・後ろ髪は小さく、または逆方向に動く。「前髪は必ず顔より大きく動く」「横髪は全部顔の奥へ回る」を一律の規則にしない。内側の横髪は頬の手前、外側の束は奥、という違いを形に反映する。

`ParamAngleX/Y = ±30` は今回の可動域の端で、見た目の実角度30度を強制しない。見た目15〜20度程度に抑え、まず固定の描画順で成立するか試す。必要性が確認された部位だけ順序切り替えを検討し、切り替えの瞬間も確認する。線の分離、グルー、追加の顎下素材も、枚数や機能を使うこと自体を目的にしない。

## 3. Codex への依頼の仕方

### 3.1 生成は基本1パーツ、判断は部位一式

推奨は**1回の生成では1つの連続した部位を描き、数枚ごとに必ず組み合わせて判断する**こと。全パーツを一括生成する方式も、全パーツができるまで単体だけを見る方式も避けたい。

| 判断するまとまり | 個別に用意するもの | 合成して決めること |
| --- | --- | --- |
| 顔の印象 | 顔土台、左右目、眉、鼻、口 | 顔に対する両目の比率、間隔、目線、微笑み |
| 顔を囲む髪 | 前髪、左右の内横髪、手前の長い髪、頭頂・後ろ髪の境界 | 肌の露出量、頬への被り、中央束、頭頂の高さ |
| 首から胸 | 首、顎影、首輪の前後、丸飾り、服、胸の菱形 | 首の陰、首輪との接触、2つの飾りの間隔 |

左右目は同じ段階で比較し、先に採用した片目をもう片方の参照にも使う。ただし最初の片目自体が顔に合っていることを確認してからにする。「左右がそろう」と「元のシエルに合う」は別の条件である。

前髪も、いきなり5本を独立に創作させるより、元絵の毛束の流れと組み上がりを先に確定し、同じ完成形から各束を分離・補完する方が形の整合を保ちやすい。色のしきい値だけで切り抜くと v7 の縁の問題を再発させるため、輪郭に沿うマスクを整え、隠れた部分を補う。良い既存素材を使える箇所は再利用する。

### 3.2 参照は目的を付けて渡す

各依頼に、原則次の4種類を渡す。参照が多すぎて役割が曖昧になる場合は、関係の薄いものを外す。

1. **承認済みの全体絵または頭部全体**：シエルらしさ、頭身、顔と髪の量感、目の強さ、光の方向の基準。今回の指定された原画を正とする。
2. **対象の枠**：座標・縮尺・見える毛先の参考。枠いっぱいに描く指示にしない。枠内の位置は生成後に検査して補正する。
3. **採用済みの隣接パーツを置いた現在の合成**：前髪なら顔と両目、横髪なら顔・前髪・首、首輪なら首と服。単体画像を別々に並べるだけでなく、実際の接点を見せる。
4. **必要な補助参照**：反対の目、耳、前回候補と修正箇所、髪の下を補完した画像など。補完用画像は見えない構造の参考であり、見える顔つきの基準にはしない。

過去の報告では、全体参考に `v7/peel-body/full-1x.png` が使われていた。今回、その画像と承認済み原画の完全な一致は**未確認**。次回は承認済み原画を明示し、派生画像の役割を限定する。

左右は「キャラクター右＝画面左」のように毎回書く。隠れる付け根、頬へ入る毛先、見える外形を区別し、完成形のどこを担当するかを示す。隣のパーツを参照に渡しても、出力へ描き込むのは対象パーツだけとする。

### 3.3 避ける指示と置き換え

| 避けたい指示・前提 | 置き換え |
| --- | --- |
| 「顔の前を横切らない」「顔の輪郭の外に置く」 | 「元絵どおり頬に重ねる。鼻や反対の目を横断する新しい束は加えない」 |
| 「瞳を隠さないため、前髪全部を目より上で止める」 | 「中央束は目の間へ、側束はこめかみへ。瞳孔と主要ハイライトが読める元の被りを保つ」 |

### 3.5 目の大きさ・首の影を保つ工夫

目は両目の完成形を顔に置いた状態で、虹彩径、目の横幅と高さ、両目間隔、目尻の角度、顔幅との比率を記録する。これは合格した顔を再現するための記録で、数値が一致すればかわいいと判定するものではない。髪の重なりを直した後、例えば現在倍率・約5%拡大・約10%拡大を同じ中心位置で比較する。これらは試す値であり、推奨確定倍率ではない。

首は首単体の画像だけでなく、顎と首輪が重なった状態を必ず参照にする。「首の上に影がある」ではなく「実際に見える顎と首輪の間が、元絵と同じく顔より一段暗い」を基準にする。白磁の肌をベージュや常時の赤みに変えて立体感を出さない。

ただし、**今回、修正版の合成を作って効果を検証したわけではない**。Cubism GUI を安定して操作できるか、PSD 書き出し経路、動画の直接確認経路、現在のリグをこちらで完全に再現できるかは**未確認**。ローカル画像を加工できることから、完成リグの品質まで保証しない。

### 4.2 次の組み立て方法

生成原本は保存しておき、別の配置定義に次を記録する。

| 項目 | 内容 |
| --- | --- |
| 原本 | 明示的に採用したファイル名とハッシュ。`v2` の存在だけで自動更新しない |
| 座標 | 基準キャンバス2172×2896、枠座標、原本からキャンバスへの変換 |
| 補正 | 基準点、移動量、倍率、回転角。縦横別倍率や局所変形は必要な場合だけ理由を記録 |
| 重なり | 描画順、マスク対象、合成方式、不透明度 |
| 接続 | どのパーツの下へ入るか、隠れた領域、動かす親、影の所属 |
| 採用状態 | 単体確認済み／合成確認済み／動作確認済みを区別 |

枠への初期変換後、目は目の中心と目尻、髪は分け目・根元・主要毛先、首輪は左右の接点と金具、飾りは中心と間隔を基準に調整する。**不透明画素の外接枠だけで合わせない。** 隠れた描き足しや白いにじみが外接枠を変えても、顔上の目の位置を動かす理由にはならない。

調整の順序は、頭・顔の大きな外形→前髪・頬髪の被り→両目→首・首輪→胸飾り→陰影と縁を基本にする。各部位を直した直後に上半身全体も見る。顔を直してから何段階も後に全体を初めて見る流れを避ける。

再サンプリングは常に原本から行い、縮小済み画像を何度も拡大しない。透明境界に背景色が混じらないアルファ処理を使う。ぼかしやアルファの一律しきい値処理で白い縁を消すと、細い毛先や線も失うため、輪郭のマスクを部分的に整える。

### 4.3 反復で提示する確認図

- 同じ倍率・切り取りでの「承認済み原画／直前の合成／修正後」の比較。顔だけでなく上半身全体も添える。
- スマホに表示する想定サイズでの顔。画面幅とアプリ内の表示枠は**未確認**なので、最初は複数の縮小サイズで仮確認し、Unity 実機で確定する。
- 中間灰・白・暗い背景での透明縁。分解図は部位名と原寸に対する倍率を付ける。単体を全部同じ箱に収めた分解図だけで大小を判断しない。
- 髪を外した顔、顔を外した髪、首と首輪だけなど、重複や欠落を確認する表示。
- 仮の移動・回転で隠れた部分が足りるかを見る図。ただし2D平行移動だけの確認を「角度±30の動作確認」と呼ばない。

見た目の評価は私が合成を表示して行い、数値検査は位置ずれ・重複・意図しない切断の検出を補助する。何回か直しても改善しない場合は、同じ制約で再生成を繰り返す前に、参照・部位の担当・指示の矛盾を見直す。

### 6.2 動作の具体的な確認

頭XYはまず −30・0・+30 の3×3で、正面・上下左右・4隅を確認する。次に −15・+15 を含む5×5と、連続する左右往復・上下往復・斜めの周回で途中の折れや跳びを見る。検査点を増やすことと、キーフォームを全部増やすことは別である。

目は開度0・0.25・0.5・0.75・1で、正面と左右端、視線の左右端を組み合わせる。口も閉・小・中・最大の途中を、通常と笑顔・困りで見る。首影は上下向きと斜め、横髪と耳は物理の両端と頭の向きが同時に重なる状態を確認する。

合格判定は次の観点を使う。原画との差のRMSや目の中心の誤差は補助記録にとどめる。

| 観点 | 合格の見方 |
| --- | --- |
| 顔の印象 | 目が印象の中心で、額・頬の露出と髪の流れが承認した顔を保つ |
| 髪と顔 | 頬への意図した被りが保たれ、鼻・反対の目へ束が滑り込まない。毛束間に穴が出ない |
| 首と飾り | 顎から首輪まで立体感があり、上向きで白や灰の柱にならない。丸と菱形が不用意に接触しない |
| 目・口 | 閉じた状態で中身が漏れず、中間で二重線や色の帯が出ない。会話中も同じ顔に見える |
| 耳・頭頂 | 根元が離れず、頭頂の丸みが二重に盛り上がらない |
| 連続性 | パラメーターの途中で輪郭・描画順・陰影が跳ねず、表情終了後に基準へ戻る |
| 実表示 | 実機の背景とサイズで縁・細線・クリッピングを確認し、目と口が十分に読める |

### 6.3 引き渡しと未確認事項

PSD は部位ごとに整理し、通常の描画に必要な線・塗り・効果を適切に統合する。別に動かす線や影は独立レイヤーを保つ。PSD のレイヤーマスクや効果がそのまま同じ見た目で取り込めると仮定せず、PNG合成と取り込み後を照合する。[Live2D公式：PSD作成時の注意](https://docs.live2d.com/en/cubism-editor-manual/precautions-for-psd-data/)

既存の `render-moc.py` は書き出したモデルと Cubism Core を使う確認経路であり、編集中の `.cmo3` をそのまま画像化するものではない。資料には Unity との形の一致とクリッピング縁の残差が記されているが、今回は再検証していない。顔の形の高速確認には活用しつつ、物理・表情・音声口パクの時間変化と最終描画は Cubism／Unity の経路で確認する。

スマホ用のマスク数・アトラス容量・負荷の具体的な上限は、対象端末と使用SDKの構成では**未確認**。メッシュ数だけで軽さを判断しない。公式もクリッピングの負荷や表示差について実環境での確認を求めているため、最終段階だけでなく仮リグでも一度 Unity へ持ち込む。[Live2D公式：SDK使用時のクリッピングの注意](https://docs.live2d.com/en/cubism-editor-manual/clipping-mask/)

今回の提案でまだ確かめていないのは、修正版の正面合成の実際の改善量、最適な目の倍率、髪と耳の描き足し量、首影の各角度での形、口内・歯・舌の採用デザイン、PSD書き出しとCubism操作の安定性、実機の表示サイズ・性能である。これらを一度に決め打ちせず、上の段階ごとの成果物で確かめる。
