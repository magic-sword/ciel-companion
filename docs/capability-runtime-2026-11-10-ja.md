# 能力カタログと会話専用MCPの実装・検証記録

実施日：2026-11-10。これは当日の証拠です。現在の方針は[設計方針の正本](design-policy-ja.md)、APIと実装範囲は[能力カタログの契約](capability-runtime-ja.md)を参照します。

## 変更

- rootと会話サーバーのAGENTS、資料一覧から設計方針の正本へ誘導。Claude Codeの既存`@AGENTS.md`参照にも適用する。方針変更時の正本・契約・実装状況・検証記録の更新手順を明文化した。
- pipelineにサービス概要と`load_capabilities`を導入。最大3サービスを再利用し、対象の道具とドメイン指示を次の推論に公開する。停止・状態確認は探索を要しない。発言元・コメント・ゲーム所有・議事録への明示依頼による制限を先に適用する。
- 記憶・検索・歌・議事録・会話検索・内なる考えを会話専用のMCPアダプター経由に統一。スキーマ検証、信頼できるRunContextのホスト内注入、取消、期限、返事の要否、結果サイズの制限、通信所要時間の記録を追加した。
- 記憶の意味単位の操作をLiveKit非依存の`MemoryService`へ抽出。本人確認・同意・DBスコープ・削除時のキャッシュ抑止を保ち、保存受付を`queued`で返す。任意人物IDは公開引数にしない。
- Minecraftの外部MCPと作業契約、構造化受付、アプリ通信は維持した。ゲームの依頼処理に段階的ロードを重ねて再実行しない。

## 確認結果

| 確認 | 結果 |
|---|---|
| `run-regression.py --suite unit` | 590件合格、失敗・エラー・skipなし |
| `check-capability-runtime.py` | 会話入口→ロード→次の推論→実MCP→検索ホストまで合格 |
| 既存Cielの初期化 | pipeline設定で起動時の道具・プロンプト構築に成功 |
| `git diff --check` | 差分の空白エラーなし |

単体テストでは、実MCPの往復、SDKの引数注入、任意人物IDや不正型の拒否、未同意・本人不明、コメントへの切替後の拒否、会話間のロード状態の分離、LRU、外部道具の置換・名前衝突、取消伝播、返事を追加生成しない設定、大きな結果の明示的切り詰めを確認した。

会話入口の確認は検索のみを利用可能にした固定入力の試験。LLMのサービス選択と検索結果を固定し、配線と公開範囲を検証した。登録済み31道具に対し、初回公開2道具、検索の読み込み後4道具。JSONスキーマの文字数は登録済み合計9,571、初回431、検索読込後985。初回指示本文12,327文字、読込後13,121文字だった。人物像・本人確認・保存同意などの共通指示は引き続き保持する。

これは登録されている定義量と公開量の確認であり、旧構成との速度比較ではない。実モデルの選択精度、トークン数、初動時間、音声品質、GPU共用時の実行時間は測定していない。以前のMinecraft一巡の成績を今回のソースの成績として扱わない。

ローカルの回帰レポートはGit管理外の`server/benchmark/data/capability-runtime-final-20261110/`に保存した。DB結合テスト、実際の歌の採点、実Minecraftベンチマーク、本番配備は未実施。会話専用アダプターの独立ネットワーク配備、汎用の結果保管・ページングも実装範囲に含まない。
